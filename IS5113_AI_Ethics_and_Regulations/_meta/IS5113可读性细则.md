# IS5113 可读性细则

本文件只补充 IS5113 的学科要求。句子、段落、版面、表格尺寸、分层和三种阅读场景，全部按 [[可读性总规则]] 执行。两者冲突时以总规则为准；原件或正式题面需保留特殊格式时，旁边另给可读解释。

本课读者哲学、伦理、法律零基础。最常卡住的是四件事：

- 一个结论到底依据哪几条前提；
- 一句话是在描述事实，还是在说“应该”；
- 一条法律在哪个地区、从什么时候起适用，适用条件是什么；
- 课堂案例很长，读完不知道它用来说明哪个概念。

本课笔记的超长句最多（M04 有 66 句超过 120 单元），主要来自把论证、案例叙事和课堂原话写进同一句。

## 1. 本课默认版式（补充总规则 §3）

| 内容类型 | 默认版式 |
|---|---|
| 一个论证 | 论证链：问题 / P1、P2… 前提 / 推理 / C 结论 / 最强反驳 / 条件改变后（见 §2） |
| 理论比较（如功利主义 vs 康德主义） | 对比表：行是比较维度，列是理论，最多 5 列；单元格 ≤ 25 单元（见 §3） |
| 课堂案例 | 案例卡：两列表，固定字段（见 §4） |
| 案例分析题的作答 | 四步：事实 / 适用标准 / 套用 / 结论与边界，每步一个列表项（见 §5） |
| 法律条文 | 适用行 + 引用块原文 + 中文 + “在本案意味着”（见 §6） |
| 课堂原话 | 引用块 + 中文意思；一段最多引一次（总规则 R7b） |
| 研究论文的发现 | 一篇论文一个列表项：谁做的 / 怎么做 / 发现什么 / 本讲用它说明什么 |
| 考试要默写的英文定义 | 引用块放英文原句，下一行写中文；哲学术语按课程 `CLAUDE.md` §3 的统一译名 |

## 2. 论证链

### 2.1 规则

1. 每个前提单独一行，编号 P1、P2……，每条 ≤ 50 单元。
2. 每个前提标类型：〔事实〕、〔规范〕或〔定义〕。“应该”“不应该”一类的话是〔规范〕。同一句不能既陈述事实又下规范判断。
3. 推理只写一步：“由 P1 和 P2 得到……”。中间缺的一步，补成新前提 P3，不能跳过。
4. 结论 C 单独一行。
5. 最强反驳单独一行，写清它攻击的是哪个前提。
6. 最后一行写“条件改变后”：哪个前提改了，结论会怎样变。

### 2.2 示例

❌ 不合格（示意写法：前提、推理和反驳压进一句）：

> 康德主义认为把人仅仅当作手段是错误的，而算法用用户数据训练又不告知用户，因此违背了尊重自主性，但有人会说用户已经同意了隐私条款，所以也不一定。

✅ 合格：

> 问题：不告知用户就用其数据训练模型，在康德主义下是否可以接受？
>
> - P1〔规范〕：不能把人仅仅当作手段使用。
> - P2〔定义〕：“仅仅当作手段”指对方无法合理同意的使用方式。
> - P3〔事实〕：用户不知道自己的数据被拿去训练。
> - 推理：由 P2 和 P3，用户无法对一项自己不知道的用途表示同意。
> - C：按康德主义，这种做法不可接受。
> - 最强反驳：攻击 P3。用户签过隐私条款，可以算已经告知。
> - 条件改变后：如果条款清楚写明训练用途，用户也能拒绝，P3 不成立，结论随之改变。

## 3. 理论对比表

1. 列是理论，最多 5 列。行是固定的比较维度：核心问题 / 判断对错的标准 / 本讲例子的结论 / 主要批评。
2. 单元格只写短语，≤ 25 单元。理由和例子写在表后，一个理论一个列表项。
3. 理论名第一次出现：中文（English）+ 一句 ≤ 20 单元的人话。

## 4. 课堂案例卡

### 4.1 规则

案例先用案例卡，再写分析。案例卡固定字段：

| 字段 | 写什么 |
|---|---|
| 时间与地点 | 年份、国家或地区；不确定写 `[?]` |
| 当事方 | 公司、个人、机构 |
| 发生了什么 | ≤ 2 句；经过更长时，单元格写“见表后经过”，在表后用编号列表按时间顺序写 |
| 争议点 | 一句话 |
| 结果 | 判决、和解、整改；未知写“讲义未说明” |
| 本讲用来说明 | 对应的概念，回链小节 |

ASR 不确定的人名、年份，只在案例卡里标一次 `[?]`。分析段落里不再重复“读音不确定”。

### 4.2 示例

❌ 不合格（M04 §2.6.4，一段 457 单元：情境、当事人读音、两个年份的不确定、四个时间戳和政策细节写在一起）：

> 想象你在一家航空公司官网上问客服机器人"能不能因为家人过世申请特殊票价"……这是加拿大航空（Air Canada）真实发生的事（转录时间线交代较跳跃，具体年份标 `[?]`，教授先后提到 "2024" 与 "2023, ChatGPT4 came out"）。当事人转录称为 "Mofat" 或 "Moffat"（读音不确定，标 `[?]`）……

✅ 合格：先用 2 句写情境，再放案例卡。

> 想象你问航空公司的客服机器人，家人过世能不能申请特殊票价。机器人说可以事后申请，你照做了，公司却拒绝退款。
>
> | 字段 | 内容 |
> |---|---|
> | 时间与地点 | 加拿大，2023 或 2024 年 `[?]` |
> | 当事方 | 加拿大航空（Air Canada）；乘客 Moffat `[?]` |
> | 发生了什么 | 见表后经过 |
> | 争议点 | 公司要不要为聊天机器人说错的话负责 |
> | 本讲用来说明 | 透明与问责：…… |
>
> 经过：
>
> 1. 机器人告诉乘客，可以先买普通票，19 天内再申请丧亲优惠。
> 2. 公司的实际政策要求出行前申请。
> 3. 乘客事后申请被拒，于是起诉。
>
> 时间戳写在 🎙️ 标签行：（01:40:37–01:42:02）。

## 5. 案例分析题的作答

### 5.1 规则

1. 固定四步，每步一个编号列表项：事实 / 适用标准 / 套用 / 结论与边界。
2. 每步里还有并列小点时，用二级列表，不写 ①②③。
3. 法律结论必须写条件：“若……适用，则……”。条件不满足时写“材料不足，不下结论”。
4. 末尾的小节回链放在单独一行：“对应：§2.2、§2.4.3”。

### 5.2 示例

❌ 不合格（M04 §7 案例分析题答案，一段 355 单元，①–④ 加改进建议全在一段）：

> ① 拆构件：六项几乎全无——不解释、不披露数据、不公开模型……② 受众：客户层零透明；监管层未知。③ 障碍：撞上"商业利益 / 专有算法"……④ 三面：伦理上……法律上，若GDPR范围适用且为纯自动化重大影响决定，还须核Article22例外和保障……

✅ 合格：

> 1. 拆构件：透明的六个构件几乎都缺。
>    - 不解释决定理由。
>    - 不披露训练数据，不公开模型。
>    - 客户未必知道是 AI 做的判断。
> 2. 受众：对客户完全不透明；对监管者是否透明，材料没有说。
> 3. 障碍：公司担心公开算法会被人钻空子，模型本身也是黑箱。
> 4. 伦理、法律、商业三方面：
>    - 伦理：没有解释，偏见就看不见，客户也无法申诉。
>    - 法律：若 GDPR 适用，且这是完全自动化、影响重大的决定，还要核对第 22 条的例外和保障。仅凭“有欧盟客户”不能断定违法。
>    - 商业：放弃了建立客户信任的机会。
>
> 对应：§2.2、§2.4.3、§2.6.2、§2.7.4、§2.9.2。

## 6. 法律条文

1. 分析前先写一行适用：“适用：欧盟 GDPR 第 22 条，2018-05-25 起”。法域、条号、生效时间缺一不可。核不到当前版本时写明“未核当前版本”。
2. 原文放引用块，下一行写中文。原文超过 60 词时，只引与本题相关的句子，并写“节选”。
3. 引用块后写一句“在本案意味着：……”。
4. 条文的例外和保障措施，用列表逐条写，不塞进一句。

## 本课高风险术语（提示清单）

每个独立学习单元首次实际用到这些概念时，至少给 1 句具体解释；跨单元可用 1 句唤醒加回链。下表是说明方向，不是逐字替换词典。R6d 只报待核提示，不能认证解释正确。

| 术语 | 需要讲清的意思 |
|---|---|
| 规范判断 | 说明应该怎么做，并交代判断标准 |
| 事实判断 | 说明发生了什么，并交代证据 |
| 自主性 | 当事人能了解选择并作出自己的决定 |
| 问责 | 明确谁解释决定、接受审查并处理后果 |
| 适用范围 | 先核对地区、主体、行为和时间是否符合条件 |

❌ 不合格：把表中若干术语并排写成结论，让读者自己补步骤。

✅ 合格：选本题的一个对象，逐步写它发生了什么变化，再用术语命名，并说明结论来自哪一步。
