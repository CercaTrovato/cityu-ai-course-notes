# CityU 课程笔记库

我是 CityU MSc Artificial Intelligence in Business 的在读学生，这个仓库是我 2026 年 9 月开学起给自己五门课建的知识库。它是一个 Obsidian vault，我每天在用；公开出来有两个目的：一是同班或者以后修这几门课的同学可以直接读笔记、挑错、拿去改；二是它本身是我做"用 AI 建个人知识库"这件事的一个完整样本——规则、脚本、翻车记录都在里面，想做类似事情的人可以少踩几个坑。

如果你只想读笔记，直接进 [[#五门课|五门课]] 那张表。如果你想知道它是怎么做出来的，往下读。**先看一眼 `NOTICE.md`**：讲义和课堂转录有使用限制，笔记可能有错。

## 我为什么做这个

我的底子是软件开发和数据分析，AI / 机器学习的东西读起来不费劲；但这五门课里有三门落在我完全没学过的领域——法律与伦理学（IS5113）、会计（AC6761）、金融（EF5560）——课件上一页"Balance sheet"我要查半天才知道每一行在说什么。

课的形式也决定了光看课件不够。教授的 PPT 是"准备讲什么"，课上讲的才是"实际讲了什么"：哪道练习题的答案讲义留白了课上才给、哪句"you don't have to memorize this"、哪个例子是教授临时加的、哪几页教授直接跳过——这些全在录音里，课件上一个字都没有。我每节课都录音转成文字，但一节课三百多段、十万字的英文语音识别稿，我自己是读不动的，识别错误还特别多（会计课把 "debit" 听成 "David"）。

所以我想做的事很具体：**把讲义和课堂转录合成一份中文精读笔记，让一个没听过课、零基础的人也能靠它自学；而且笔记里每一句"教授说"都带时间戳，能回到转录去核对，不允许 AI 编。**

第二个动机更个人一点。我想弄清楚，让大模型做长文档知识工程，到底需要什么样的规则、什么样的验收、会在哪里出错。这个库就是我的实验场，所有规则文件和验收脚本都是在做的过程中一点点逼出来的，不是事先设计好的。

## 一篇笔记长什么样

每篇笔记都是同一副骨架，九节：§0 三分钟速览 → §1 知识衔接 → **§2 正文** → §3 一图看懂 → §4 速查表 → §5 双语术语卡 → §6 考点预判 → §7 自测 → §8 讲义页码映射 → §9 延伸与勘误。

§2 里每个概念一个小节，小节内部固定七格：**是什么**（先说人话，再给定义）→ **为什么需要它** → **课件原例** → **🎙️ 课堂补充** → **💡 换个说法** → **⚠️ 常见误解** → **所以呢**（引向下一节）。公式型小节还要有符号表和一个手把手算的数字例子。

我最在意的是来源标记。笔记里每句话都能看出它从哪来：`（讲义 p.X）` 是课件原文，`🎙️` 加 `` `01:23:45` `` 是教授课上说的（引文里 `[ ]` 内是我对语音识别错误的更正），`💡` 是 AI 或我补的解释，`🔗` 是外部资料。考点也分三级：🔴 教授明说过的，🟡 从课程大纲反推的，⚪ 笔记自己猜的。**💡 和 ⚪ 是最容易错的地方**，读的时候心里要有数。

版本号只有两个：`v0.9` 表示只用了讲义，`v1.0` 表示课堂转录已经合并进去。

## 它是怎么建出来的

这个库不是"让 AI 帮我写笔记"，而是我写规则、AI 按规则干活、脚本验收、我抽查拍板。具体是这几层：

**1. 规则先于内容。** 根目录的 `CLAUDE.md`（Claude Code 读）和 `AGENTS.md`（Codex 等读）写清楚全库方法论；`_meta/笔记模板.md` 定骨架和七格；`_meta/笔记质量规范.md` 把"讲透了"拆成可以量化的门槛——每个小节至少多少字、公式型小节必须有哪些元素、💡 换个说法至少两个角度。AI 每次开工先读这些文件。

**2. 三个核心机制。** 一是**前置知识台账**：每门课记录"哪些概念算读者已知、哪些概念第几讲第一次出现"，写第 N 讲时不在表里的概念必须就地展开，这样零基础的人才读得下去。二是**正文按学习逻辑重排**：讲课顺序不等于学习顺序，笔记可以重排，但要附一张"笔记小节 ↔ 讲义页码"的映射表。三是**讲义 × 转录双源比对**：两个来源的差集最值钱——课上讲了课件没有的是最高价值内容，课件有但课上跳过的要降权。

**3. 转录融合有一套 SOP。** 在 `.claude/skills/transcript-merge/` 里：先登记转录（时间跨度、空档、是否缺头缺尾、前多少分钟是上周顺延的内容），再通读对齐，再把每一处 🎙️ 格填成四种状态之一（A 有原话可引 / B 教授照念讲义 / C 教授跳过 / D 录音没覆盖），最后跨文件回写考点库、术语表、作业 DDL。这套 SOP 是我把前几次用 Opus 手工做的过程标准化后写成的，目标是换成便宜的模型也能做到同样的形态。

**4. 验收靠脚本，不靠"看起来不错"。** 三个脚本在 `_meta/tools/`：`note_quality.py` 按质量规范打 L / G / E 三层门槛，判 PASS / FAIL（阈值怎么校准的记录在 `_meta/质量体检-2026-09-16.md`）；`transcript_check.py` 做 12 项检查，其中最重要的两项是逐个核对笔记里的时间戳是否真的存在于转录、每句引文用词组模糊匹配去转录里找——这是防止 AI 编造"教授说"的机制；`link_check.py` 查全库双链。脚本之外，写完还会派一个**没看过讲义的独立模型**按固定六道题试读，看零基础的人到底能不能读懂。

**5. 我做的部分。** 定规则、看回执、抽查引文回转录、决定哪些内容值得标 🔴、在 Notion 看板上追踪每一讲走到哪一步。"已通读"和"自测通过"两个勾是我自己的学习行为，AI 不碰。

## 我是怎么用 AI 的

工具链：Claude Code 是主力（Opus 做主代理，负责规则、任务拆分和验收；Sonnet 做子代理，负责按任务单干活和做独立验收）；Codex 帮我做另一个库；Notta 做录音转录；Obsidian 看笔记，同步走我自己服务器上的 WebDAV；Notion 做进度看板。

工作方式上有几条是吃过亏才定下来的：

- **子代理必须带任务单和进度文件。** 任务单写清输入、边界、必须回答的问题、验收命令；进度文件让它被打断后能接着做。没有这两样，长任务基本做不完整。
- **分块写、分块验。** 一篇笔记两三万字，让 AI 一次写完质量一定塌。现在是每写一块跑一次 `note_quality.py --strict`，不达标不进下一块。
- **给每个判断留证据。** 时间戳、页码、脚本输出。AI 说"教授强调了这一点"，我要能点开转录看到那一句。
- **文件安全。** 2026-09-17 我出过一次事故：三篇笔记被截成半截——脚本整读整写不是原子操作，同步插件恰好抓到写了一半的文件传上去又拉回来覆盖了完整版，其中一篇后半部分丢了，最后是从手机上还没同步的版本找回来的。更危险的是发现损坏后子代理开始"凭记忆重写"那篇笔记去顶替。现在的规则是：写文件一律原子写（`_meta/tools/safe_write.py`）、开工前快照收工后比对（`integrity_check.py`）、每次开工先备份（`backup_vault.py`）、发现损坏只许停下报告不许重建、AI 运行期间关掉自动同步。这几条写在根 `CLAUDE.md` 的「文件安全协议」里。

做到现在最大的体会是：规则文件比 prompt 重要，验收脚本比感觉重要，让 AI 把"我不确定"写出来比让它把每一格都填满重要。

## 怎么用

- **在读这几门课的同学**：直接看 `*/notes/`。以官方材料为准，尤其是考试和作业；每篇笔记的 §9.3 / §9.5 列了已知的讲义问题和待核对项。发现错误请开 Issue，写明笔记文件、小节号、讲义页码。
- **想用同一套方法做自己的课**：`_meta/`、`.claude/skills/`、根 `CLAUDE.md` / `AGENTS.md` 拿去改课程名就能用，步骤见 [[开源仓库说明]] §7。
- **下载与打开**：`git clone` 或 Download ZIP，约 80 MB（其中 67 MB 是课程材料）；用 Obsidian `Open folder as vault` 打开根目录即可，仓库不含任何社区插件和同步配置。GitHub 网页也能直接看公式和 Mermaid 图，只是 `[[双链]]` 点不了。
- **版权**：`*/course_files_export/`（讲义、数据集）和 `*/transcripts/`（课堂转录）**只用于核对笔记里的引用，未经版权方许可禁止下载和再分发；侵权请联系我删除**。转录是语音识别输出，不是源音频，也没有逐字校对过。笔记和规则的授权见 `LICENSE.md`（脚本与规则 MIT，笔记正文 CC BY-NC-SA 4.0）。

## 我知道的局限

- 笔记是 AI 生成 + 我复核，不是官方材料，一定还有我没发现的错。
- 转录错误率高，会计课最差；引用时按讲义纠正并用 `[ ]` 标出改动，但不保证每处都对。
- 2026-09-16 之前写的 12 篇笔记还没按新版质量规范返工，`_meta/质量体检-2026-09-16.md` 列了哪些 FAIL、差在哪。
- 只有 EF5560 建了可复现代码库，其他课的数字来自笔记里注明的临时脚本，没有全部入库。
- 学期还在进行中，这个库会一直改。

## 三个核心机制

**① 前置知识台账** — 每门课 `_meta/知识层级台账.md` 记录「L0 入场基线」和「每个概念首现于哪一讲」。写第 N 讲时，不在表里的概念**必须就地展开**并登记回表。这是"读到第 N 讲不出现陌生概念"的机制保证。

**② 正文按学习逻辑重排** — 课件顺序是讲课顺序，不是学习顺序。正文重排，另附「笔记小节 ↔ 讲义页码」映射表。

**③ 讲义 × 转录双源比对** — 讲义是"教授准备讲什么"，转录是"教授实际讲了什么"。**两者的差集最值钱**：课件没有但课上讲了的（🎙️ 最高价值）、课件有但课上略过的（⏭️ 可降优先级）、教授明说会考的（🔴 直接考点）。
