## 我为什么做这个

我的基础是机器学习和数据分析，AI / 机器学习的东西读起来不费劲；但这五门课里有三门落在我完全没学过的领域——法律与伦理学（IS5113）、会计（AC6761）、金融（EF5560）——课件上一页"Balance sheet"我要查半天才知道每一行在说什么。

课的形式也决定了光看课件不够。教授的 PPT 是"准备讲什么"，课上讲的才是"实际讲了什么"：哪道练习题的答案讲义留白了课上才给、哪句"you don't have to memorize this"、哪个例子是教授临时加的、哪几页教授直接跳过——这些全在录音里，课件上一个字都没有。我每节课都录音转成文字，但一节课三百多段、十万字的英文语音识别稿，我自己是读不动的，识别错误还特别多（会计课把 "debit" 听成 "David"）。

所以我想做的事很具体：**把讲义和课堂转录合成一份中文精读笔记，让一个没听过课、零基础的人也能靠它自学；而且课堂引文都有来源定位：有时间戳资料逐源核时间，无时间戳第三方文字用固定物理页／行定位，不允许 AI 编造。**

第二个动机更个人一点。我想弄清楚，让大模型做长文档知识工程，到底需要什么样的规则、什么样的验收、会在哪里出错。这个库就是我的实验场，所有规则文件和验收脚本都是在做的过程中一点点逼出来的，不是事先设计好的。

## 本地课程问答扩展（2026-09-24 原型）

这套知识库也作为一个**独立本地课程问答 Agent** 的只读资料来源。问答程序保存在本人另一处面试准备工作区的 `projects/cityu-course-agent/`，不包含在本仓库；索引写到 vault 外的本机 scratchpad，模型文件存放在本机 `E:` 盘。运行问答不会修改本库的笔记、讲义或转录，也不会把课程材料传给云模型。

原型将五门课的笔记按标题、PDF 讲义按页、PPTX 按幻灯片、课堂转录按时间切成可检索文本，保留课程、来源类型、笔记版本和定位符。当时索引包含 **3,723 个笔记块、1,390 个讲义块、1,225 个转录块**。检索可选 SQLite FTS5 中文双字关键词、[Qwen3-Embedding-0.6B](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B-GGUF) 本地语义向量或 RRF 融合；本地 Qwen3-4B 根据证据生成带编号引用的回答，无证据或引用无效时拒答。`agent` 模式只允许模型决定是否**额外检索一次**，工具只读、有步数上限，不是通用自主 Agent。

**小型开发烟测**：16 道人工选取的课程题按“正确来源文件＋具体页码／小节／时间”统计 Recall@5，关键词为 **13/16**、语义检索 **15/16**、混合检索 **13/16**。这些题在开发过程中用于检查和修正检索，**不是独立留出测试**，也不等于答案正确率。复杂问题曾触发再检索后生成无引用答案；当时的原型会拦截这类输出。图像页、PPTX 演讲者备注和更深层材料尚未完整索引；转录有 ASR 错误。对原始讲义、转录和整理笔记的可靠性要分别判断，尤其不能把笔记的现行质量 PASS 当成事实正确证明。

目前**没有完成课程问答模型的 SFT / LoRA 微调**。课程事实继续由检索库提供；后续只有在独立标注题证明引用、拒答或格式行为存在稳定缺陷时，才评估是否微调回答模型。这个问答原型是本知识库的伴随应用，不改变上文的笔记生产与验收流程。课程材料和转录的使用边界仍以 [NOTICE.md](NOTICE.md) 为准。

## 一篇笔记长什么样

每篇 Module 笔记保留 §0–§9 导航：§0 三分钟速览 → §1 知识衔接 → **§2 正文** → §3 一图看懂 → §4 速查表 → §5 双语术语卡 → §6 考点预判 → §7 自测 → §8 讲义页码映射 → §9 延伸与勘误。

§2 按学习任务和依赖组织：具体问题 → 对象与动作/状态 → 中间理由 → 结果与抽象 → 边界和迁移。七格不再逐概念强制展示；完整原例、课堂来源与必要机制深度保留。今后完稿后由未参与写作的独立子代理按高中知识起点审查，作者自查和脚本均不能替代。

我最在意的是来源标记。笔记里每句话都能看出它从哪来：`（讲义 p.X）` 是课件原文，`🎙️` 加 `` `01:23:45` `` 是带时钟的课堂来源；明确无时间戳第三方文字用 `` `U1 p.01 L003–L010` `` 定位，未核音频不自动认定说话人（引文里 `[ ]` 内是我对语音识别错误的更正），`💡` 是 AI 或我补的解释，`🔗` 是外部资料。考点也分三级：🔴 教授明说过的，🟡 从课程大纲反推的，⚪ 笔记自己猜的。**💡 和 ⚪ 是最容易错的地方**，读的时候心里要有数。

版本号只有两个：`v0.9` 表示只用了讲义，`v1.0` 表示现有课堂转录已经纳入。缺讲义的第三方转录整理单独标明，版本不代表整堂课或讲义全覆盖。

## 它是怎么建出来的

这个库不是"让 AI 帮我写笔记"，而是我写规则、AI 按规则制作、独立 agent 按高中知识起点实读、脚本辅助查有限问题、我保留反馈纠错。具体是这几层：

**1. 规则先于内容。** 根目录的 `CLAUDE.md` 和 `AGENTS.md` 是不同工具的入口；共同验收标准是 [笔记模板](_meta/笔记模板.md)、[笔记质量规范](_meta/笔记质量规范.md)、[课件题目处理规则](_meta/课件题目处理规则.md)、[对抗自检清单](_meta/对抗自检清单.md)、[材料处理规则](_meta/材料处理规则.md) 和 [转录融合流程](.claude/skills/transcript-merge/SKILL.md)。课程目录下的规则补充本课上下文。笔记质量还需核对原始材料、人工试读，不能只凭脚本 PASS；讲义原题要按 [题目覆盖台账](_meta/课件题目覆盖台账.md) 逐问验收。

**2. 三个核心机制。** 一是**前置知识台账**：每门课登记概念首现和依赖，帮助定位前置；登记不证明读者掌握，当前推理所需仍须就地唤醒或展开。二是**正文按学习逻辑重排**：讲课顺序不等于学习顺序，笔记可以重排，但要附一张"笔记小节 ↔ 讲义页码"的映射表。三是**讲义 × 转录双源比对**：两个来源的差集最值钱——课上讲了课件没有的是最高价值内容，课件有但课上跳过的要降权。

**3. 转录融合有一套 SOP。** 在 `.claude/skills/transcript-merge/` 里：先登记转录（时间跨度、空档、是否缺头缺尾、前多少分钟是上周顺延的内容），再通读对齐，再把每一处 🎙️ 格填成五种状态之一（A 有课堂增量 / B 与讲义一致 / C 有证据略过 / D 所有录音缺失 / E 教授明确留到下讲），最后跨文件回写考点库、术语表、作业 DDL。这套 SOP 是我把前几次用 Opus 手工做的过程标准化后写成的，目标是换成便宜的模型也能做到同样的形态。

**4. 教学靠独立实读与事实核对，脚本查有限机械问题。** `_meta/tools/note_quality.py` 默认按现行规则检查 L / C / R，并另存历史 G/E 诊断；`transcript_check.py` 核对带时间戳转录的时间与引文；`untimed_source_check.py` 核无时间戳公开文本、页行及局部引文；同课双录音还用 `transcript_source_check.py` 把 A/B 引用分别对回各自来源；`link_check.py` 与 `readme_check.py` 检查全库链接和首页状态。脚本之外还要对原材料与笔记做人工核对、零基础试读；任何脚本 PASS 都不等于事实全对。

**5. 我做的部分。** 定规则、看回执、抽查引文回转录、决定哪些内容值得标 🔴、在 Notion 看板上追踪每一讲走到哪一步。"已通读"和"自测通过"两个勾是我自己的学习行为，AI 不碰。

## 我是怎么用 AI 的

工具链曾以 Claude Code 为主，现由 Codex 接手维护整个 CityU 知识库；两者都须遵循上面同一套质量规范，并以原文和验收记录判断成果。录音转录现用本地 Whisper（早期文件来自 Notta）；Obsidian 用于阅读，Notion 用于进度追踪。

工作方式上有几条是吃过亏才定下来的：

- **子代理必须带任务单和进度文件。** 任务单写清输入、边界、必须回答的问题、验收命令；进度文件让它被打断后能接着做。没有这两样，长任务基本做不完整。
- **先完成候选，再集中验收。** 作者按学习单元改写并做必要的来源、计算和文件安全核对；所有候选完稿后集中检查语义与实际图文显示。发现具体缺陷才定点修复，不重复全库 Q/R，也不以机器 PASS 代替读懂。
- **给每个判断留证据。** 时间戳、页码、脚本输出。AI 说"教授强调了这一点"，我要能点开转录看到那一句。
- **文件安全。** 2026-09-17 我出过一次事故：三篇笔记被截成半截——脚本整读整写不是原子操作，同步插件恰好抓到写了一半的文件传上去又拉回来覆盖了完整版，其中一篇后半部分丢了，最后是从手机上还没同步的版本找回来的。更危险的是发现损坏后子代理开始"凭记忆重写"那篇笔记去顶替。现在的规则是：写文件一律原子写（`_meta/tools/safe_write.py`）、开工前快照收工后比对（`integrity_check.py`）、检查 Git 恢复基线并在每批完成后提交、推送和核实远端（2026-10-21 起取消日常全库 ZIP）、发现损坏只许停下报告不许重建、AI 运行期间关掉自动同步。这几条写在根 `CLAUDE.md` 的「文件安全协议」里。

做到现在最大的体会是：规则文件比 prompt 重要，验收脚本比感觉重要，让 AI 把"我不确定"写出来比让它把每一格都填满重要。

## 规则体系

**规则文件是这个知识库的核心。** 笔记是每次任务的产物，规则则规定 agent 如何读取材料、解释概念、使用来源、检查结果和安全写回。把这些要求保存在仓库里，是为了在换模型、换工具或会话中断后，仍能沿用同一套工作标准，也能定位一次失败究竟漏了哪条要求。

我把“零基础能自学”“引用可追溯”“图文能配合着读”拆成具体的写作要求、核对动作和发布条件。规则提供质量控制的基础；脚本负责检查它能判断的部分，解释是否讲清、原文是否被误读、图义是否正确，仍须实际核对。

### 规则如何分层

- **全库入口**：[AGENTS.md](AGENTS.md) 面向各类 agent，[CLAUDE.md](CLAUDE.md) 是 Claude Code 的对应入口。这里规定读者基础、必读文件、原始材料保护、文件安全和任务边界。
- **共同标准**：根 `_meta/` 保存教学语言、笔记结构、机制理解、来源、练习和验收规则。教学语言以[可读性总规则](_meta/可读性总规则.md)为唯一现行入口，日常制作与写回以[笔记制作与融合验收流程](_meta/笔记制作与融合验收流程.md)衔接。
- **课程补充**：各课程的 `AGENTS.md` / `CLAUDE.md`、可读性细则、前置知识台账补充学科背景。例如会计要解释账户和跨期确认，金融要解释收益分母与样本区间，伦理法律要讲清事实到判断的推理。
- **当前任务**：任务单写明本次材料、核心主题、允许修改范围、顺延内容和交付条件。子代理必须收到真实规则路径与任务边界，不能只被告知“照以前的质量做”。

课程细则不能降低共同标准。遇到旧文件或历史样板与现行语言、验收流程冲突时，按现行规则处理并修正冲突；不能为了省事挑较宽松的一条。正式评分作业另按教师题面和作业规范，不把课堂笔记模板机械套进提交稿。

### 每类规则解决什么问题

**把知识讲清楚。** [笔记模板](_meta/笔记模板.md)组织速览、知识衔接、正文、图示、术语、自测和来源映射；[可读性总规则](_meta/可读性总规则.md)要求先说明具体问题，再展开对象、动作、中间结果和理由，随后命名术语或写公式。它同时约束句段、表格逐列读法、公式符号、代码说明、信息分层及图文配合。[机制理解与可读性标准](_meta/机制理解与可读性标准.md)进一步要求核心方法有完整过程、依据、可复算例、停止条件和失败／变式解释；懂 AI / ML 不代表本讲核心算法可以略讲。

**保留材料覆盖和来源边界。** [材料处理规则](_meta/材料处理规则.md)规定讲义、文档、代码及其他材料怎样读取和存放；[课件题目处理规则](_meta/课件题目处理规则.md)要求逐小问回答并说明过程，页码映射不能替代正文讲解。[转录处理规则](_meta/转录处理规则.md)区分课件内容和课堂增量，要求识别 ASR 错误、缺录与顺延。没有录到不能写成“教授略过”，笔记推断也不能写成教授答案。

**让图真正帮助理解。** [教学图示规范](_meta/教学图示规范.md)规定何时需要局部图、怎样回源和解释图义；[教学图示工具流程](_meta/教学图示工具流程.md)分别安排 Mermaid、Graphviz 和 Matplotlib。复杂图保留可编辑图源，图旁说明路径、符号、具体例和条件；渲染成功与语义正确、阅读尺寸合适分别核对。

**区分学习解析与正式作业。** [课堂练习完成与解析规范](_meta/课堂练习完成与解析规范.md)要求逐问答案、难句拆解、过程、总结与改条件练习。[作业规范](_meta/作业规范.md)及其课程细则约束题面核实、正式答卷和私人学习材料的分工。参考解完成、官方答案已核、本人学会和已经提交是不同状态。

**把要求落实到交付。** [笔记质量规范](_meta/笔记质量规范.md)保留结构诊断和历史校准；[对抗自检清单](_meta/对抗自检清单.md)提供覆盖、真实性、连贯性和教学缺口的核对问题。[笔记制作与融合验收流程](_meta/笔记制作与融合验收流程.md)把这些标准接到候选、一次集中核对、验收记录与正式写回。[机制笔记子代理任务模板](_meta/机制笔记子代理任务模板.md)用于给代理一次交清范围、来源、解释深度和成功条件。

**让转录融合也执行同一套标准。** [通用融合技能](.claude/skills/transcript-merge/SKILL.md)与 [Codex 技能入口](.agents/skills/transcript-merge/SKILL.md)保持同步，配套[任务单](.agents/skills/transcript-merge/reference/task-brief-template.md)、[内容及回执模板](.agents/skills/transcript-merge/reference/formats.md)、[ASR 纠错词典](.agents/skills/transcript-merge/reference/asr-dictionary.md)。新增课堂解释、上一讲回填、受影响的图表和自测，都必须符合当前规则，不能只把原话翻译后塞进笔记。

### agent 从接单到写回要经过什么

1. **读规则和原材料。** 明确读者、核心主题、逐页逐题范围、已有概念和未知内容；转录按全文对齐，保留每个独立音源的时间戳。
2. **保存基线，制作候选。** 开工检查 Git 恢复基线并建完整性快照，关闭自动同步，不生成日常全库 ZIP；原件只读。分片代理只在 vault 外的任务目录写候选和补丁，保存原文件字节与 SHA-256。
3. **按规则完成解释。** 新写／整篇重写覆盖全部适用正文；局部融合覆盖全部新增及受影响单元。来源定位、重要计算复算和必要渲染可以在创作时进行。
4. **候选完成后集中核对一次。** 检查解释链、适用机制要求、来源、R 层疑点和图文实际显示。批量任务等整批候选完成；发现具体缺陷后，只修复并核对受影响部分，不反复全库盲读或补造评分。
5. **绑定证据，通过发布门槛。** `review.md` 记录实际检查的位置和结果，`review.json` 绑定源文件、候选、报告及相关图源的哈希。待核事项不能直接填成通过。运行[统一发布检查器](_meta/tools/note_release_gate.py)；[融合器](_meta/tools/merge_apply.py)也会在正式写入前调用检查。
6. **由单一写者安全落盘。** 写前重新核对源文件，发现并发变化则停止覆盖；通过后用[原子写工具](_meta/tools/safe_write.py)写入并回读，收批核对链接、README 和文件完整性。候选完稿、机械预检、教学核对、已写回分别记录。

这里的“发布”是候选写回正式笔记。Git 提交和推送仍需要仓库主人授权；Notion 的“已通读”“自测通过”等本人学习字段也不能由 agent 代勾。

### 脚本能保证什么，哪些仍需判断

[note_quality.py](_meta/tools/note_quality.py)默认输出 L（格式）、C（内容证据）与 R（可读性）；旧 G/E 配额保存在 JSON historical 字段，显式 historical 模式可查。C.hard 阻塞机器与发布门槛，C.warn 须人工核对；原题未传清单时明确未验证。新写／整篇整改使用 `readability_rules: v2`，已有 v1/v2 笔记也须清零适用 R 机械硬项。R 层的语义疑点必须逐项判断真实缺口、误报或合理保留；旧 G/E 字数和标签失败如实报告，不能靠凑篇幅取得教学通过。**D 层是机制理解的实质要求，不是一个自动评分结果。**

[transcript_check.py](_meta/tools/transcript_check.py)检查融合结构、时间戳和引文线索；[transcript_source_check.py](_meta/tools/transcript_source_check.py)辅助逐源核对。它们不能单独证明课堂录音完整、答案正确或解释易懂。`v0.9` / `v1.0` 表示材料融合阶段，不是教学质量等级。

统一发布检查器会拦截适用的 L/R 失败、检查器异常、缺失或未完成的教学记录，以及核对后发生变化的候选／报告／登记资产；融合器还核对正式源文件是否改变。哈希只证明“核对记录对应这一版文件”，不能证明记录中的判断正确。因此，来源、推理、数值和实际看图必须真正完成。未直接查看正式 Obsidian 阅读视图时，也要如实说明实际查看了什么。

链接与状态由 [link_check.py](_meta/tools/link_check.py)、[readme_check.py](_meta/tools/readme_check.py)辅助检查；[integrity_check.py](_meta/tools/integrity_check.py)负责文件完整性；[backup_vault.py](_meta/tools/backup_vault.py)仅在显式 `--create` 时临时归档，无参数不生成／删除 ZIP，日常版本由 Git/GitHub 保存。检查器已知误报、材料缺口及未验范围均保留在回执中，不能合并成一句“全部通过”。

## 三个核心机制

**① 前置知识台账** — 每门课 `_meta/知识层级台账.md` 记录「L0 入场基线」和「每个概念首现于哪一讲」。台账帮助定位而不证明掌握；写第 N 讲时，当前依赖就地解释/唤醒，新概念登记回表；独立审查核是否仍有缺桥梁。

**② 正文按学习逻辑重排** — 课件顺序是讲课顺序，不是学习顺序。正文重排，另附「笔记小节 ↔ 讲义页码」映射表。

**③ 讲义 × 转录双源比对** — 讲义是"教授准备讲什么"，转录是"教授实际讲了什么"。**两者的差集最值钱**：课件没有但课上讲了的（🎙️ 最高价值）、课件有但课上略过的（⏭️ 可降优先级）、教授明说会考的（🔴 直接考点）。
