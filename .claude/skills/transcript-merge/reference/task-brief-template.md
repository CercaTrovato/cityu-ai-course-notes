# 转录融合任务单模板

> 主代理（或用户）在派发前填好，存到 `<课程>/_meta/转录融合任务-M0N.md`。执行者开工第一件事是读它。
> 目的：把"只有读过上一讲笔记 / 扫过转录的人才知道的事"一次性交给执行者，避免它从零摸索或漏掉顺延。

```markdown
---
type: 任务单
course: 〈课程码〉
module: 〈N〉
created: 〈日期〉
---

# 转录融合任务 · 〈课程码〉 M0N

## 1. 输入
- 转录：`〈课程目录〉/transcripts/M0N-transcript.txt`（已按 §5 改名；原 Notta 文件名：〈…〉）
- scan 结果（〈日期〉）：〈段数〉 段，`〈起〉 → 〈止〉`，时长 〈…〉，时序倒退 〈无/有〉，≥120 秒空档 〈N〉 处：〈列出区间与初判性质〉
- 目标笔记：`〈课程目录〉/notes/M0N-….md`（v0.9，〈N〉 个 🎙️ 格其中 〈M〉 个"待转录补充"；§9.2 有"转录到手后要做的事"清单 〈K〉 条）
- 讲义：`〈文件〉`（〈页数〉 页）；notebook / 附件：〈…〉
- 上一讲笔记：`notes/M0(N−1)-….md`，其 §9.1 / §9.5 里标 ❓ 的项：〈列出〉

## 2. 主代理已做的判断（执行者需核实，不是照抄）
- 完整性初判：〈缺开头 / 缺结尾 / 完整〉，依据：〈首句 / 末句〉
- 顺延边界：`〈ts〉` 之前是上一讲内容（〈什么内容〉），本讲讲义从 `〈ts〉` 开始（依据：〈原话〉）
- 空档性质初判：〈…〉
- 信号词命中里值得先看的：〈exam/quiz/upload/group … 各几处，时间戳〉

## 2b. 分片表（分片模式；每片一个代理，并行）
| 片 | 转录时间段 | 目标笔记 | 笔记行号范围 | 🎙️ 格数 | 小节 | 本段信号词时间戳 |
|---|---|---|---|---|---|---|
| shard_spill | `00:01`–`49:04` | `notes/M0(N−1)-….md` | §2.6–§2.7（行 〈a〉–〈b〉） | 2 | … | … |
| shard_1 | `49:04`–`01:19:45` | 本讲 | 行 〈a〉–〈b〉 | 18 | §2.1–§2.4 | important 01:05:54 … |
| shard_2 | `01:19:45`–`02:24:04` | 本讲 | 行 〈c〉–〈d〉 | 17 | §2.5–§2.9 | exam 01:14:37 … |

自验命令（各片在自己的工作目录里跑）：
`merge_apply.py <工作目录> --note <笔记> --transcript <转录> --dry-run`

## 3. 本次必须回答的问题（按优先级）
1. 〈上一讲 ❓ 的页是否在本讲录到〉
2. 〈讲义答案栏空白的练习题，课堂解答〉
3. 〈教授是否点明 …〉
4. 〈作业 / 提交渠道 / 截止 / 参与记录方式〉
5. …

## 4. 交付
- 按 `.claude/skills/transcript-merge/SKILL.md` 全流程；验收命令：
  `transcript_check.py audit 〈笔记〉 --transcript 〈本讲转录〉 〈上一讲转录（若顺延）〉`
- 顺延回填后对上一讲也跑 audit（两份转录都给）
- note_quality 模式：〈legacy / strict〉（融合前判定：〈PASS/FAIL 及项目〉）
- 回执写到工作目录 PROGRESS.md 并汇报

## 5. 不做的事
- 〈例如：不改 Notion（主代理做）；不重写 v0.9 正文的讲义部分；不动 course_files_export〉
```
