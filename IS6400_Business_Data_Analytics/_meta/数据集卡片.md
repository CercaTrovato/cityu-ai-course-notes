### 3.1 缺失机制（这是本数据集最值得讲的一点）

**`review_scores_rating` 的缺失不是随机的，是结构性的：**

| | 有评分 | 评分缺失 |
|---|---|---|
| **`number_of_reviews` > 0** | 52,858 | **841** |
| **`number_of_reviews` == 0** | **0** | **14,434** |

- **14,434 条（94.5% 的缺失）是因为这个房源一条评论都没有** —— 没人评价当然没有评分。这属于 **MNAR（非随机缺失）中的结构性缺失**：缺失本身携带信息（= 新房源 / 无人问津的房源）。
- **剩下 841 条是真正的异常**：有评论却没有评分。⚪ 可能是评论者只写文字未打分，或原始数据抓取时丢失。
- ✅ **两列 host_* 的 180 个缺失是完全同一批行**（`both missing = 180`，`only pic = 0`，`only identity = 0`）。说明是整行的房东信息缺失，不是两个独立事件。

> ⚠️ **建模含义**：如果直接 `dropna()`，会一次性丢掉 22% 的样本，而且丢掉的**系统性地是新房源**，剩下的样本对"老房源"过度代表。更合理的做法是新增一列 `has_review = (number_of_reviews > 0)`，把缺失当成一种状态而不是一个待填的洞。⚪ 这是笔记补充，讲义与 tutorial 都没讲。
>
> 💡 **tutorial 为什么没踩到这个坑**：`Week 2 Regression Analysis` 只选了 `['property_type','accommodates','bathrooms','bedrooms','beds']` 五个特征，**恰好全是零缺失列**，所以 `LinearRegression` 不会报错。**但 W02 作业第 4 题要求加入 `cancellation_policy`（也零缺失），一旦有人自作主张加 `review_scores_rating`，sklearn 会直接抛 `ValueError: Input contains NaN`。**

## 4. 目标变量

**因变量是 `log_price`**（notebook cell 27 明写 `target='log_price'`）。

### 4.1 它到底是什么

`log_price` = **ln(每晚价格 USD)**。证据：对 `log_price` 取 `exp` 后，**与最近整数的最大偏差只有 9.99 × 10⁻⁷**，即还原后全是整数美元价。

| 分位 | `log_price` | `exp()` → 实际价格（USD/晚） |
|---|---|---|
| min | 1.609438 | **\$5** |
| 1% | 3.367296 | \$29 |
| 5% | 3.688879 | \$40 |
| 10% | 3.912023 | \$50 |
| 25% | 4.290459 | \$73 |
| **50%（中位数）** | **4.700480** | **\$110** |
| 75% | 5.192957 | \$180 |
| 90% | 5.700444 | \$299 |
| 95% | 6.021023 | \$412 |
| 99% | 6.856462 | \$950 |
| max | 7.600402 | **\$1,999** |

| 统计量 | 值 |
|---|---|
| mean(`log_price`) | 4.774962 |
| std(`log_price`) | 0.711940 |
| **偏度 skewness** | **0.5257**（轻微右偏） |
| **峰度 kurtosis** | 0.6230 |
| 0 或负值 | **无**（价格最低 \$5，ln 后为正） |
| `exp(mean(log_price))`＝几何均价 | **\$118.51** |
| 算术均价 `mean(exp(log_price))` | **\$158.55** |
| 中位价 | **\$110** |

### 4.2 为什么用 log 而不用 price

| 理由 | 说明 |
|---|---|
| **拉正态** | 原始价格是典型的右偏长尾（\$5 到 \$1,999，均值 \$158 却中位数 \$110）。取对数后偏度只剩 **0.53**，接近对称 —— 正好满足 [[M02-预测分析-线性回归#2.5.2 四条假设（讲义 p.17–18，⭐ 必考）\|M02 §2.5.2]] 的第 2 条"Y 在每个 X 处服从正态" |
| **把乘性效应变成加性** | 房价更接近"多一间卧室贵 **20%**"而不是"贵 **\$40**"。取对数后 `Δlog_price` 就是百分比变化，正好被线性模型的加法结构接住 |
| **压住极端值的杠杆** | \$1,999 的房源在原尺度上会强烈拉动回归线；在 log 尺度上它只是 7.6 vs 中位数 4.7 |

> ⚠️ **系数怎么读**（本课最容易漏掉的一步，讲义与 tutorial 都没讲）：
> 因变量取了 log 之后，系数 **b 不是"涨多少美元"，而是"涨百分之多少"**：
> `X 每增加 1 个单位 → 价格约变化 (e^b − 1) × 100%`。
> 例：notebook cell 31 里 `accommodates` 的系数是 **0.170006**，`e^0.170006 − 1 = 0.1853`，意思是**每多能住 1 个人，房价约上涨 18.5%**（不是"上涨 0.17 美元"）。
> b 较小时可直接近似成 `b × 100%`（0.17 → 约 17%），但 b 越大误差越明显。
> 详见 [[T02-回归实战-从合成数据到Airbnb定价#5.4 ⭐ 系数怎么翻译成生意话|T02-回归实战-从合成数据到Airbnb定价 › 5.4 ⭐ 系数怎么翻译成生意话]]。

### 4.3 目标变量与各数值自变量的相关系数（Pearson，实跑）

| 自变量 | 与 `log_price` 的相关 |
|---|---|
| `accommodates` | **0.5781** |
| `bedrooms` | **0.4827** |
| `beds` | **0.4697** |
| `bathrooms` | 0.3768 |
| `review_scores_rating` | 0.0883 |
| `number_of_reviews` | **−0.0249** |

> 💡 **两个可以直接写进项目报告的观察**：
> ① 价格几乎完全由**容量**（住几个人 / 几间房 / 几张床）决定，**口碑几乎不影响价格**（评分相关只有 0.09）。
> ② `number_of_reviews` 与价格**负相关**（−0.025，极弱）。⚪ 一个合理解释是便宜房源成交更多、因而评论更多，但这是相关不是因果，报告里不要写成"评论越多价格越低"。

## 5. 已知坑

### 5.1 ⭐ 严重多重共线性（做多元回归必踩）

四个"容量类"自变量彼此高度相关：

| | accommodates | bathrooms | bedrooms | beds |
|---|---|---|---|---|
| **accommodates** | 1.0000 | 0.5230 | 0.7244 | **0.8290** |
| **bathrooms** | 0.5230 | 1.0000 | 0.6089 | 0.5377 |
| **bedrooms** | 0.7244 | 0.6089 | 1.0000 | 0.7298 |
| **beds** | **0.8290** | 0.5377 | 0.7298 | 1.0000 |

`accommodates` 与 `beds` 相关高达 **0.829**。而 tutorial 把这四个**同时**放进模型 —— 结果就是 notebook cell 31 输出里 **`beds` 的系数是负的（−0.056）**：

```
[ 0.17000603  0.13795161  0.12490194 -0.05628411 -0.19173624  0.12103869 -0.17429126]
  accommodates  bathrooms   bedrooms    beds        House       Loft      Town House
```

**"床越多房价越低"显然违反常识。** 这就是多重共线性的典型症状：在已经控制了 `accommodates` 和 `bedrooms` 之后，`beds` 剩下的独立信息很少，系数符号变得不稳定。

⚠️ **写项目报告时不要照抄这个系数当结论。** 处理办法（M04 讲了前两种）：删掉冗余变量（特征选择）、或做 PCA（特征约简）、或用 Ridge 压系数。

### 5.2 编码不一致

**同一份文件里，布尔类信息用了两种编码：**

| 字段 | 编码 | pandas 读进来的 dtype |
|---|---|---|
| `cleaning_fee` | `True` / `False` | **`bool`**（可以直接参与运算） |
| `host_has_profile_pic` | `'t'` / `'f'` | **`object`（字符串）**（不能直接算，要先映射） |
| `host_identity_verified` | `'t'` / `'f'` | **`object`（字符串）** |

用这三列建模前必须先统一：`df['host_identity_verified'].map({'t': 1, 'f': 0})`。

### 5.3 极端稀有类别（one-hot 之后会变成灾难）

| 类别 | 行数 | 占比 |
|---|---|---|
| `cancellation_policy = super_strict_60` | **8** | **0.012%** |
| `cancellation_policy = super_strict_30` | 105 | 0.154% |
| `bed_type = Couch` | 235 | 0.345% |

**8 行**样本会产生一个几乎全是 0 的虚拟变量列。它的系数会被极少数样本主导，方差极大，且一旦 `train_test_split` 把这 8 行全分到测试集，训练集里那一列就是常数 0。

⚠️ **W02 作业第 4 题正是"把 `cancellation_policy` 加进模型"**，所以这个坑一定会遇到。做法：把 `super_strict_30` 与 `super_strict_60` 合并成一个 `super_strict` 类。⚪ 笔记补充。

**顺带**：`super_strict_60` 那 8 条房源的平均 `log_price` 是 **6.3142（≈\$552）**，比整体中位数高 5 倍。也就是说，**这 8 行既极稀有又是价格极端值**，杠杆特别大。

### 5.4 近零方差字段

`host_has_profile_pic` 有 **99.43% 都是 `'t'`**（只有 208 个 `'f'`）。这种字段几乎不携带信息，放进模型只会增加方差。**建议直接丢弃。**

### 5.5 不合常理的取值

| 现象 | 行数 | 说明 |
|---|---|---|
| `bathrooms == 0` | **129** | 一个没有卫生间的房源。⚪ 可能是共用卫生间未登记 |
| `beds == 0` | **4** | 没有床。逐条看：其中 2 条 `bedrooms=1` 却 `beds=0`（自相矛盾） |
| `beds < bedrooms` | **847** | 床比卧室少 |
| `bedrooms == 0` | 6,000 | ✅ **这个是合理的** —— 开间/studio 就是 0 卧室 |
| `bedrooms == 0` 且 `accommodates > 4` | 179 | 一个开间住 5 人以上，可疑但不必然错（可能是多张沙发床） |

四条 `beds == 0` 的明细：

| id | log_price | property_type | accommodates | bedrooms | beds | bathrooms | city |
|---|---|---|---|---|---|---|---|
| 7922378 | 5.129899 | Apartment | 2 | **1** | **0** | 1.0 | SF |
| 20269147 | 5.783825 | House | 2 | 0 | 0 | 1.0 | NYC |
| 8684344 | 4.691348 | Apartment | 2 | 0 | 0 | 1.0 | Boston |
| 15419976 | 5.991465 | House | 4 | **1** | **0** | 1.0 | NYC |

### 5.6 样本代表性 / 潜在偏见

| 维度 | 情况 | 后果 |
|---|---|---|
| 地理 | **只有美国 6 城**，且 **NYC + LA 占 75.1%** | 模型学到的是"纽约洛杉矶的定价规律"，直接套到香港或其他城市会失效 |
| 房型 | `property_type` **只剩 4 类**（原始 Kaggle 版有 30+ 类，Hostel、Boat、Treehouse 等已被剔除） | 模型对非主流房型无预测能力 |
| 床型 | Real Bed 占 **97.24%** | 另外四类几乎学不到东西 |
| 时间 | **没有任何时间字段**。看不出数据抓于何时，也无法建模季节性 | ⚠️ 房价有强季节性，这份数据完全无法处理；**做小组项目若想讲"淡旺季"，这份数据做不到** |
| 价格上限 | max = \$1,999，是个**整数上限**的形状 | ⚪ 疑似原始数据在 \$2,000 处做过截断 |

> 🔗 **跨课交叉**：地理与房型的代表性问题，正是 IS5113（AI Ethics）W03「偏见与公平」讲的**采样偏差（sampling bias）**在本课的真实实例。可以拿它当那门课的案例。

### 5.7 `id` 不是特征

`id` 是 `int64`、取值 344 – 21,230,903，看起来像个数值特征。**必须显式排除**，否则模型会去拟合"编号越大越贵"这种伪规律（Airbnb 的 id 是递增的，因此 id 大约等于"上架时间晚"，还真会有虚假相关）。tutorial 通过手动指定 `feature=[...]` 白名单规避了这个问题。

## 5. 已知坑

### 5.1 三行完全重复 + UCI 记载的两处录入误差

| 行（0 起） | 内容 | 说明 |
|---|---|---|
| 9、**34**、**37** | `4.9, 3.1, 1.5, 0.1, Iris-setosa` | 三行完全相同 |
| 101、142 | `5.8, 2.7, 5.1, 1.9, Iris-virginica` | 两行完全相同 |

🔗 UCI 的 `iris.names` 文档记载：与 Fisher 原文相比，**第 35 行**（0 起 34）第 4 列应为 0.2（文件是 0.1），**第 38 行**（0 起 37）第 2、3 列应为 3.6、1.4（文件是 3.1、1.5）——本文件保留了这两处误差，因而与第 10 行重合，造成前三行重复。101 / 142 的重复在 Fisher 原文中就存在。**影响**：`drop_duplicates()` 会删掉 3 行（150 → 147，setosa 48、virginica 49），各类不再均衡；本课两份 notebook 都**没有**去重，作业若去重要说明。

### 5.2 与 sklearn 自带的 load_iris() 不完全一致

sklearn ≥ 0.20 的 `load_iris()` 已按 Fisher 原文修正了上述两行；用本文件与用 `load_iris()` 跑 PCA / 重要性，数值会有第 3–4 位小数的差别（T04 cell 31 的 `z` 首行 −2.6842 / 0.3266，`load_iris()` 版为 −2.6841 / 0.3194）。**作业统一用 `iris.txt`。**

### 5.3 类别列是字符串，标签顺序按字母

`Iris-setosa` < `Iris-versicolor` < `Iris-virginica`——sklearn 内部按此编码 0 / 1 / 2；`groupby` 与 `pairplot` 的图例顺序也是这个。

### 5.4 特征之间高度相关

| | sepal-L | sepal-W | petal-L | petal-W |
|---|---|---|---|---|
| sepal-L | 1 | −0.109 | 0.872 | 0.818 |
| sepal-W | −0.109 | 1 | −0.421 | −0.357 |
| petal-L | 0.872 | −0.421 | 1 | **0.963** |
| petal-W | 0.818 | −0.357 | 0.963 | 1 |

petal-L 与 petal-W 相关 **0.963**——两列几乎冗余（M04 §2.4），这是 PCA 一个主成分就能保留 92.5% 方差的原因（`verify_w3w4.py`：方差比 0.9246 / 0.0530 / 0.0172 / 0.0052，未标准化）。

### 5.5 量纲相同、方差悬殊

四列都是厘米，但方差 0.686 / 0.188 / **3.113** / 0.582——不标准化直接 PCA，PC1 几乎就是 petal-L 方向（载荷 0.86）；标准化后 PC1 方差比降到约 0.73。T04 没标准化，作业若换做法要说明。

### 5.6 它太"干净"

无缺失、无离群、类别均衡、线性可分（setosa）——**在它上面成立的结论不一定能推到真实数据**；T03 用它练完手立刻换 Airbnb 就是这个意思。
