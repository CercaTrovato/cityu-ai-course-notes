2. **类别与尺度（§2.1 b）**：可复述“箱数为计数，所以离散数量型；0 箱为没有卖出，所以在本例是比率尺度；Easter 的 0/1 为类别标志，不表示程度”。能分清编码数字与测量数值。该例的真实来源单位待第二阶段核对，第一阶段只确认正文推理可跟随。

## 发现与处置建议

### S1-B1：模板应用检查缺少最小操作桥梁，建议修后定向复核

位置：ProjectTemplate-逐页使用导览.md 第 94、101、107–118、141–143 行。

**具体断点**：§3–§4 要初学者先核 run、区分 H04/R3/冻结检查/F0/G1/G2，以及 80/20 fit/cal 和同名 F0 的权重。我能照正文写出“这些不能混”，但正文没有说明 run 是一次怎样被标识的运行、训练／开发／冻结后期检查各拿哪些数据做什么，fit 与 cal 两部分各做什么。因而无法仅凭正文解释为什么 43 与 50 的训练条件不同，或执行“确认哪个 run／相同权重”的第一步。现有表只给整文件入口，不能用抽检者自己的项目／ML 知识补齐后判通过。校准本身已有一句定义，仍不足以解释未展开的 fit/cal 动作。

**最小修法**：在使用表前后补一个短操作桥梁即可：解释 run 为一次固定数据范围、处理方式、参数／权重、模型与评价条件的运行记录；用一个真实项目记录示例指出“到登记表核哪些字段、各字段回答什么”。再用几句解释训练用于学参数、开发用于比较选择、冻结后检查用于观察较后时期而不回流改选；fit/cal 的 80/20 分别用于拟合与校准，训练数据条件改变使 43 与 50 不能直接归因于校准优劣。若这属于另篇已讲的核心内容，提供精确教学小节回链，并在当前核查动作旁保留一句唤醒。无需在导览展开全部模型或重写准备包。

**阻塞范围**：阻塞“高中知识起点能按 §4 独立做 A06 运行身份／协议核查”的声称；不阻塞模板六章映射和复盘计算样本。尚未据此要求全篇重审。
