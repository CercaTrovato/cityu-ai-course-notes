## A · AI 范式与历史

| 中文 | English | 英文定义（可默写） | 首现 |
|---|---|---|---|
| 生成式 AI | Generative AI | AI that produces new outputs from learned probability distributions instead of selecting only from fixed responses. | M01 §2.2 |
| ELIZA | ELIZA | A rule-based conversational program (Weizenbaum, MIT, 1964–66); its DOCTOR script used pattern matching, scripted rules and reflective replies. | M01 §2.3.2 |
| ELIZA 效应 | ELIZA Effect | Users attributing empathy and intelligence to a system; "ELIZA's power came from **the user's interpretation, not genuine understanding**." | M01 §2.3.2 |
| 符号 AI | Symbolic AI | Representing knowledge explicitly with symbols, logic and if–then rules. Strength: **transparency**. Limitation: **brittle** when rules cannot cover real-world ambiguity. | M01 §2.4.1 |
| 专家系统 | Expert System | Encoding expert knowledge as rules for repeatable decisions. | M01 §2.4.1 |
| 可扩展性墙 | Scalability Wall | The point where rule bases grow faster than teams can maintain them. | M01 §2.4.1 |
| AI 寒冬 | AI Winter | A period when exceptions exceeded system capability and funding retreated. | M01 §2.4.1 |
| 统计机器学习 | Statistical Machine Learning | Estimating patterns from examples instead of hand-coding every decision rule; **trades explicit rules for data-dependent performance**. | M01 §2.4.2 |
| 漂移 | Drift | Change in the data-generating environment after deployment. **The world changed, not the model.** | M01 §2.4.2 |
| 半监督学习 | Semi-supervised Learning | Learning from a small labelled set plus a large unlabelled set. | M01 §2.4.2 |
| 表示学习 | Representation Learning | Multi-layer networks learn useful representations **directly from large datasets**, instead of humans deciding how data should be represented. | M01 §2.4.3 |
| 特征工程 | Feature Engineering | Humans manually specifying which measurable attributes a model should use. | M01 §2.4.3 |
| AlexNet | AlexNet | 2012 ImageNet winner: 5 conv + 3 FC layers, ≈60M parameters, GPU-trained; **top-5 error 15.3%** (runner-up ≈26%). | M01 §2.4.3 |
| 残差连接 | Residual Connection | A shortcut path letting a block learn only **the residual**—what needs to change relative to the input—making much deeper networks trainable. | M01 §2.4.3 |
| 基础模型 | Foundation Model | A large pretrained generative model adaptable across tasks, modalities and business processes. | M01 §2.4.4 |
| 四范式并存 | Four Paradigms Coexist | Symbolic AI, statistical ML, deep learning and foundation models **continue to coexist**; 🎙️ "the paradigms are **building blocks, not competing brands**." | M01 §2.4.4 |

## B · LLM 内部机制

| 中文 | English | 英文定义（可默写） | 首现 |
|---|---|---|---|
| one-hot 编码 | One-Hot Encoding | A vocabulary-size vector identifying a token but conveying **no semantic distance**. | M01 §2.5.2 |
| token | Token | A discrete unit of text; **one word may be one token or several** depending on the vocabulary. | M01 §2.5.2 |
| 嵌入 | Embedding | A dense learned vector representing a token; encodes features but **not position**. | M01 §2.5.2 |
| 位置编码 | Positional Encoding | Information added so the model knows where a token appears in the sequence. | M01 §2.5.2 |
| 上下文向量 | Contextual Vector | The representation after position and attention; **the same token identifier yields different vectors in different sentences**. | M01 §2.5.2 |
| 自注意力 | Self-Attention | Each token attends to other tokens with **learned, per-sentence weights—not fixed dictionary meanings**. | M01 §2.5.3 |
| 多头注意力 | Multi-Head Attention | Learning several relationship patterns between token positions in parallel. | M01 §2.5.3 |
| Transformer | Transformer | An architecture replacing recurrence with attention over the full sequence. **"Training becomes parallel, while generation still proceeds token by token."** | M01 §2.5.3 |
| 自回归生成 | Autoregressive Generation | At each step the model predicts a distribution over the next token, selects one, appends it and repeats. | M01 §2.6.1 |
| 解码策略 | Decoding | How a probability distribution becomes the next token. | M01 §2.6.1 |
| 温度 | Temperature | A control exposing a trade-off between **consistency and diversity**. | M01 §2.6.1 |
| 大语言模型 | Large Language Model (LLM) | A large, pretrained language model: scale + self-supervised pretraining + adaptation. **There is no single numerical threshold for "large".** | M01 §2.6.2 |
| 预训练 | Pretraining | Self-supervised objectives learning reusable representations; **labels are derived from the data itself**. | M01 §2.6.2 |
| 适配 | Adaptation | Prompting, retrieval, fine-tuning and tools that specialize behaviour for a business task. | M01 §2.6.2 |

## C · 可信与架构

| 中文 | English | 英文定义（可默写） | 首现 |
|---|---|---|---|
| 不透明性 | Opacity | The internal cause of a specific output is hard to observe, but **sources, versions, tool calls and approvals can be audited**. | M01 §2.7.2 |
| 可信 AI 三支柱 | Capability / Evidence / Control | Capability measures accuracy, robustness, latency and cost; Evidence grounds outputs and preserves provenance; Control applies permissions, monitoring, human review and incident response. **"A strong model is only one component of a trustworthy business system."** | M01 §2.7.3 |
| 神经符号 AI | Neuro-Symbolic AI | Hybrid systems combining neural flexibility with **interpretable, controllable logic for high-stakes use**. | M01 §2.7.4 |
| 任务契合 | Mission Fit | "The best enterprise model is the one that **meets the mission within operational and governance constraints**." | M01 §2.8.1 |
| 六向量 | Six Vectors | Modality, latency, performance, context, throughput, cost. **"Improving one vector can weaken another; prioritize the dominant business failure cost."** | M01 §2.8.1 |
| 首字延迟 | Time To First Token (TTFT) | The delay before the response begins (prefill). | M01 §2.8.3 |
| token 间延迟 | Inter-Token Latency (ITL) | How quickly the rest of the answer appears (decode). | M01 §2.8.3 |
| 有效上下文 | Effective Context | The context a model actually uses well; **an internal benchmark, not a standardized model specification**. | M01 §2.8.5 |
| 中间迷失 | Lost in the Middle | Stronger use of information near the **beginning and end** of a document than in the middle. | M01 §2.8.5 |
| 吞吐 | Throughput | Total work completed across many requests; a **system-level** metric (vs latency, a user-level metric). | M01 §2.8.6 |
| 批处理 | Batching | Grouping requests to raise fleet utilization, **at the cost of per-request latency**. | M01 §2.8.6 |
| 总拥有成本 | Total Cost of Ownership (TCO) | Input tokens + output tokens + retrieval and tools + hosting + people and controls. | M01 §2.8.6 |
| 复合 AI | Compound AI | Routing each request to the least expensive capable component; improves cost and control **through selective allocation—not merely a larger model**. | M01 §2.8.7 |
| 路由器 | Router | The component that identifies task type and difficulty and dispatches to a small model, retrieval, tools, or human review. | M01 §2.8.7 |

## D · 治理与责任 AI

| 中文 | English | 英文定义（可默写） | 首现 |
|---|---|---|---|
| 确定性 vs 概率式 | Deterministic vs Probabilistic | Deterministic systems follow predefined logic and can be tested exhaustively; probabilistic systems vary with sampling, context and model updates, so **testing must focus on distributions of outcomes**. | M01 §2.9.1 |
| 分布式评估 | Distributional Evaluation | Repeated evaluation across scenarios rather than one expected response. **"A single successful demonstration tells us almost nothing about reliability."** | M01 §2.9.1 |
| 幻觉 | Hallucination | Models optimize plausible continuation, not objective truth, so false statements can be delivered with confidence. **"Fluency must never be treated as evidence."** | M01 §2.9.2 |
| 接地 | Grounding | Connecting model output to approved evidence and controlled system actions: **ground, log, validate, escalate**. | M01 §2.9.3 |
| RAG | Retrieval-Augmented Generation | Grounding generation in retrieved, approved **external** evidence. 🎙️ Unlike reasoning, it **can** reduce hallucination because the evidence is verified by humans. | M01 §2.9.3 |
| 证据链 | Evidence Chain | **"Audit what the system did and what evidence it used; do not treat hidden reasoning as an audit record."** | M01 §2.9.4 |
| 提示注入 | Prompt Injection | Crafted input that induces the model into unauthorized behaviour. | M01 §2.9.5 |
| 检索投毒 | Poisoned Retrieval | Contaminating the knowledge base so the "approved evidence" itself is compromised. | M01 §2.9.5 |
| 纵深防御 | Defence in Depth | Red teaming, content provenance, input/output filters, permission boundaries. **"Security is a lifecycle discipline—not a one-time model evaluation."** | M01 §2.9.5 |
| 记忆式相似 | Memorized Similarity | Output-side IP risk where generated content closely resembles protected training material. | M01 §2.9.6 |
| 人口均等 / 机会均等 | Demographic Parity / Equalized Odds | Example fairness metrics; **"No single fairness metric is universally correct; goals and trade-offs must be documented."** | M01 §2.9.7 |
| 申诉渠道 | Recourse | A path for affected people to contest or correct an AI-influenced decision. | M01 §2.9.7 |
| NIST AI RMF | NIST AI Risk Management Framework | Voluntary, non-sector-specific framework organizing risk work into **Govern, Map, Measure, Manage**; a common language, **not a certification or one-time checklist**. | M01 §2.10 |
| 可接受风险 | Acceptable Risk | **"Probabilistic systems cannot eliminate uncertainty, but organizations can govern it to explicit tolerances."** | M01 §2.10 |
| 残余风险 | Residual Risk | Risk remaining after treatment; must be **explicit, monitored, and accepted** by a named owner. | M01 §2.10 |

## E · 模型全景与基准评测（M02）

| 中文 | English | 英文定义（可默写） | 首现 |
|---|---|---|---|
| 训练四阶段 | Pretraining / Instruction training / Preference (reward) training / Application inference | "Different training stages shape broad capabilities, instruction following and preferred response behavior." Pretraining → broad representations; instruction training → task and instruction following; preference / reward training → behavior aligned with the training objective; application inference → a response for the current request. | M02 §2.3 |
| 能力 ≠ 数据访问 | Capabilities vs data access | "A model's capabilities and its application's data access come from different components." | M02 §2.3 |
| 🎙️ 奖励作弊 | Reward hacking | 🎙️ "exploiting a weakness in the scoring system without achieving our real goal"—e.g. a scorer that rewards longer answers teaches the model to pad. | M02 §2.3 |
| 每美元推理 | Reasoning per dollar | 🎙️ "how much useful reasoning do we get for the money we spend"; a cheaper model that needs three attempts may cost more overall. | M02 §2.5.2 |
| 🎙️ 轮 | Turn | A unit of interaction during an agent's work (read, edit, run tests…); fewer turns may suggest less wasted work, but not automatically lower cost. | M02 §2.5.2 |
| 🎙️ 有益合规 vs 不必要拒答 | Helpful compliance vs Unnecessary refusal | 🎙️ "If we only reward refusal, a model can appear safe by declining almost everything… We need to measure helpful compliance and unnecessary refusal together." | M02 §2.8.9 |
| 🎙️ 世界模型 | World model | 🎙️ A model that "tries to represent the aspects of environments and how they can change"; the direction Fei-Fei Li's World Labs pursues (product: Marble). | M02 §2.2 |
| 开放权重模型 | Open-weight model | Weights are published and self-hostable (on-prem or air-gapped); full fine-tuning, quantization and distillation of the actual weights; permissive licensing (MIT / Apache 2.0). | M02 §2.4 |
| 闭源专有模型 | Closed proprietary model | Cloud-API only, subject to the vendor's hosting and data-retention terms; architecture, training data and safety testing largely undisclosed; vendor-managed updates with enterprise SLAs. | M02 §2.4 |
| 开放 vs 闭源结论 | Bottom line (p.8) | "Closed labs still lead on peak capability and turnkey support; open-weight labs win on cost, control, and customization. Speed no longer tracks license type." | M02 §2.4 |
| 量化 | Quantization | Reducing the numerical precision of weights to shrink and speed up a model. | M02 §2.4 |
| 蒸馏 | Distillation | Training a smaller model to imitate a larger model's outputs. | M02 §2.4 |
| 混合专家 | Mixture of Experts (MoE) | A sparse architecture in which each token activates only a subset of expert sub-networks; total parameters set capacity, active parameters set per-token compute. | M02 §2.5.2 |
| 基准 | Benchmark | A fixed task set with fixed scoring rules that makes model scores comparable. | M02 §2.7 |
| 十类四组 | Ten benchmark categories in four groups | A Core capabilities (can it solve the underlying task?), B Business information (can it interpret the input and support the answer?), C Reliable interaction (can it act consistently and handle users safely?), D Overall value (how does task quality translate to a useful deliverable?). | M02 §2.7 |
| 饱和 | Saturation | Frontier models approach a benchmark's ceiling so scores no longer differentiate capability; "SWE-bench Verified is saturating." | M02 §2.6.5 |
| 基准生命周期 | Benchmark lifecycle | "A broad benchmark launches, labs optimize against it, it saturates within 2–3 years, and a harder successor replaces it — MMLU → MMLU-Pro → GPQA → ARC-AGI → HLE." | M02 §2.8.1 |
| 数据污染 | Data contamination | Overlap between training data and a test benchmark; "contamination (problems leaking into pretraining) is now the central threat to any public math benchmark." Four levels: semantic, information, data, label (DCR). | M02 §2.8.2、§2.9.2 |
| 思维链 | Chain-of-thought (CoT) | Writing intermediate reasoning steps before the answer; "CoT now clearly beats direct answering" on MMLU-Pro. | M02 §2.8.1 |
| 校准 | Calibration | Whether a model's expressed confidence matches its actual accuracy; SimpleQA grades correct / incorrect / not-attempted. | M02 §2.8.1 |
| pass@k | pass@k | The probability that at least one of k sampled solutions passes the tests (HumanEval). | M02 §2.8.3 |
| pass^k | pass^k | The probability that all k runs of a task succeed; "pass^k metric exposed inconsistency — retail pass^8 fell to ~25% even when pass^1 was ~60%." | M02 §2.8.7 |
| CircularEval | CircularEval | Shuffled-choice evaluation of multiple-choice items to guard against guessing; drops naive scores 10–20+ points. | M02 §2.8.4 |
| 有效上下文长度 | Effective context length | The longest context at which accuracy stays above a threshold (RULER) — "often far below advertised." | M02 §2.8.5 |
| 内在 / 外在幻觉 | Intrinsic / extrinsic hallucination | Output contradicting the given input vs. output adding unsupported content; distinguished by HalluLens. | M02 §2.8.6 |
| 模仿式谬误 | Imitative falsehood | Confidently repeating common human misconceptions (TruthfulQA); "larger, more capable models have historically been less truthful on imitative-falsehood tests." | M02 §2.8.6 |
| LLM-as-judge | LLM-as-judge | Using a strong model to grade other models' outputs; cheaper than human voting but gameable (length bias). | M02 §2.8.8 |
| Elo 评分 | Elo rating | Pairwise rating system: expected win probability depends on the rating gap; ratings update after each blind comparison (LMArena). | M02 §2.8.8 |
| 排行榜幻觉 | The Leaderboard Illusion | A crowdsourced leaderboard distorted by selective private testing and unequal sampling. | M02 §2.8.8 |
| 越狱 | Jailbreak | Adversarial prompting that bypasses a model's refusal behavior (HarmBench, JailbreakBench). | M02 §2.8.9 |
| 增益 | Uplift | The additional dangerous capability a model gives a malicious user (WMDP, Cybench as proxies). | M02 §2.8.9 |
| 前沿安全框架 | Frontier safety frameworks | OpenAI's Preparedness Framework, Anthropic's RSP and Google DeepMind's Frontier Safety Framework "tie quantitative thresholds directly to release-gating decisions." | M02 §2.8.9 |
| 复合指数 | Composite index | One number aggregating many benchmarks with weighted, frequently revised categories (AA Intelligence Index). | M02 §2.8.10 |
| 真实经济价值基准 | Real-world economic value benchmark | Tasks with direct economic meaning graded against real professional deliverables (GDPval: 1,320 tasks, 9 sectors, 44 occupations). | M02 §2.8.10 |
| 协议 | Protocol | "A score is evidence under a protocol, not a universal measure of model quality." | M02 §2.9.1 |
| 快照 | Snapshot | A dated leaderboard reading; "They are not a controlled experiment." | M02 §2.9.3 |
| 任务级评测协议 | Task-level evaluation protocol | "A reproducible evaluation fixes the task set, inputs, scoring rules and operating conditions": task specification → controlled comparison → scoring and slices → independent holdout. | M02 §2.10.1 |
| 每接受任务成本 | Cost per accepted task | "Cost per accepted task = total evaluated workload cost / number of accepted tasks." | M02 §2.10.1 |

## G · agent 与 harness（M03）

> 来自 [[M03-AI-agent-从harness到部署]] v0.9（无转录，英文定义取讲义原句）。"强化学习"为本讲用到、L0 里没有的背景词。

| 中文 | English | 英文定义（可默写） | 首现 |
|---|---|---|---|
| agent | Agent | A system that pursues a defined outcome (goal), chooses tools and observes real results (action), and continues, stops or requests help within limits (control). The model helps choose actions; the application executes tools and enforces the limits. | M03 §2.4.1 |
| 固定工作流 | Fixed workflow | A system in which product logic defines the route; the model may perform isolated steps but does not choose the next step. | M03 §2.4.2 |
| 多 agent | Multiple agents | A coordinator delegates tasks to several agents; worthwhile when subtasks are independent. | M03 §2.4.2 |
| 范式转移 | Paradigm shift (from synthesis to sovereignty) | From generative AI as a passive oracle in a request-response loop ("describing the world") to agentic AI as an active operator in a perception-action loop ("changing the world"). | M03 §2.4.3 |
| 目标导向自主性 | Goal-directed autonomy | Accepting high-level objectives rather than step-by-step instructions, and independently decomposing objectives and prioritising actions. | M03 §2.4.4 |
| 感知—行动循环 | Perception-action loop | A closed feedback loop: perceive → reason → act → learn; the agent acts to change the environment and observes the result. | M03 §2.4.4 |
| 工具编排 | Tool orchestration | Decoupling intelligence from utility: the agent actively uses external tools (browsers, APIs) via protocols such as MCP. | M03 §2.4.4 |
| 状态与持久性 | State & persistence | The ability to maintain episodic memory, recall past actions and resume tasks over long horizons, overcoming the stateless nature of raw LLMs. | M03 §2.4.4 |
| 自主性等级 | Autonomy levels | L1 chained automation (rule-based) → L2 workflow agents (router-based, humans approve critical changes) → L3 partially autonomous (bounded domain, human-on-the-loop) → L4 fully autonomous (strategic oversight only). | M03 §2.4.5 |
| 人在环上 | Human-on-the-loop | Supervision by reviewing final outputs rather than approving each step; contrasted with human-in-the-loop. | M03 §2.4.5 |
| 认知架构 | Cognitive architecture | Systems such as ACT-R and Soar that integrate memory, reasoning and action into multi-step cognition. | M03 §2.3.2 |
| 深度 Q 网络 | Deep Q-Network (DQN) | DeepMind (2013): the first artificial agent to combine representation learning with reinforcement learning end to end — learning Atari from pixels. | M03 §2.3.2 |
| 强化学习 | Reinforcement learning | Learning by acting in an environment and adjusting to rewards, without labelled correct answers (background term). | M03 §2.3.2 |
| 计算机使用 | Computer use | A model that can see a screen, move a cursor, click and type — generalising the tool interface to any GUI software (Anthropic, Oct 2024). | M03 §2.3.3 |
| A2A 协议 | Agent2Agent (A2A) | A protocol for agents to exchange tasks (Google, Apr 2025; Linux Foundation; v1.0 Mar 2026); design question: who owns a delegated task and its result? | M03 §2.3.3 |
| 上下文工程 | Context engineering | Managing what enters the model's window across a task — replacing "prompt engineering" as the named practice. | M03 §2.3.4 |
| harness 工程 | Harness engineering | Designing the scaffolding around the model, not the weights — now the dominant lever on reliability. | M03 §2.3.4 |
| harness | Harness | The runtime layer around the model: the loop that keeps it running, the tools it can reach, the context it sees, the memory that outlives the session, the permissions that constrain it, the instrumentation that makes it debuggable. The model supplies judgement; the harness supplies everything else. | M03 §2.5.1 |
| harness 六元组 | H = (E, T, C, S, L, V) | A 2026 survey's formalisation: execution loop, tool layer, context management, memory & state, lifecycle hooks, evaluation & verification; the harness, not the model, is the primary determinant of agent reliability at scale. | M03 §2.5.1 |
| 执行循环 | Execution loop | The while-loop that makes an agent an agent: read context → decide action → execute → append observation → repeat. Without it you have a chatbot. | M03 §2.7.1 |
| ReAct | ReAct (Reason + Act) | The canonical form of the loop: reason → act → observe → repeat, grounding logic in external data. | M03 §2.7.1 |
| 终止条件 | Termination conditions | Max iterations, token budget, wall-clock, explicit 'done', or a satisfied verifier — what stops the loop. | M03 §2.7.1 |
| 工具层 | Tool layer | A typed catalogue of what the agent can do; curate ruthlessly, make errors legible, name unambiguously (parameters are prompt surface), annotate structurally. | M03 §2.7.2 |
| 模型上下文协议 | Model Context Protocol (MCP) | A standard way to connect tools and context ("USB-C for AI applications"); tools expose data via MCP servers and agents discover them without retraining. | M03 §2.7.3 |
| 技能 | Skill | Reusable instructions and task resources; design question: who maintains this procedure? | M03 §2.7.4 |
| 情景记忆 | Episodic memory | Stored past actions and outcomes (e.g. in a vector database) that the agent retrieves to avoid repeating mistakes. | M03 §2.7.5 |
| 语义记忆 | Semantic memory | Facts — access to knowledge bases and policy documents via RAG. | M03 §2.7.5 |
| 程序性记忆 | Procedural memory | Stored "recipes" for common workflows, executed without re-deriving the logic. | M03 §2.7.5 |
| 上下文腐烂 | Context rot | Performance degrades as context grows, because attention cost scales quadratically and models are trained predominantly on shorter sequences. | M03 §2.7.6 |
| 压缩 | Compaction | Summarise history before the limit — keep decisions made and open problems, discard redundant output. | M03 §2.7.6 |
| 工具结果清理 | Tool-result clearing | The cheapest safe first move: drop old tool-result bodies, keep the fact they happened. | M03 §2.7.6 |
| 即时检索 | Just-in-time retrieval | Hold lightweight references (paths, URLs) and load content only when needed. | M03 §2.7.6 |
| 渐进披露 | Progressive disclosure | Reveal detail in layers as the task narrows. | M03 §2.7.6 |
| 提示缓存 | Prompt caching | Keep the stable prefix identical to reuse it across turns — cuts cost and latency. | M03 §2.7.6 |
| 系统提示组装 | System-prompt assembly | Not a static string: assembled at runtime from a base persona, discovered project/org instructions, the tool catalogue and environment state; start minimal, add specificity only in response to observed failure modes. | M03 §2.7.7 |
| 持久规划文件 | Persistent planning artifact | A plan file the agent writes, updates and re-reads — doubling as memory and as a human-readable record of intent. | M03 §2.7.7 |
| agentic RAG | Agentic RAG | Choose sources and search again if evidence is weak; set freshness, citation and search-budget rules. | M03 §2.7.8 |
| 执行沙箱 | Execution sandbox | A container/VM isolating file and network access. | M03 §2.7.9 |
| 审批门 | Approval gate | A required human confirmation before irreversible actions. | M03 §2.7.9 |
| 容器逃逸 | Container escape | An agent breaking out of its sandbox; 15–35% rates reported across the systems the harness survey examined. | M03 §2.7.9 |
| 可靠性差距 | Reliability gap | The remaining ~10% of failures at 80–90% success that prevents fully autonomous deployment in critical infrastructure. | M03 §2.7.10 |
| Petrov 规则 | The Petrov Rule | High-stakes decisions (financial transfers, infra shutdowns) must require human confirmation; a human must always be present to challenge the system and bear ultimate moral responsibility. | M03 §2.7.10 |
| 身份蔓延 | Identity sprawl | Agents require API keys and service accounts, creating a massive attack surface where compromised agents can move laterally. | M03 §2.7.11 |
| 即时权限提升 | Just-in-time privilege elevation | Agents hold no permanent admin keys; they request temporary access tokens only when a specific task requires it. | M03 §2.7.11 |
| 零信任 | Zero trust | Treat agent identity with the same rigour as human identity: verify every access, least privilege, revocable. | M03 §2.7.11 |
| 生命周期钩子 | Lifecycle hooks | Injection points before/after each tool call, model call and session boundary — for authentication, logging, policy enforcement, redaction, cost tracking; customise a harness without forking it. | M03 §2.7.13 |
| 可观测性 | Observability | Answering after the fact: what did the agent do, why, what did each step cost, where did it go wrong — trajectory logging + tracing + per-step cost attribution. | M03 §2.7.13 |
| 轨迹日志 | Trajectory logging | Recording every observe–decide–act step of a run for later analysis; without a trace, debugging a non-deterministic agent is guesswork. | M03 §2.7.13 |
| 环内验证 | In-loop verification | The agent runs tests / a linter / a critic model and iterates until they pass — the single biggest driver of quality in coding agents. | M03 §2.7.14 |
| 离线评估 | Offline evaluation | Eval suites, CI integration and regression gates on harness changes. | M03 §2.7.14 |
| 评估效度 | Evaluation validity | Whether an evaluation measures what matters; currently the weakest component in the stack — benchmark success does not reliably predict real-world acceptance. | M03 §2.7.14 |
| 子 agent | Sub-agent | A fresh agent with its own clean context for a bounded subtask, returning a condensed summary rather than its whole trajectory. | M03 §2.8.1 |
| 编排 | Orchestration | Arranging sub-agents: hierarchical (lead + workers), parallel (fan out, fan in), sequential (pipeline); costs ~15× tokens and requires concrete briefs. | M03 §2.8.1 |
| Deep Research | Deep Research architecture | A lead agent divides the question; workers investigate aspects in parallel; a research loop closes gaps; the report carries citations. | M03 §2.8.2 |
| OpenClaw | OpenClaw architecture | A personal assistant runtime connecting channels, a gateway, an agent runtime, workspace & memory and tools with access policy & approvals. | M03 §2.8.3 |
| 网关 | Gateway | The component that routes requests, manages sessions and coordinates access and activity for all channels and device nodes. | M03 §2.8.3 |
| autoresearch | autoresearch architecture | Karpathy's repository: the human defines the experiment rules; a coding agent changes training code, a fixed evaluator scores it, and the change is kept or discarded. | M03 §2.8.4 |
| 固定评估器 | Fixed evaluator | The scoring component protected from agent edits (prepare.py · val_bpb); lower is better. | M03 §2.8.4 |
| 隐性知识 | Tacit knowledge | Knowledge that lives in experience and judgement rather than documents; support agents degrade where resolution depends on it. | M03 §2.9.4 |
| 蛋白质折叠 | Protein folding | Predicting the 3D shape a protein folds into from its amino acid sequence — a 50-year grand challenge in biology. | M03 §2.9.9 |
| AlphaFold | AlphaFold | DeepMind's system that predicted structures for 200M+ proteins and shared them openly; a scientific AI, not an LLM agent. | M03 §2.9.9 |
| 领域不对称模式 | Domain-asymmetry pattern | Agents succeed where the environment is deterministic and feedback is unambiguous, and struggle wherever it is organisational, tacit and contested. | M03 §2.9.11 |
| 任务专属评测集 | Task-specific evaluation set | Cases of four types — typical task, ambiguity, constraint conflict, failure or attack — each with expected behaviour; define success before testing; keep development and held-out cases separate. | M03 §2.10.4 |
| 每接受结果成本 | Cost per accepted outcome | Total variable cost (all attempts including failures, plus human review) divided by the number of accepted outcomes; exclude fixed costs explicitly. | M03 §2.10.5 |
| 影子模式 | Shadow / draft mode | Outputs are reviewed before any customer-facing action; monitor review burden and correction rate. | M03 §2.10.6 |
