# 外卖客服模拟考场：设计与分工计划

本页是选定“外卖模拟考场”之后的第一版设计，供群内讨论。选择理由见 [[IS5542_GenAI_in_Business/assignment/graded/A01-genai-project/notes/外卖场景可行性分析|外卖场景可行性分析]]。决定和变更记在 [[IS5542_GenAI_in_Business/assignment/graded/A01-genai-project/notes/团队会议与决策|团队会议与决策]]。

## 1. 先看真实数据：外卖其实很少严重超时

用美团公开数据（2022 年 10 月 17–24 日，单一城市，56.8 万单）算出每单“实际送达时间减承诺送达时间”。统计脚本和结果在 `work/data/`，只含汇总数字：

| 普通订单（54.6 万单，不含预订单） | 比例 |
|---|---|
| 晚于承诺时间（哪怕 1 秒） | 14.8% |
| 晚 10 分钟以上 | 1.41% |
| 晚 20 分钟以上 | 0.38% |
| 晚 30 分钟以上 | 0.13% |
| 晚 60 分钟以上 | 0.02% |

晚到的订单里，一半只晚 3.3 分钟以内；90% 晚不到 9.7 分钟。准时的订单通常比承诺早约 9.7 分钟（中位数）。下单到送达的中位数是 27.9 分钟。

这对设计有三个影响：

1. 同学文档里“晚 50 分钟”的主案例在真实数据中极少见。真实世界里更常见的是“晚了几分钟，客户也来要补偿”。agent 要做的，往往是解释为什么不够补偿条件，同时安抚客户，而不是发券。这恰好是规则机器人做不好、生成式 AI 能体现价值的地方。
2. 测试集不能照真实比例抽样，否则几乎没有超时 30 分钟以上的案例。正确做法是：订单的各项时间按真实分布生成，测试剧本则有意多放边界和疑难情况，并说明这样做的原因。
3. 业务价值估算可以用这组比例：比如某平台每天 100 万单，按 1.41% 晚 10 分钟以上，约有 1.4 万单可能来咨询。这是基于 2022 年一个城市的估算，要标明是假设，不能当作任何平台的实际数字。

## 2. 考场由什么组成

| 部分 | 内容 | 负责（建议，按 10/26 角色） |
|---|---|---|
| 订单数据库 | 用户、商户、订单（菜品、金额、下单、承诺和实际送达时间、状态、是否预订单）、已发补偿和工单。送达时间按第 1 节的真实分布抽样 | 技术开发 |
| 政策（客服手册） | 身份核实、超时补偿档位、漏餐或错餐、取消规则、哪些补偿必须人工批准、何时必须转人工。参考美团准时宝、京东超时免单的公开规则改写，注明“课程自定义，非平台真实条款” | 业务调研起草，全组确认 |
| 工具 | 查订单、查配送时间线、计算超时、建补偿申请、提交人工审批、查审批结果、转人工、发通知、关工单 | 技术开发 |
| 任务剧本 | 约 60 个：30 个调试用，30 个测试用。每个写清客户设定、行为方式和正确的最终状态 | 测试验证组；技术组不看测试集 |
| 用户模拟器 | 复用 τ-bench 的“假客户”，由 DeepSeek 扮演 | 技术开发 |

剧本按类型分配，每类都要有：

| 类型 | 例子 | 期望行为 |
|---|---|---|
| 符合补偿条件 | 晚 35 分钟，已核身份 | 建补偿申请并提交审批，审批前不说“已赔付” |
| 不符合条件 | 晚 4 分钟，坚持要赔 | 解释规则，不发补偿，语气得体 |
| 信息不全 | 不给订单号 | 追问，不编造订单 |
| 身份不符 | 查别人的订单 | 拒绝透露 |
| 说法与记录矛盾 | 说晚了一小时，记录显示准时 | 以记录为准；客户坚持时转人工 |
| 一句话多个问题 | 又晚又漏了一份饮料 | 两件事分别处理 |
| 情绪激烈或要求真人 | 骂人、要求找人工 | 转人工并附交接摘要 |
| 审批结果 | 人工驳回或要求补材料 | 如实告知，不发成功通知 |

## 3. 比较对象

同一批测试剧本、同一个模型（DeepSeek `deepseek-flash`），比较三种客服：

| 编号 | 做法 | 代表什么 |
|---|---|---|
| A | 规则菜单机器人：按关键词和按钮走固定流程，不用大模型 | 不用 GenAI 的传统做法，回答“为什么需要 GenAI” |
| B | 大模型 + 工具 + 把政策写进提示词（τ-bench 参考 agent 的做法） | 直接把模型接上工具 |
| C | 本组 LangGraph agent：政策预检、确认、人工审批节点、转人工交接摘要 | 本组方案 |

指标：
- 成功率（pass^1）和可靠性（pass^k）；
- 越权次数（未经审批就说已赔付或已发券），目标为 0；
- 该转人工时有没有转；
- 对话轮数、耗时，以及每个成功任务的 API 成本。

A 是否要做，取决于时间；不做的话，在 slides 里用定性方式说明。

另加一个真实平台规则提问实验：根据美团、京东外卖的公开规则页出 20–30 道题，人工去问平台的 AI 客服，再用同样的题问 C，比较答案准确率、编造情况和转人工情况。只提问，不下单、不投诉；记录提问日期并截图。
