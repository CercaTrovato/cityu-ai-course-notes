# 笔记制作与融合验收流程

本流程把 [[可读性总规则]] 接到日常制作与融合任务中，不另设语言标准。新笔记、课堂补充、顺延回填、速查与自测答案都适用。`transcript_check.py audit` 检查融合证据，不证明解释可读；`transcript: merged` / `status: v1.0` 仅说明材料融合状态，不能代替教学验收。

## 1. 开工和派单

执行者先读以下文件；主代理给子代理明确的真实路径，不能只说“按原来的质量”。

1. 根 `AGENTS.md`，本课规则及任务单。
2. `_meta/可读性总规则.md` 与 `<课程>/_meta/<课程码>可读性细则.md`。
3. `_meta/机制理解与可读性标准.md` 的当前简化流程、适用 D 层要求；本流程。
4. 笔记模板、概念台账、对应讲义及适用的原题处理规则。转录融合还须读 `transcript-merge/SKILL.md`、转录全文及目标笔记上下文。
5. 需要图示时读《教学图示规范》和《教学图示工具流程》。转录新增了步骤、条件或数值时，同时检查相邻正文、原图、公式、表格及自测是否需要更新。

派单写清目标、来源、核心主题、允许修改范围、scratch 路径和交付条件。新写／整篇整改的范围是全部适用正文；局部融合的范围是全部新增及受影响单元，包含上下文衔接和上一讲顺延内容，不自动扩大成全库整改。

所有候选、补丁和核对记录放在 `E:/app-data/codex/scratchpad/<英文任务目录>/`。子代理不写 vault。保存修改前原始字节与 SHA-256，不覆盖基线；新建笔记明确目标原先不存在。备份、快照、关闭自动同步、原件保护按根规则执行。

## 2. 写作约束

先提出具体问题，再展开对象、动作、中间结果和理由，最后命名或写公式。首次概念就地解释，独立学习单元唤醒旧概念；表格逐列交代含义、来源／算法、单位／频率／分母与一个值的读法。原话配中文解释，引用用于证据，不能代替教学过程。

每个适用核心主题交出完整过程、具体例、必要条件及失败／变式解释。算法、公式、代码等要求取并集；财会、法律、伦理按本课类型落实 D 层。保留页码、时间戳、来源区分、原题逐问答案和未知边界，不为压短句删除条件或改写来源数值。

图文按总规则 §11.3：先有学习问题，再说明路径／关系，用具体例走图，保持图文符号和条件一致，解释边界并给文字替代和读图自测。评估是否需要局部图，不能把“无图”默认当作不适用。引用已有图也须检查本次文字变化是否改变图义。

新写／整篇整改填 `readability_rules: v2`；局部融合保留既有 v1/v2，不降级或删除字段逃避检查。未启用该字段的旧稿，局部融合不凭一次局部核对宣称整篇达标。

## 3. 一次集中验收

创作时允许必要来源定位、重要计算复算、渲染与防损，作者最多一次整篇自查。任务候选完成后，主代理对本次范围集中做一次实质核对，可由主代理自己完成，不强制另派评分代理。批量任务在全部候选完成后集中进行；日常单篇以该篇候选完成为界。发现具体缺陷才修复并核对受影响范围，不恢复全库反复 Q/R、盲读或读者评分。

报告 `review.md` 按实际章节记录以下内容，不能只写四个“通过”：

- **理解与覆盖**：列本次全部受影响单元、核心问题、解释链及 D 层证据位置；核对逐页／逐题范围，指出修复过的缺口。新写按全篇，局部融合注明未复验的未改内容。
- **来源与计算**：页码／逐源时间戳、重要数字复算证据、推断与补充标记。已知材料缺失保留原限制；新增无依据断言或未完成的必要核对是阻塞项。
- **R 层疑点**：保留机器原始输出；适用范围内每个 △ 归为已修复、误报或合理保留，并列已有解释位置／理由。可以按同类问题合并记录，但须列齐位置。真实解释缺口不能靠退出码或豁免放行。
- **图文与视觉**：列图及相关正文、来源和可编辑图源，实际观看的渲染或最终载体、尺寸、路径和发现。没有查看就写待核，不能写 passed。没有受影响图且不需补图，写明判断理由，才可标 not_applicable。查看同源渲染不等于查看正式 Obsidian 阅读视图，分别记录。

运行 `note_quality.py <候选> --strict --sections --readability` 并保留 L/G/E/R 原始结果。下面的统一门槛会自动调用这一检查，直接运行门槛即可，不必重复运行。T 笔记按正式目标名识别类型，scratch 中叫 `candidate.md` 也必须按 T 检查。

L 问题须定位处理；机器误报要先修复检查器或提供经维护确认的处理，不悄悄跳过。新写／整篇整改、已有 v1/v2 笔记要求 R 机械 ✗ 为 0。旧 G/E 的字数、标签失败只作诊断，不能冒称 PASS，也不为凑分重复扩写。

未启用 v1/v2 的旧稿局部融合，机器仅保留完整未变单元的历史 R 硬项及未恶化的原有全文统计项；修改单元的硬项仍阻塞。报告须列出历史项，不能写整篇 R 通过。语义范围仍以本次全部受影响单元为准。

## 4. 回执与机器门槛

核对完成后由主代理保存 `review.md`，再写 `review.json`。哈希按真实文件字节计算，不能把示例、旧版本或空报告填成通过。`review.json` 是记录，不是正确性的数学证明；执行者必须实际完成 §3。

```json
{
  "schema": "note-review-v1",
  "note": "课程目录/notes/M0N-主题.md",
  "scope": "changed",
  "source_sha256": "修改前原始副本的 SHA-256；新笔记填 null",
  "candidate_sha256": "候选字节的 SHA-256",
  "review_file": "review.md",
  "review_sha256": "实质核对报告的 SHA-256",
  "checks": {
    "understanding": {"status": "pending", "evidence": "报告中的受影响单元与 D 层证据位置"},
    "sources": {"status": "pending", "evidence": "来源、计算与限制记录位置"},
    "warnings": {"status": "pending", "evidence": "R 疑点逐项处理位置；无疑点写实际结果"},
    "visuals": {"status": "pending", "evidence": "实际观看证据或不适用理由"}
  },
  "assets": [],
  "unresolved": ["尚未执行核对；按真实结果填写"]
}
```

只有实际完成才把前三项改为 `passed`，视觉改为 `passed` 或有理由的 `not_applicable`，并清空本次阻塞项 `unresolved`。已有材料限制写在报告和笔记里，不编造补齐。`assets` 列出本次核对的外部图源与渲染文件，每项为 `{"path": "相对回执路径或绝对路径", "sha256": "真实哈希"}`；纯内嵌图由候选哈希覆盖。外部资产未变也不能漏列本次实际依赖它的视觉证据。

新写／整篇重写使用 `--scope full`；局部修改使用 `--scope changed --source <原始副本>`。修改既有笔记不论 scope 都须提供 `--source`。只有新笔记无 `--source` 且 JSON 中 `source_sha256` 为真正的 `null`。

```powershell
D:\anaconda3\python.exe -X utf8 _meta/tools/note_release_gate.py <scratch候选.md> --note <正式相对路径> --scope full --review <scratch/review.json>
D:\anaconda3\python.exe -X utf8 _meta/tools/note_release_gate.py <scratch候选.md> --note <正式相对路径> --source <scratch原始副本.md> --scope changed --review <scratch/review.json>
```

仅需机械预检时用 `--check-only`，该结果不能当作教学验收或发布许可。工具异常、结果缺失、哈希不符、回执缺项或 pending 都阻塞正式门槛。修改候选、核对报告或图源后，先定向复核实际变化，再更新哈希；不为让工具通过而直接重算并覆盖证据。

## 5. 写回与完成状态

转录融合先 `merge_apply.py ... --dry-run` 生成 `merged.md`；全部候选完成后按 §3 核对这一文件，填写同目录 `review.json`，最后由单一主写者运行正式合并。合并器强制核对材料 audit、L/R 门槛、回执和候选／源／资产哈希；缺回执不能写 vault。整篇重写在 dry-run 与正式命令都传 `--scope full`。

新写或其他编辑也必须先通过统一门槛，再由主写者在写前重读正式目标：既有文件与基线哈希一致，新建目标仍不存在。调用 `safe_write.atomic_write`，并对写后字节回读核对候选哈希。合并器未负责的元文件共享修改，要重读后精确合并，不覆盖其他会话改动。

收批时做必要的链接、README 和完整性检查；顺延回填的上一讲按自己的候选、来源和回执单独核对。候选完稿、机械预检、教学核对、已写回分开记录；未实际观看的最终载体如实列出。只在用户授权提交／推送时操作 Git。用户学习状态与真人理解评分不得代填。

两份 `transcript-merge/SKILL.md`（`.claude` 与 `.agents`）及各自任务单／回执模板必须同步更新，不能留一份旧执行入口。此流程为日常工作长期有效规则；2026-10-09 全量整改的模型、批次与历史进度不自动套到未来任务。

## 6. 每次制作与融合后的同步闭环（五门课强制）

新写、重写、转录融合和顺延回填后，必须逐项同步适用目标并回读。笔记写回、材料 v1.0、教学验收、本地同步、Notion 同步、Git 提交／推送是不同状态，不能以其中一个完成替代其余项。此节是全库统一执行入口，覆盖 M / T 笔记；不增加重复盲读、评分轮次或额外审批。

### 6.1 适用目标与事实口径

- `README.md`：顶部当前库存、各课入口、五门课表、转录列、待办／最近完成、DDL 提示和目录树相关说明全部检查。当前库存从实际笔记 frontmatter 与转录文件计数；保留有日期的历史统计，不改写成当前值。`readme_check.py` 零问题只是辅助，仍须人工比对所有相关信息点。
- `<课程>/00-课程总览.md`：新增笔记、版本、材料缺口和当前验收限制；同一课其他讲未改变的状态不顺手升级。
- `<课程>/_meta/考点库.md`、`知识层级台账.md`、`术语表.md`：同步本次增量、首现与复用位置、来源和置信度，删除本次已兑现的“等待登记”表述。嘉宾观点不自动当作教授考试明示。
- `<课程>/_meta/待并入术语总表.md`：登记本次跨课或易混译名候选；由管理者指定的单一发布者重读根 `_meta/术语总表.md` 后精确合并适用增量，并回写已合并状态。不适用须写明理由；未合并须列为待办，不隐去。
- `<课程>/_meta/作业与DDL.md` 及适用的私有作业总览：同步已确认行政要求与缺口。无新要求记“不适用：无新增行政事实”；未确认的截止、题面、渠道不得推断，课堂活动、参考解析、可提交与本人已提交分开。
- `_meta/转录处理规则.md` §8：有新转录／融合就登记或更新该来源行，记录时间跨度、多源时钟、空档、缺首尾、顺延去向、融合状态与未核事项。教学／视觉未过不能只留完成勾号。
- Notion 学习进度与作业 DDL：按下节执行。同步范围包含本次顺延修改的上一讲，不能只更新新讲。

### 6.2 Notion 写入与回读

先读 `_meta/Notion进度看板.md`，定位既有正确数据库与 module／作业行，查重并读取当前字段；不要误改旧本科课表。仅按已验证事实更新材料复选框、笔记路径、版本与备注。材料 v1.0 不代表教学通过；未完成的教学、视觉、核听、来源缺口必须写进备注。已有“已通读／已掌握”等个人汇总状态不得因材料更新而降级覆盖。

保护 `👁️ 已通读`、`✅ 自测通过`、复习次数、下次复习以及本人提交／评分状态；保留既有备注，只精确更新本次内容。不因 AI 生成了笔记就代填本人行为。DDL 只同步课程已确认要求与待确认项，未知截止保持空缺，不编造日期。

优先使用 Notion 连接器；无可用连接器时检查现有已登录浏览器是否能完成同一工作，不得直接省略。登录、权限或工具确实阻塞时，保存精确的页面／行、字段、拟写值和阻塞原因，在回执列为“Notion 未同步”，不得称全任务同步完成。无需反复索取已获得的同步授权。

每次写入后重新读取目标行／页面，逐字段比对拟写值，并核对个人字段保持不变；工具返回成功或点击保存不等于回读验证。保存可复查的目标标识、写前／拟写／回读值及未核事项。

### 6.3 并发、收尾与交付

建立本次同步清单，每项记录“已写并回读／已核无增量／不适用及理由／阻塞及原因”和证据位置。共享文件写前重新读取，仅合并本任务增量；原始字节与哈希保存到本任务 scratch，发现源冲突停止该文件写入并重新合并，不覆盖别的会话基线。按文件安全规则原子写，写后重新读磁盘并核对内容及哈希。

一次完成适用链接、README 和自有基线完整性检查，报告具体残余问题；只因新发现的具体缺陷再定向核对。同步回读不替代正文发布前的教学／视觉门槛，也不能补造旧验收。

Git 仅在用户明确授权提交／推送时执行：提交前 fetch，复查 diff，仅暂存本次范围，不带入并发改动；不加 AI 署名、不绕过钩子、不 force push。回执分别列本地同步、Notion 回读、教学限制和 Git 状态；只有所有适用同步项完成并回读，才写“同步完成”。
