# 教学图示规范：何时画、怎样画、怎样核对

> 图要帮助第一次接触内容的人看懂关系或过程。正确性来自题面、原始数据、明确假设和实际核对；漂亮、能渲染、节点数对上都不能证明业务正确。未知事实不能被画成确定关系。按条件成立的参考图要写条件，不宣称是官方唯一答案。

本规范补充 [[笔记模板]]、[[机制理解与可读性标准]]、[[课堂练习完成与解析规范]] 和 [[作业规范]]，五门课共同执行。新写或修改正文时主动判断配图需求，放在难点附近；§3“一图看懂”不能代替 §2 就地讲解。原件、私人答案、正式交付和本人学习状态继续按原规则保护。

图文教学语义的唯一入口是 [[可读性总规则]] §11.3；长链条评估、走图例、读图自测与图文配合引用该处，本文件只保留图型、图源、来源和核对技术要求。整批末尾验收时机按总规则 §1.3：创作时允许必要渲染和防损，所有候选完稿后统一语义与视觉验收，不派中途验收。无法实际观看须待核；渲染成功不能写视觉通过。

## 1. 什么时候必须画图

遇到下列难点，图能承载准确含义时，必须提供对应图示及读图说明，不能只留抽象定义或指向课件截图：

| 理解障碍／题目要求 | 要画出什么 | 例子 |
|---|---|---|
| 题目明确要求模型、关系图、流程或结构 | 完整的指定图型，逐问满足对象与限制 | AC6761 的 REA Core model、关系模型 |
| 核心机制有顺序、分支、循环、状态变化或停止条件 | 流程图／状态图，初始化、判断、返回与输出可见 | 算法迭代、从交易到分录到余额、内控审批 |
| 容易把对象、关系、属性、身份或端点方向读反 | 结构图，标关系类型、参与次数、属性归属 | Resource 与 Event、PK/FK、M:N、关联金额 |
| 同一事项跨多个时点／角色／账户，文字难以追踪 | 时序图、时间线或带状态的流转图 | 先付款后耗用、先赊销后回款、责任分工 |
| 公式背后有几何、范围、分母或资源构成的难点 | 与符号和真实数值对应的示意图／数值图 | PCA 方向、损失曲线、资产结构与分母变化 |
| 数据结论依赖趋势、分布、比较或变量关系 | 用实际数据重算的统计图 | 收益曲线、箱线图、散点、预测误差 |

并列定义、少量数值、左右借贷、单步运算等用 Markdown 表格更清楚时，表格就是合格图示，不为装饰额外造图。单一事实、目录、行政事项不强制画图。判断标准是“读者哪里会卡住、这张图能让他完成什么理解动作”，不是每节必须凑几张图。

## 2. 工具固定，按图的含义选择

| 用途 | 默认工具 | 最终形式／切换条件 |
|---|---|---|
| 普通流程、分支、循环、时序、状态、简单结构 | Mermaid | 正文内可编辑源码；选 flowchart、sequenceDiagram、stateDiagram 等正确图型。简单类图也可用，必须实际看端点和布局 |
| REA／UML 类图、关系模型等，端点或属性密集、布局需控制 | Graphviz DOT，本机用 Viz.js 的本地 WASM 实现 | 保存单一 JSON 模型、DOT、SVG 与核对记录；复杂模型提供结构图和完整属性图。自动布局有遮挡时调整布局，不能删业务条件来适应工具 |
| 有真实数值、坐标、统计分布或几何计算的图 | Python Matplotlib | 输入数据＋生成脚本＋SVG，必要时另导 PDF。PNG 仅作必要兼容副本，不是唯一图源。不得用流程图工具凭感觉描曲线 |
| 小规模比较、账户左右、逐步余额／状态 | Markdown 表格 | 每列含义、单位和状态时点讲清；表格不能代替题目明确要求的关系模型 |

不把 UML 的 min..max、多重性位置、数据库乌鸦脚等不同记号混用；转换记号时写清读法。关联线不自动表示时间、因果、继承或资金流；需要哪种箭头必须由关系含义决定。REA 的 Sale–CashReceipt 关联不是“Sale 必然立即引起 CashReceipt”的因果箭头。

精确知识图不采用 AI 生成位图、手工截图拼图或只有图片没有源文件的方案。教师原图可作为只读来源，正文重画并保留差异说明。

## 3. 固定流程：先语义，后布局

1. **定教学问题与范围**：写一句“图要解释什么”，明确输入、输出和图外内容。不要把多个层级的模型挤在一起。
2. **回源形成结构清单**：逐个列节点／类别／属性／连线／方向／端点／数字／单位／来源位置。分别标来源事实、参考推断和范围假设。流程另列步骤、判断、循环、初始状态与停止条件；数据图保留真实输入和计算口径。
3. **按语义组织图源**：将每条关系翻回一句业务话；UML 分两方向固定一个对象数另一端，检查最少和最多。逐属性问它描述单个对象还是对象组合。用一个最小完整案例运行该机制，覆盖本题关键分支或边界。
4. **选择工具并生成**：从同一结构清单／JSON／数据脚本生成图；所有中间图、预览和诊断放任务 scratch。排版约束和隐形布局边只是布局，不能冒充新的业务关系。
5. **整批末尾两道核对门槛**：本轮所有候选完稿后集中完成下文语义与显示核对。生成时的结构整理、必要渲染和防损不登记为教学通过；发现具体缺陷只修相应源文件并重看受影响图，不重复全库验收或补造读者分数。
6. **发布并回写**：核对后把可编辑图源和最终矢量图放正确的持久位置，用 `safe_write.atomic_write` 发布文本／SVG。正文补图注、读图步骤、图源入口和必要边界；进度只登记实际完成动作。

不得在 SVG、导出 HTML 或最终图片上偷偷改数字，却让 JSON、DOT、代码和正文保留旧值。图源是唯一维护入口；语义改动要同步正文及相关例子，单纯布局变动不能改变语义清单。

## 4. 语义核对：数量不是证明

- 对照全题或所引用来源：对象、类别、每项属性、每条线、方向和端点均有依据；来源中的细节不能因为画图麻烦被丢弃。
- 每条 UML 关联都实际说两句话：“固定一个 A，有几个 B；固定一个 B，有几个 A”。数字写在被数的类旁边。例如 `Purchase 0..* — 1..1 Supplier` 表示一笔 Purchase 恰好一个 Supplier，一个 Supplier 可无或多笔 Purchase。
- REA 逐事件检查资源流入／流出和参与角色；独立指派与某次事务参与分开；多对多上的分配金额或数量放关联，不挤进单个类；派生余额不自动变成新经济资源。
- 流程逐步对照文字与完整小例：判断真假出口、循环返回位置、状态更新和停止输出正确；只画家族分类图不能满足控制流程图要求。
- 数值图从原数据／公式实际重算，核坐标、单位、符号、点线含义、基准和关键边界。示意几何不标成精确测量，新增小数据标“笔记补充”。
- 合理假设标在图中或紧邻图注，并说明改假设时哪些部分变化。缺关键来源的图标“参考／待核”，不能因语法通过改成已官方确认。

脚本可检查节点／关系／属性／端点数量、引用存在及与清单一致；它不能判断清单本身是否理解错了。节点数、SVG 生成成功或 0 语法错误不是语义 PASS。

## 5. 显示核对：必须看实际图

生成后实际查看最终图，而不是只读代码或缩略图；检查文字、公式、中文字体、负号、箭头、连线、端点、图例与布局。重点看 min..max 是否贴对对象、是否被框或线遮挡，关联属性是否看似落进错误的类。

图在预期阅读尺寸下必须看清。不得靠无限缩小字号把全图塞进一页。复杂模型先给省略类内字段的结构图，再给同源完整属性图；前者保留关系、所有端点及关键关联属性，明确哪些字段另见完整图／表。切分子图时注明共同节点与未显示关系，不能让局部图冒充全模型。

源码正常但字被遮住、字体缺失、标签压在节点上、读不出端点，也须修。先改布局、线距、字号或分图，业务内容不变。Graphviz 字体测宽／标签警告不能默认为无害：核实际字体与边界，修正后再发布。若当前 WASM 对中文测宽不可靠，可保留题面原英文标签并配中文解释；必须用中文框时实际核字宽与边界，不能隐藏警告或只把警告改为 PASS。

优先在 Obsidian 阅读视图核对；环境不能直接查看时，用同源本地浏览器查看 SVG／Mermaid 与正文，记录“浏览器已核、Obsidian 未直接查看”。若教师要求 PDF／Word／Notebook 输出，另看其最终导出位置，不能把浏览器核对冒充导出核对。

## 6. 放置与读图说明

图的放置、图前问题、路径／箭头读法、具体例走图、符号一致、紧邻边界、文字替代、概览与局部关系、读图自测，统一按 [[可读性总规则]] §11.3，不在这里维护第二套教学要求。

颜色只作辅助编码，类型、方向、阶段或状态同时用文字／符号表达；不依赖单独红绿区别。来源、假设、币种、单位、时点和参数需要改变结论时必须显式出现，不能为了美观删除。

## 7. 本地执行入口与文件安全

已有 Mermaid 继续在 Markdown 中维护。Graphviz 路线用 `_meta/tools/render_concept_graph.mjs`：输入 `cityu-concept-graph-v1` JSON，默认本地运行时 `E:/app-data/diagram-tools`，可用 `--runtime-dir` 指定另一处持久缓存。锁定 `@viz-js/viz 3.31.0`；本次实际构建为 Graphviz 16.1.0。节点、边、属性均须有来源和 `source / reference / assumption` 状态。工具拒绝重复身份、悬空关系和无效多重性，但仍需语义与显示核对。

安装与调用说明见 [[教学图示工具流程]]。依赖只放 vault 外的持久缓存，不写进仓库或任务临时目录；不自动升级、不运行未知安装脚本、不把课程材料上传公共绘图服务。模型源码／最终 SVG 是成果，不能只留在 scratch；导出预览和临时截图在 scratch。

公开讲义图可放 `<课程>/notes/figures/` 的 ASCII 子目录；私人练习图源和 SVG 放 `assignment/practice/work/<ASCII任务名>/`，继续受 Git 忽略。量化图复用已有 `code/` 或私人 `work/`。保存 JSON／DOT／代码、SVG、输入版本及必要核对记录；SVG 保留可检索文字，截图不充当可维护图源。此节允许有可编辑文字图源的矢量 SVG，替代旧“只许 Mermaid 或表格”的工具限制；原始材料仍禁止改动。

根及五课 AGENTS／CLAUDE 都引用本规范。旧图遇到本轮处理的理解缺口或实际错误时定向修正；新规范生效不等于全部历史图已重新验收。用户学习／自测勾选、官方答案状态与转录缺口不因画图改变。

## 8. 工具依据

工具能力核对日期：2026-10-07。Mermaid 支持类图多重性与方向配置，见 [Mermaid 官方类图说明](https://mermaid.js.org/syntax/classDiagram)。Graphviz 的端点标注与距离控制见 [headlabel / taillabel 等边属性](https://graphviz.org/docs/edges/)、[labeldistance](https://graphviz.org/docs/attrs/labeldistance/)；本地 WASM 调用见 [Viz.js 官方 API](https://viz-js.com/api/)。数值图矢量导出见 [Matplotlib savefig](https://matplotlib.org/stable/api/_as_gen/matplotlib.pyplot.savefig.html)。这些文档证明工具能力，不证明某张课程图的业务结论。
