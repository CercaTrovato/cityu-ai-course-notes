## 阻塞

1. **B1 · 注意力可见范围在主讲解、速记和算例间冲突。** p.46／p.48（约 547、567 行）与遮罩算例明确“当前位置不能读未来”。§2.5.3 的“在全序列上做注意力”（2371 行）、结构表“所有 token ↔ 注意力”（2386 行）、§5 英文卡 “attention over the full sequence”（4378 行）在自回归语境却会让初学者把“同层位置的已知输入可并行计算”读成“每个位置都可读取任何键”。实际复做时位置 2 的 V 第二维会从 0.669762 被读错成 1.435946。统一这三处的可见范围，表明编码器等结构可用不同遮罩。将遮罩后矩阵另记为 `S_masked`，或给可见公式明确限定 `j≤i` 并单列其他列权重为 0，避免照抄式子使用原始 S。
2. **B2 · TCO 无法依正文复算，且六向量自测暴露同一缺口。** p.76–78 说明费用来源，§2.8.6（3325 行）却把 token 数量直接与托管、人力等费用写在一个加法等式里。§4.2（4254 行）复用了混量纲写法，§7 第 7 题（4717 行）只说弱模型重试更贵、照片消耗大，成本取舍列是破折号。我能解释为什么会贵，但无法用现有文字比较两套流程的一次成功处理成本。用同一货币和时间/工作量单位，给一个“输入／输出量×对应单价，再计检索、重试、托管和人审”的微型假设算例，区分每次请求与每件完成成本。将自测成本栏回指，图片消耗改为按模型计量和实际负载核算。
3. **B3 · 把攻击入口和坏结果写成互斥分类，学完会漏掉一种后果。** §2.9.2 末段与 §9.5 第 ③ 项把提示注入定义为“被诱导做出未授权承诺”，但 §2.9.5 正确列出其也可让模型请求越权工具。Chevrolet 可分开写“攻击手段是提示注入，输出后果是虚假或未授权承诺”，保留课堂把后果称为幻觉的用法。§7 第 7 题约 4741–4747 行用“无批准工具权限、金额只能由计算工具产生”回答“诱导承诺高额赔付”，前者只能挡实际赔付，后者也挡不住模型在回复里捏造金额或作承诺。沿用 §2.9.5 的输出过滤/核验、区分估算与审批状态，再保留工具侧权限；用“正确计算但未审批”作为反例复测。
4. **B4 · 复习卡优先显示的英文与精读中的边界冲突。** §5 的 TTFT 首行 “The delay before the response begins (prefill)” 把相邻概念并排等同，后面中文才更正。以正文 500 ms 的 trace 为例，单算 prefill 只有 200 ms。ITL 英文只有 how quickly，容易把速率与时间混用。将前者首行明确为端到端起止点，后者为相邻 token 的间隔。同处 Foundation Model 首行把所有基础模型都写成 generative、Contextual Vector 把“可能变”写成 “yields different”，与卡后说明及 §7 第 2 题冲突。保留原课件措辞时标课件口径，并让可用于独立复习的定义与正文相同。
