## 待修断点

1. **M04-A｜SQLite 约束会放过文本数量。** 依候选 schema_sql 和 input_sql 建同样内存库，执行 INSERT INTO SaleLine VALUES ('S001',2,'C01','oops',10,8) 成功。实查 quantity 为 'oops'、typeof 为 text，乘单价得 0。正文已提 SQLite 类型宽松，但粒度表仍称“数量严格为正”，容易把 CHECK(quantity>0) 当成完整检查。可明确正负约束只对已验证的数值输入成立并给反例，或为数量和金额增加 SQLite 存储类型检查，同时更新独立 SQL 与完整 Python 脚本。
2. **M04-B｜复习的 Step 2 把特定粒度误成普遍主键规则。** §4.6 和 §2.10.12 决策树直接写“主键＝两个主键拼成复合主键”，与 p.45、§2.10.3 已说的一对可多次修读冲突。相同学生与课程在两个学期重修会撞键。复合键加“一对只许一行”条件；可多次时加事件标识或按粒度设联合唯一。
3. **M04-C｜§7 第 8 题的金额字段与守恒条件不一致。** 结构写 Sale(saleID,date,amount) 且没有 SaleLine，随后要求与 Sale 明细总额比较。若这是简化模型，按 Sale.amount 核；若采用 §2.9.9 的统一结构，须按 SaleLine 汇总且不另存 Sale.amount。§6.3 的简图可标明只示意键。
4. **M04-D｜空外键与必选条件在速查不同步。** §4.5 写“外键要么 null，要么匹配主键”，未带 p.39 与 Case 4 Q4 的条件。按速查会误以为 CashReceipt.Cashier# 可空。改为非空 FK 必须匹配，只有业务可选且列允许空才允许 Null。p.51 可再区分图上的 Sale 端 0..* 和 1..*，非空 FK 无法保证客户至少有一笔销售。
5. **M04-E｜SQL 样本不覆盖没有客户的非销售收款。** p.35 和 §7 第 8 题允许银行贷款等无销售收款，§2.9.9 的 CashReceipt.custID 一律 NOT NULL。R4 虽无应用记录，仍给定 Joe，只能演示未应用。就地说明此 schema 假设收款均有给定客户；无客户收款要用可空或更一般的付款方/类型关系，无需为 R4 补造业务性质。
6. **M04-F｜Case 4 Q1 的最小值来自业务条件。** “only one supplier”直接限制最多一名。最少一名来自题目要求采用的业务常识（已发生采购必须有实际供应商）。保留官解 1..1，同时区分两侧依据；若换成可缺供应商的草稿状态，最小值要重新判断。
7. **可优化。** §1.3 可给 Case 4/SQL 的就地选读路线。p.32/33 图含答案，现有深读已允许先作答，可在导航点出先停在共同题面和四个业务情境。p.52 可用一句话强调该页恰一在收款端，与 p.33 相反。
