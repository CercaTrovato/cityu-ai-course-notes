# 转录处理规则（课堂录音 → 笔记素材）

> 处理任何 `transcripts/` 下的文件前，先读完本文件。
> 这是 [[材料处理规则]] 的专项展开，因为转录是本库最特殊、也最容易被处理错的材料。
>
> **本文件是原理层（为什么、提取什么）。执行层在 skill `.claude/skills/transcript-merge/SKILL.md`**（2026-09-17 起）：逐阶段的做法、每个块的固定模板（`reference/formats.md`）、按课程的 ASR 纠错词典（`reference/asr-dictionary.md`）、任务单模板，以及机器验收脚本 `_meta/tools/transcript_check.py`（`scan` 融合前登记 / `audit` 融合后 12 项检查，标杆 AC6761 M01 / M02 均 PASS）。**任何模型做转录融合都必须按 skill 执行并让 audit PASS**；本文件不再重复执行细节。

---

## 1. 为什么转录要单独立规

讲义和转录**不是同一种东西的两个版本**，它们回答不同的问题：

| | 讲义 | 转录 |
|---|---|---|
| 回答 | 教授**准备**讲什么 | 教授**实际**讲了什么 |
| 强项 | 结构完整、术语拼写准确、有页码可引用 | 有例子、有强调、有取舍、有课堂互动 |
| 弱项 | 不知道哪些重要、哪些被跳过 | 无结构、专名易错、大量口语噪音 |

把转录当成"讲义的补充说明"来处理，会浪费掉它最有价值的部分。正确做法是**双源比对**。

---

## 2. 四类差集信息（核心产出）

处理转录的目标不是"把转录也写进笔记"，而是提取这四类信息：

| # | 情况 | 价值 | 去向 |
|---|---|---|---|
| 1 | 课件有 + 课上讲了 | 核心内容，确认无误 | 正文主体，正常写 |
| 2 | 课件有 + **课上略过** | 考试权重可能低 | 正文保留，加标注 `⏭️ 课上略过` |
| 3 | **课件没有 + 课上讲了** | **最高**——只有到场的人才有 | 正文重点，标 `🎙️` |
| 4 | 教授明确强调 | 直接考点 | 考点库，可信度「教授明示」，**引原话** |

外加一类：**课堂问答与讨论** → 填进正文的「常见误解」格。同学问的问题，就是真实存在的困惑点，比你凭空想的"常见误解"准得多。

**判断"略过"要谨慎**：讲义某页在转录里找不到对应内容，可能是教授真的跳过了，也可能是转录漏了、或者教授用完全不同的措辞讲的。只有在**比较确定**时才标 `⏭️ 课上略过`，并在第 9 节说明判断依据。宁可不标，也不要误导读者跳过实际会考的内容。

## 3. ASR 专名校正（最容易出错的一步）

### 3.1 本地 Whisper（2026-09-18 起的转录来源）

工具：`E:\AIworkspace\lecture-transcribe\`（`transcribe.py` 转录、`record.py` 录音；OpenAI Whisper large-v3，faster-whisper / CTranslate2，GPU fp16，纯本地不联网）。产出 `<音频名>.txt`（Notta 布局：时间戳一行 + 文本一行 + 空行）、`.srt`、`.md`；`transcript_check.py` 与 transcript-merge skill 直接可读。与 Notta 的差异：

| 方面 | Notta（历史） | 本地 Whisper |
|---|---|---|
| 分段粒度 | ~6–10 秒一段（2h 约 600 段） | **逐句，~3–8 秒一段**（2h13m ≈ 1361 段）；`quote` 取 ±4 段才够上下文 |
| 时间戳 | 录音相对时间 | 同；`00:00` = 音频开头。**录音暂停（课间）不产生空档**，墙钟不连续要靠内容判断 |
| 说话人分离 | 无 | 无。学生提问混在教授的流里，通常声音远、只有半句 |
| 大小写 / 标点 | 句首大写 | 句子可能以小写开头（跨段续句）；标点由模型生成，仅供参考 |
| 数字 | 多写成英文 | 多写成阿拉伯数字（`20 intervals`、`3.5`） |
| 专名错法 | 拆专名（`Kantianism`→`Contianism`） | **按发音写成常见词**：`CityU`→`CPU`、`ParknShop`→`Pace`、`skewness`→`SKU needs`、`Chernoff face`→`channel phase`。仍按「以讲义书面拼写为准」校正，听不清标 `[?]` |
| 幻觉 | 少 | 长静音 / 音乐 / 噪声处可能吐出无关短句（`Thank you for watching`、重复同一句）。已用 VAD 抑制，但**与上下文完全无关的短句视为噪声，不当教授原话引用** |
| 整块丢失 | 无 | 早期版本偶发「一块 30 秒只剩几个词」，已修。**若仍见 ≥12 秒只有几个词的段，在回执里报时间戳**，用户可重转 |
| 小测 / 自习时段 | 空档 | 经过滤后同样是空档（同学闲聊、静音幻觉已按语种检测 + 重复检测删掉，删掉的片段在录音目录的 `transcript.dropped.json`）。**≥120 秒空档仍按原规则当作课堂练习时间的信号**；笔记里某段"应该有却没有"时可去 dropped.json 找 |

某课专名反复出错时，在回执里建议下次加 hotwords：`uv run transcribe.py <音频> --hotwords "术语1, 术语2"`。

### 3.2 Notta 的易错模式（2026-09-17 前的转录仍适用）

Notta 这类语音转写工具，对**英文哲学、法律、人名**的识别错误率显著高于日常英语。已知易错模式：

| 正确 | 常见误识 |
|---|---|
| Kantianism | Contianism / Cantianism |
| deontology | the ontology / dentology |
| Bentham | Benthem / Bentam |
| Kohlberg | Colberg / Goldberg |
| categorical imperative | categorial imperative |
| utilitarianism | utilitarism |
| Rawls | Rolls / Ralls |
| maxim | maximum |
| GDPR | GDP R / GDPR的各种拆分 |

**规则：**

1. **先用讲义建术语表，再拿它过一遍转录**。讲义的书面拼写是唯一权威，转录里的拼写一律服从
2. 中文转写同理：教授中英夹杂时，转写工具可能把中文词转成同音异字
3. **听不清、拿不准的术语标 `[?]`，绝不猜一个填上**。一个被猜错的术语比一个空缺危害大得多——读者会把错的背下来
4. 数字、日期、法条编号、百分比 **一律以讲义为准**；讲义没有的，标 `[?]` 并在第 9 节列出待核对项

## 4. 噪音过滤

以下内容**不进笔记**：

- 口语重复、语气词（"um", "you know", "对吧", "那个"）
- 设备/教室事务（"能听见吗"、"这个投影仪"、点名、下课时间安排）
- 与课程内容无关的闲聊、寒暄
- 教授的自我介绍与履历（除非讲义本身把它作为内容的一部分）

以下内容**要保留**：

- 教授的口语化解释——往往比讲义的书面定义好懂，是「💡 换个说法」的最佳来源（但要标明来自转录，不是你编的）
- 教授讲的**题外话式例子**（新闻、亲身经历、行业案例）——这类最容易在考试和小组项目里用上
- 教授对考试、作业、评分的任何表述

## 5. 文件约定

**存放位置**：`<课程目录>/transcripts/`

**命名**：`M<两位数>-transcript.<ext>`，例如 `M01-transcript.txt`、`M02-transcript.docx`

`M` 是全库统一的 module 序号前缀——**无论该课自己叫 Week、Lecture 还是 Module，转录一律用 `M`**，与笔记文件名对齐。各课的 `M0N` ↔ 原始命名的对应关系写在该课 `00-课程总览.md` 里。

**后缀标记**（让缺陷在文件名上就可见，不必打开文件才发现）：

| 后缀 | 含义 |
|---|---|
| `-partial` | **录音不完整**（开头/结尾/中间缺失）。例：`M01-transcript-partial.txt` |
| `-part1` / `-part2` | 一节课分多段录制，内容完整 |

> ⚠️ `-partial` 的文件，笔记里必须在 §9 写明缺失的时间区间，且该区间对应的讲义内容**不可标注「课上略过」**——你没有证据，只是没录到。

**格式偏好**（从优到劣）：

| 格式 | 说明 |
|---|---|
| **带时间戳的 txt / srt / vtt** | 最佳。时间戳能对齐到讲义进度，也便于回听核对 |
| 纯 txt | 可用。没有时间戳就无法标注"教授在这页停了 20 分钟"这类权重信息 |
| docx | 可用。用 `python-docx` 提取 |
| PDF | 可用但不推荐，排版会干扰提取 |

**本地工具（2026-09-18 起）**：用户用 `E:\AIworkspace\lecture-transcribe` 转录后，把 `.txt` 按上表改名为 `M0N-transcript.txt` 放进 `<课程>/transcripts/`；**源音频（mp3 / wav）可能在同一目录，不要动它**（`.gitignore` 已排除音频，不进仓库）。音频同名的 `.srt` / `.md` 不必保留。历史提示：Notta 导出时选包含时间戳的格式；说话人分离两种工具都没有。

### 5.1 录完课之后：从 lecture-transcribe 取转录（2026-09-18 起的标准动作）

用户用 GUI（`E:\AIworkspace\lecture-transcribe\app.py`）录课，录音结束自动转录。用户说"录完了 / 转录一下今天的课"时，agent 按下面做：

```
cd E:\AIworkspace\lecture-transcribe
uv run lt.py list --json                 # 最新在前；status=done 表示转录完成，files.txt 就是 Notta 布局的 txt
uv run lt.py transcribe <id> --json      # status 不是 done（还在转）时用它阻塞到完成
uv run lt.py export <id> --module M04    # 按录音的 course 字段找到 transcripts_dir，写成 M04-transcript.txt（不覆盖已有；-part1 / -partial 写成 --module M04-part1）
```

- 最新一条名称 / 时间对得上就是这节课，直接用；不确定就把最近 3 条列给用户选。`list --json` 里 `exported` 有值 = 用户已在 GUI 点过「导出到知识库」，不要重复导出。
- 导出后走 `.claude/skills/transcript-merge/`（§11 分片并行模式）。
- 术语提示：某课专名反复识别错时，在回执里给一份 hotwords（逗号分隔）建议；正式来源见 §5.2。

### 5.2 `courses.json`：课程 → hotwords / 下次模块 / 转录目录

GUI 的课程下拉读 `E:\AIworkspace\lecture-transcribe\courses.json`（选课程即自动填 Whisper hotwords、默认录音名 `IS6400_M04`、一键导出到该课 `transcripts/`）。**它由本库生成，不要手改**：

```
PYTHONIOENCODING=utf-8 /d/anaconda3/python.exe _meta/tools/export_courses_json.py [--dry-run]
cd E:\AIworkspace\lecture-transcribe; uv run lt.py courses      # 验证：五门课都在、hotwords 条数 40–60
```

- 数据来源：`<课程>/_meta/术语表.md` 各表 English 列（按表头定位）+ `asr-dictionary.md` 本课分节「应为」列 + 各 M0N 笔记 frontmatter `date:`；课程全名取根 README「五门课」表。
- hotwords 排序 = 优先级：`CityU` → 专名 / 缩写 / 人名（前 30）→ ⭐ 术语（≤10）→ 曾被听错的词的正确写法 → 其余专名 → 其余术语；过滤普通英语词、整句、中文；按约 140 估算 token 截断（faster-whisper 约 100 真实 token 后截掉，靠前的才保证生效）。
- `next_module`：今天之后最近一次课的笔记模块（课前建稿的 M0N）；没有就是最近一次已上课的模块 + 1（每周一次）。GUI 只拿它拼默认录音名，用户可改。
- **什么时候重跑**：① 某门课新 module 的术语表写完（新专名进来了）；② asr-dictionary 加了新错例；③ 新一周开始、`next_module` 该往后推时。重跑只改 courses.json（vault 外），不需要提交本库。

## 6. 处理流程

```
1. 读讲义，建本讲术语表（英文书面拼写）
2. 读转录全文（不要只读开头）
3. 用术语表校正转录中的专名，拿不准的标 [?]
4. 把转录分段对齐到讲义章节 —— 产出一张对齐表：
      讲义页码区间 ↔ 转录时间区间 ↔ 覆盖情况(讲了/略过/展开)
5. 按第 2 节提取四类差集信息
6. 写进笔记：
      类型1 → 正文主体
      类型2 → 正文 + ⏭️ 标注
      类型3 → 正文 + 🎙️ 标注
      类型4 → 考点库（引原话）+ 笔记第 6 节
      问答  → 正文「常见误解」格
7. 第 9 节写：9.1 课上略过清单、9.2 课上补充清单、9.3 待核对的 [?] 项
8. frontmatter 改 transcript: merged
```

第 4 步的**对齐表建议留在笔记第 8 节**，和讲义页码映射合并成一张表。这样读者复习时能直接看出"哪一页教授讲得最久"。

## 7. 无转录时怎么办

**不要因此推迟写笔记。**

- frontmatter 标 `transcript: pending`（将来会补）或 `transcript: none`（那节课确实没录，永远不会有）
- 正文七格微结构里的「🎙️ 课堂补充」格**保留**，内容写「待转录补充」或「本讲无录音」
  - 保留这一格是有意的：它让欠债可见。删掉了就再也想不起来哪里缺
- 第 6 节考点预判只能用「ILO 反推」和「笔记推断」两级可信度，不能有「教授明示」
- 第 9 节写明：本讲无转录，故无法判断课上略过/补充了哪些内容

### ✅ 已解决：IS5542 导出截断

> ⚠️ **历史方法**：下面的 Notta 分享页 DOM 提取只对 Notta 导出有效。2026-09-18 起转录来自本地 Whisper（§3.1），不存在导出截断问题，此法不再适用；保留作记录。

**问题**：Notta 的导出功能只给出 `43:39` 之后的内容（171 段 / 52KB），缺开头 43 分 39 秒。但云端**从 `00:00` 就有内容**——是**导出环节的缺陷，不是录音缺失**。

**解决方法**（可复用）：Notta 的**分享链接页无需登录即可访问**，且它用 ProseMirror 编辑器，**把全部转录块一次性渲染进 DOM**（不是虚拟滚动）。因此可以直接从页面提取：

```js
// 在 Notta 分享页执行
[...document.querySelectorAll('.transcribeItem')].map(el => {
  const t = el.textContent || '';
  const m = t.match(/^(\d{1,2}:\d{2}(?::\d{2})?)/);
  if (!m) return null;
  return m[1] + '\n' + t.slice(m[1].length)
    .replace(/^\s*(未知讲话人|Unknown speaker)\s*/,'')
    .replace(/\s*(播放|暂停|加载中|Play|Pause|Loading)\s*/g,' ')
    .replace(/\s+/g,' ').trim();
}).filter(Boolean)
```

⚠️ 注意 `innerText` 会被裁剪（只返回可见文本），**必须用 `textContent`**；否则会误判成虚拟滚动列表。

**拼接校验**：把新取的头部与原文件在重叠时间戳处逐字比对（本例 `43:39` 块完全一致）后再拼。拼完必须跑一次时序检查——段数、起止、时序倒退、>2 分钟空档。
