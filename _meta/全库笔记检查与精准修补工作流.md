# 全库笔记检查与精准修补工作流

本流程执行 [[逐页学习与课件图示规范]] 和 [[笔记制作与融合验收流程]]，解决“怎样高效找到缺口、回源、修到可用并结束”。它不降低原题、来源、机制、图文、独审或文件安全要求。本次用户明确授权全库检查修补，指定统筹会话只制定规则／决策／派单／监督，五个课程新会话实际修补；课程执行者与其独立审查者均为 `gpt-6.1-sol`、`high`。不自动启用 Superpowers。

## 1. 范围与唯一工作入口

批次入口为 `_meta/learning-repair-20261104/README.md`，课程任务、清单、状态与会话 ID 从该处读取。新会话无需依赖原聊天记忆。先核任务单、根／本课规则、来源和当前文件，不沿用旧稿的“完整／通过”作为本标准结论。

本次基线包含五门课现有 48 篇 M/T 笔记。各课程首次清点时还须登记本课实际用于学习的练习解析、学习导览、配套复习解释及其依赖，逐文件说明纳入或排除理由；不能把 48 当作所有材料的固定上限。只含导航的索引核链接与状态，不套教学全文审查；历史候选／审查副本／缓存排除，原始课件／教师答案／正式已提交稿只读。正式答卷不因本批检查重写，私人学习解释可修。新发现但超出上述学习用途的内容先列范围待定，由统筹决策。

每课先生成本课 inventory，随后逐篇完成诊断到交付；不要先把全库诊断完才开始修，也不要做完清单就结束。IS6400 第一篇是用户正在使用且已确认缺口的 M09。其他课按正在使用／已知缺口、图示密集与算法／模型依赖、其余讲次排序；无当前学习证据时不编造优先级理由。

## 2. 五课并行、每课一条写入线

| 角色 | 职责与可写范围 |
|---|---|
| 统筹会话 | 规则、范围决策、课程派单、批次登记、效率监督及结果汇总；不编写／重构教学正文 |
| 每课执行会话 | 只写本课派单允许的正文／图资产／课程元文件及其专属审查目录；一时只修改一篇候选，完成一篇再推进下一篇 |
| 每课独立审查者 | 未参与当前候选写作，显式 `gpt-6.1-sol / high`；只写独审证据，不改正文／原件／个人状态 |
| 收尾发布者 | 全部课程结果收回后，由统筹从已完成的课程会话中明确指定；串行处理共享元文件及批次整体验证，不另改教学含义 |

五个会话共用当前本地项目，不另建工作树，不丢失未提交的新规则和笔记。课程之间不互改、不代审。每个课程最多一个正在工作的独审者，不为公式、图、每条警告另派代理，不增加管理代理。独审身份隔离和两阶段按制作流程，工具不可用时保存待审并推进可独立工作，不冒充通过。

并行期间课程执行者禁止直接修改：根 README、根术语总表、根转录登记、全局规则／工具、其他课程、其他课程的 Notion 行、共享 integrity_manifest、批次总登记。每篇对共享文件的增量写进本课 `shared-updates.md/json`，注明目标、真实原值／哈希、拟变更、来源和适用篇目；这一项记“待共享收尾”，不能省略或声称已同步。

本课概念台账、术语／考点、课程总览和本课 Notion 行仍逐篇精确更新并回读；保护本人通读、自测、复习、提交／评分字段。已有同步关闭确认在本批继续有效，不重复索取；观察到同步重新开启或并发冲突时停受影响写入并报告。

## 3. 每篇闭环：诊断 → 对源 → 修补 → 收尾

### A. 一次完整诊断，建立缺陷清单

保存当前正文原始字节／SHA 和来源版本。执行者完整读当前正文，并实际看本次全部源页；T 核全部 cell／任务及必要输出。按 [[逐页学习与课件图示规范]] 建 `page-evidence`，把源页要素、原图、本页增量、原题、公式／算例和笔记精确位置对上。不能用文字提取、页码命中或旧截图存在证明已看图。

先集中识别可学习性断点：预习缺前置／理由，课中缺页入口／原图／图义对应，复习缺回指／自测理由；再核来源事实与必要计算。诊断由执行者完成，不先追加一次独立全篇审查。记录本次全部范围，发现同机制问题时一次列齐所有位置。

每个缺陷只维护一个 ID：`课程-篇目-序号`。必填问题类别、正文位置、源页／图／cell、读者做不下去或容易误判的具体动作、最小修复范围、关联影响、阻塞／建议、状态与证据。状态用 `open → fixed → verified`；误报用 `not-a-defect` 并给依据；真实外部缺口用 `blocked`，不靠改标签清零。

### B. 按缺陷选择最小有效修法

| 情况 | 修法 |
|---|---|
| 本标准全部适用项已成立 | 保留正文，保存本次检查证据；旧证据只在真实源版本、候选和范围吻合时承接 |
| 错别字、链接、元数据且无教学含义变化 | 维护通道；主代理核差异，不新增教学独审 |
| 少量独立缺口，现有结构可继续使用 | 就地补原图与读法、条件／步骤、逐页入口及必要回指；保留正确算例与解释 |
| 多页混在大节、找不到本页内容或图义普遍丢失 | 按源页重构受影响的连续单元；复用正确正文、计算与资产，不从零重写整讲 |
| 全篇组织本身阻碍跟读和学习 | 才进行全篇结构重构，先记录依据及迁移映射，防止原题、转录与自测丢失 |
| 缺源、来源冲突、工具无法完成必要视觉／独审 | 冻结受影响部分并列精确阻塞；继续本课可独立篇目，不猜造、不覆盖正式稿 |

先回原课件再写修补；新增解释／小例标为补充，不能偷换原图或原题。原图要放到对应页并解释，不能批量贴满幻灯片后算完成。已有本讲正确图、公式和完整算例优先复用，重复图复用资产；补流程图仅针对真实分支／循环机制。

### C. 集中修补并冻结候选

一次处理当前清单中的相关缺陷，并同步受影响的摘要、速查、术语、自测、图与页码回链。候选、预览和临时脚本都在本课专属 scratch；不边审边改同一文件。

执行者集中自查一次，核来源、原题、计算、源页视觉、最终图文及真实机械硬项。渲染一次可复用来源缓存；图或公式改动才重渲受影响部分。不要反复运行耗时模型／训练、全库检查或生成同型预览来换“绿色”。冻结候选 SHA，再交独审。

### D. 一次独立全范围审查，随后只定向复核

对教学修改，沿用制作流程的同一次两阶段独审：第一阶段只读冻结候选及必要教学链接，尝试预习顺读、复做和复习回指；stage-1 落盘后，第二阶段提供规则、全部源页、真实基线／diff 和必要证据，逐页／逐图检验课中跟读。整篇重构审全篇；局部修补审全部新增及受影响范围。全库诊断覆盖整篇，不因局部候选只审变化就把未核范围升级。拟宣布“整篇符合新标准”时，本次或可承接的独审证据必须覆盖全篇新标准；即使无需改文，旧独审未覆盖新要求也须以当前正文为冻结候选做一次全范围独立核查，不为留回执而重写正文。

独审一次提交完整缺陷清单，执行者批量处理；原独审者只复核这些缺陷及依赖。正确未变部分承接对应版本证据。只因新的实质缺陷、真实来源变化或新增影响范围才扩大复核，不能因风格偏好、版本号或哈希变化重开全篇。

### E. 达到终点就交付并推进下一篇

当本次全部源页／学习范围有证据、真实阻塞关闭、预习／课中／复习结论成立、源图与最终显示已核、机械硬项已处理、独审完成且绑定真实候选，即执行 `note-review-v2` 门槛、写前基线比对、原子写及精确回读。运行 gate 已包含 note_quality，不再机械地重复同一检查。

每篇完成本课增量同步与本课 Notion 回读，共享增量交单一收尾者；记录已写／待共享同步／外部阻塞的不同状态。结束条件不是“作者没有任何润色想法”。不得把个人已学会／已提交填成完成。

## 4. 收敛约束与升级

- 默认节奏为“一次完整诊断＋一次集中修补＋一次两阶段独审＋必要定向复核”。这是工作形态，不是放过真实缺陷的轮数配额。
- 同一实质缺陷经过两次定向修补仍未关闭，或连续两次出现新的系统性缺陷类别：停止该篇的盲目改写，落盘失败原因／证据／两个可选方案，请统筹做范围或方法决策。该篇保持待修，先推进其他无依赖篇目；不能以轮数上限判通过。
- 审查建议与阻塞分开。建议不延迟交付；要求额外同型例子、装饰图、无关背景或个人措辞偏好，不扩成新修补任务。
- 关闭的缺陷不反复重开；只有候选、来源、图义或依赖的实际变化影响旧结论时才重开，并记录新证据。
- 首篇／首个复杂单元用于验证工具路线；看图、公式和原子写路线可行后复用。工具失败第二次须改变方法或精确报告限制，不无限重试同一命令。
- 没有真实语义证据不能靠脚本／回执字段通过；没有重要新证据也不为“更放心”追加一轮全库审核。

## 5. 并行安全与检查成本

开批由统筹运行一次全库 integrity snapshot 并保留自有副本。课程会话用 `_meta/tools/course_integrity.py` 创建自己的 scoped manifest（命令见任务单），禁止重写共享 manifest。写每个目标前仍保存真实字节、校验基线；课程收尾核本课完整性。跨课变化不当作本课损坏，也不能被覆盖。

所有原始课件只读；课程正式产物使用 `safe_write.atomic_write`，二进制资产用同目录临时文件＋哈希校验＋原子替换。原图／图源／必要证据进入持久目录，批量渲染和中间草稿只留 scratch。已有未提交修改按当前工作区基线保护，不从 Git 旧版回滚或混入无关改动。

每篇核本篇机械、链接与必要显示；全库 link_check／README 核对与总完整性在共享收尾串行完成一次。课程可用工具检查本课，但不能每改一句就扫描全库。基线已有历史问题与本次新增问题分开。

本批不提交／推送 Git，不运行自动同步，不上传／提交作业，不改原件，不改本人学习状态。日常保存规则与本次“仅统筹派单、课程本地修补”的执行范围分开；后续 Git 动作按用户明确要求执行。

## 6. 轻量进度、监督与恢复

每课维护一个 `status.json`，字段为课程、真实线程 ID、当前篇／阶段、核心及补充任务总数、完成／已核无改／待修／受阻数、当前已看源页数／总页数、开放阻塞数、最近实质产物、下一动作、更新时间。另保留一张按篇 inventory 和一份 defects；长工具输出只落盘，不复制到聊天。

状态在阶段变化、完成一篇、出现阻塞时更新；长任务至少约 10 分钟落一次真实断点。刷新时间戳或写“继续检查”不算实质进展；源页证据、候选、缺陷关闭、真实检查或正式写回才算。时间／用量能取得就记，不捏造服务商账单。

统筹约每 15 分钟读取五个会话的紧凑状态和各课 status，运行中不反复打断。约 30 分钟无可核实实质增量先查具体阻塞，不能因篇幅大或一次等待就强停。发现循环按 §4 决策；只在重要完成、失败或需要用户动作时通知，正常细碎进度保留台账。

上下文恢复只读任务单、status、当前篇缺陷与最终候选／报告哈希，从真实断点继续；不重读全部旧报告、不重建已关闭清单、不重派同一全篇独审。需要续接由统筹给当前会话 follow-up，不另开重复课程会话。

## 7. 结果收回与全批关闭

每课完成后给 `course-result.md/json`：纳入／排除范围、逐篇源版本、修补类型和文件／资产、已核的三场景结论、独审与 gate 证据、正文写回、课程同步／Notion、共享待办、仍阻塞及原因。已有未改篇也给真实证据，不只报“48 篇已检查”。

统筹收回五课结果并核数量、职责边界、阻塞和证据是否匹配，不亲自重审或改写全部正文。存在具体缺口就把定向任务发回该课，不以主会话接管写作代替。

五课完成本课范围后，统筹指定一名已完成课程执行者串行合并共享增量：根 README 全部当前信息、总术语、适用转录登记和跨课索引，按真实范围回读必要 Notion 状态。重复／冲突先核依据，不覆盖个人字段。随后一次全库链接、README 与自有全库基线完整性核对。共享未完成时全批仍为收尾中。

全批可标完成的条件：所有纳入项均为“已修并核验”或“全范围已核无需修改”，全部适用同步已完成并回读，无开放实质阻塞；外部材料／权限确实受阻则诚实交付“已完成范围＋剩余受阻范围”，不能用完整率或轮数隐去。完成或确需用户动作时停止周期督导，避免无限空转。

## 8. 本批显式用户收尾选择（2026-11-04）

用户在主会话回复前台恢复请求：“其实检测之前那些没问题，基本上后面的就不需要再查了”。本批剩余逐篇界面实测因此不再要求；不再占用用户窗口。此例外不自动沿用到其他任务，也不授权绕过工具安全限制、跳过来源和教学真实性、或把未看过的显示写成已验。

沿用已完成独审与来源证据，完成必要文本/原题/代码保真、图片和链接存在、机械硬项、CAS/原子写/回读，再交付正式入口。复杂答案可用保留原 Markdown/LaTeX/代码的 Obsidian 原生折叠 callout 或本批已验证等效容器，简单且已正常的 details 保留；此本批容器选择覆盖旧入口中只列 details 的实现约束，不改自测内容及默认折叠目的。纯容器修正不重开教学全篇独审。

未实际检查的最终显示在 note-review-v2 中写 `checks.visuals.status: waived_by_user`，不能写 passed 或伪称不适用。同时提供 `user_visual_waiver`：`scope: remaining_final_display_checks`、`source_visuals: completed_for_available_sources`、准确的 `authorization_file`／`authorization_sha256`，以及明确未实测内容的 `limitations`。授权记录为本批 `decisions/user-skip-remaining-display.json`；先读真实文件和哈希，不复制占位值。图源阅读仍由 sources 和实际页清单证明。机器只核记录/范围/哈希，统筹须核人类原话的真实授权。

课件自身缺失的原图／讲义须保留来源限制；可以交付已审的可得内容和导航，不能伪造原图、把给定答案键写成已复算，或把无课件讲次标为逐页验收完成。只因该来源缺口不阻止其他已审内容写回。现有真实教学阻塞仍要解决或精确隔离，不能用本次界面豁免掩盖。

完成本地发布和可执行同步后统一收回；不支持保真更新的外部字段继续列待办，不为强行同步覆盖原格式或个人状态。
