# 日常复习：主会话教学，子代理异步收尾

生效：2026-11-27。本人明确要求把每轮资料同步和自检交给子代理，避免学习等待。本规则适用于五课日常复习，不改变固定框架、笔记优先、考试优先及真实掌握判定。

## 1. 每轮只在前台做什么

主复习会话负责讲解、即时反馈、必要的判分核对、下一步教学决定。复用本地笔记，仍按整体→分支→知识点→例题/本人作答→变式展开。不能为了后台独审把明显不确定的判分当正确讲下去。

一轮是一组已经发生的知识点互动，不是每条消息。结束时用一次轻量原子写保存 `review/final-2026/maintenance/inbox/<round-id>.json`：真实原问、题面、原答、提示顺序、已讲内容/现有笔记定位、当前停点和下一步。已有耐久正文可引用路径与 SHA，不复制整份笔记。round-id 使用日期时间加唯一后缀；补充或纠正另建事件并引用前一 ID，不覆盖原包。未作答留空并标等待，未知用时不编。

交接写后回读成功，立刻给下一步讲解或题目，并把收尾交给本课后台子代理。**禁止在给下一题前调用等待代理完成、长轮询 Git/发布、整库自检或重审旧材料。** 正常对话只在阶段结束简短报告维护状态，不播报每个工具步骤。

前台不重复后台工作；后台处理中，主会话只追加 inbox，不同时改 sessions/mistakes/progress/route/README。接续位置取当前对话和最新原始事件，并与已落盘进度合并，不能被稍旧的 progress 拉回上一题。

## 2. 子代理怎样调度

- 每门课在当前学习期间复用一个维护子代理。新建时显式 `model: gpt-6.1-sol`、`fork_turns: none`；提供课程绝对路径、本文、交接文件和限定职责，避免传整段旧聊天。运行中追加通知，空闲时继续派任务；不要为每句话重复创建代理。
- 默认维护代理处理主会话已经写出的冻结教学文本：先做必要的独立轻量抽检，再归档/更新进度。只移录原文、加索引和维护状态不使它成为教学作者；若它新增或实质改写教学解释，它已是作者，该部分须由另一位未参与撰写的子代理审查。不得自写自审或让主会话换身份冒充独审。
- 已核笔记的引用、本人原答、提示先后、状态和文件链接等纯记录，只核事实/引用/枚举/完整性；不重新独审未变教学。真正新增解析按现行制作流程审查，仅覆盖变化及其依赖；保留两阶段证据和实际身份，不以机器绿灯代替教学验收。
- 暂无空闲名额、指定模型不可用或子代理失败时，原包保持待处理并写明原因；主会话继续可独立开展的教学，在后续交互中重试。不得换用其他模型、声称已派成功，或把整套同步退回前台让用户等待。
- 只维护本课复习记录，获准以总监督委派的收尾身份执行本课既有三端发布；不改他课、正式作业、共享代码/白名单、考试事实或固定框架。需要扩大范围交回总监督，不自行跨会话发消息。

## 3. 顺序写回与发布

每课一个维护写者，使用 `_meta/tools/review_maintenance_lock.py` 的 `course-<课程码>` 锁。按前一事件 ID/实际时间处理队列，已记录的 round-id 不重复新增 session、错题或累计次数。若连续多轮已排队，可一起检查和发布，但每轮原答、审查范围与状态分别保留。

1. 读取不可变原包、最近回执及当前文件，保存本批文件字节/哈希及任务隔离的完整性基线。先核已有回执，恢复已完成步骤；不因重试全套重跑。
2. 在库外 scratch 制作本轮 session/错题候选，完成适用审查。原始事件可以先保存，未审新解析不得进入正式教学文档或发布快照。存在疑点则保留候选与原答，并报告具体待核点。
3. 持有本课锁完成顺序写回。所有目标写前比对当前 SHA、原子写、写后回读；发现外部并发变化，重新读取并合并本批增量，无法安全合并则停该项。progress/route 的停点必须对应最新已归档事件，不能把较晚进度改回较早一轮。未审新判分结论不升级掌握，原始行为单独保留。
4. 运行一次本课 `review_workspace_check.py --course <课程码>` 和本批适用链接/完整性核对。每批一次，只有新缺陷/新修改才补定向检查；不每轮扫描五课或重新渲染所有课件。
5. 再申请 `shared-publish` 锁，覆盖本批 fetch→核现有 index→精确暂存→commit/push→远端核验→本地看板回读→本课线上发布/回读的完整事务。既有其他暂存、文件哈希变化或不可确认的发布增量均停止该项；不 reset/覆盖他人的 index，不夹带其他成果。其他遵守本规则的代理不会同时发布；旧会话不一定遵守锁，仍须核实际状态。
6. 本课在线发布使用既有工程 `E:/AIworkspace/codex-workspace/cityu-board-online` 的 `node scripts/publish.mjs --publish --course <课程码>`。只在已核范围内发布；记录 Git SHA、本地回读和线上 release/content_hash。发布器共享 latest-receipt 在释放锁前复制到本批专属回执目录，不能引用后续被覆盖的共享文件当本批证据。
7. 每完成一个阶段就原子更新 `maintenance/receipts/<round-id>.json` 并回读，记录结果、证据、最后错误及下一步；不是到最后才第一次写回执。共享发布回执必须在 shared-publish 锁内复制到本批目录并记录，然后释放共享锁；本批逐轮最终回执写毕、回读后才释放本课锁。每个 round-id 保留独立状态，可指向同一合批发布回执。所有适用环节有实证才标完成；失败同样先保存恢复点再释放锁，不升级学习状态。

锁顺序固定：本课锁→shared-publish；不持有共享锁再申请其他课程锁。共享锁忙时立即返回并记 `pending`，释放本课锁，后续有界重试；不能持锁反复长等。交接包仍能继续追加。每次执行处理启动时已知的有限批次，不承诺会话结束后永久运行。

## 4. 状态与中断恢复

原包的“已保存”、后台“已派/运行中”、教学“已抽检”、记录“已归档”、GitHub/本地/线上“已回读”分别记。主会话的派出结果/名额不足/重试原因只写 `maintenance/dispatch/<round-id>.json`，后台不改此文件；维护回执只由持本课锁的维护者写。没有回执的原包默认为待处理，不回写不可变原包。阶段值使用 `pending/running/done/failed/blocked/not_applicable`，不适用写理由；整轮完成由适用阶段实证决定。inbox/receipts 是接续账本，不计作学习完成量，也不新增看板学习单元。

主会话在下一次用户交互或分支结束时非阻塞查看回执/代理状态；出现影响当前知识正确性的发现时立即说明并纠正该点，其他维护失败留给后台修复。只有下一步确实依赖尚未核实的答案/考试要求时才暂停该点，可先转到不依赖它的内容。

停止学习、关闭应用或中断不等于后台已完成。离开前原包和待处理状态必须已落盘；后台是否继续运行以实际平台状态为准。再次进入课程时检查 inbox 中无完成回执的事件，核旧代理/锁的真实状态，接续最近事件，恢复待处理批次。不要把过期 running 当成功或重建同一事件。

锁不按时间自动抢占。发现持锁者失联，先核其已停止、正在执行的命令已结束、Git/index 与本地/线上实际状态，记录接手依据，再凭原 token 释放；不能确认就标待处理，教学继续。锁文件 PID/时间不是代理存活证明。

若 mkdir 后、owner 写完前中断，工具显示 held-owner-unreadable，不能凭空造 token。由总监督做一次有界恢复：核无活跃持锁者/相关命令，解析 Git common directory 并检查锁的准确绝对路径、目录归属、非重解析点及当前文件/哈希，保存事故与已执行步骤；将该单个锁目录移至同一锁根下唯一的 `<scope>-recovered-<时间>` 保留现场，再重新获取锁并从已完成证据恢复。移动前后核绝对目标仍在该锁根内，不递归删除、不清空其他锁；无法确认安全则保留现场。此为人工判断后的恢复流程，不是按超时自动解锁。

同一 token 只能有一个释放执行者，主会话和后台不能同时 release；接手者须先确认旧执行者和命令已停止。工具的 token 核对不是操作系统跨命令事务，不把合作式互斥宣传成能防止违反协议的双重释放。

```json
{
  "schema": "review-round-intake-v1",
  "course": "IS5113",
  "round_id": "YYYYMMDD-HHMMSS-unique",
  "previous_round_id": null,
  "recorded_at": "真实时间及 +08:00",
  "unit_ids": ["U01"],
  "events": [{"question": "实际题面/原问", "answer": "本人实际原答或 null", "hints_in_order": [], "teaching_excerpt_or_durable_refs": []}],
  "current_point": "全课主干→分支→实际知识点",
  "next_step": "主会话已决定的下一步",
  "source_refs": [],
  "teaching_author_ids": ["实际作者标识"]
}
```

示例仅定义结构，不创建虚构学习记录。任务消息包含：

> 你负责 `<课程绝对路径>/review/` 的本批异步收尾。先读本课 review/AGENTS.md 和 `_meta/final-review-2026/ASYNC-MAINTENANCE.md`。按指定 inbox 文件顺序处理，保留本人原答/提示/曝光/真实独立程度；先核已有回执，按实际教学增量做审查。只写本课 records/progress/route/README/handover 与维护回执；框架、原件、其他课程和作业只读。获取本课写锁及共享发布锁后按规则三端闭环，完成或遇阻保存回执并回报。主会话继续教学，不要要求用户等你同步。未提供的事实不得补造。

实际目录使用 `sessions/`、`mistakes/` 等既有名称；模板中的 records 不是新目录。

## 6. 互斥工具

在 vault 根运行；锁存 Git common directory 下的 `cityu-review-locks/`，不进入公开课程资料。命令不会等待，忙时 exit 2，错误 token 释放 exit 3；token 只用于本机所有权核对。

```powershell
D:\anaconda3\python.exe -X utf8 _meta/tools/review_maintenance_lock.py acquire --scope course-IS5113 --owner <实际代理ID> --job <实际批次ID>
D:\anaconda3\python.exe -X utf8 _meta/tools/review_maintenance_lock.py acquire --scope shared-publish --owner <实际代理ID> --job <实际批次ID>
D:\anaconda3\python.exe -X utf8 _meta/tools/review_maintenance_lock.py status --scope shared-publish
D:\anaconda3\python.exe -X utf8 _meta/tools/review_maintenance_lock.py release --scope shared-publish --token <本批取得的token>
D:\anaconda3\python.exe -X utf8 _meta/tools/review_maintenance_lock.py release --scope course-IS5113 --token <本批取得的token>
```

工具只提供合作式互斥，不调度代理、不自动审核、不自动修改学习进度、不承诺后台常驻。持锁者必须在失败收尾时核实际状态并正确释放；工具不替代 SHA 冲突检查和真实发布回读。
