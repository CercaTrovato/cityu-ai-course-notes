# AI 辅助课程知识库：架构与工程实践

> **时间口径**：§1–§10 记录的是 2026-09-10 的历史快照，其中 15 篇笔记等数字不要写成当前规模；当前课程笔记与质量状态见根 [README](../README.md) 和 [全库质量基线](全库质量基线-2026-09-24.md)。§11 另记 9 月 24 日已验证的本地问答扩展。

> **一句话**：为研究生五门课设计并主导建设了一套 **AI 辅助的知识工程体系**——把课件、课堂录音转录、数据集转化为"没听过课也能自学"的结构化笔记库，配有质量验收机制、多代理并行生产流程和可复现的分析代码库。
>
> **时间**：2026 年 9 月起（开学两周内完成五门课全部已发材料的处理）
> **角色**：**架构设计者与产品负责人**。全部设计决策由本人做出（见 §3），AI（Claude Code）在既定规则下执行生产。
> **规模**：15 篇精读笔记 / 38 万中文字 / 覆盖 860+ 页讲义 / 8 份课堂转录 / 41 份规则与元数据文件 / 1 个可复现分析代码库

## 1. 要解决的问题

研究生课程材料有三个特点：**信息分散**（讲义、大纲、官方目录、课堂口述四个来源口径不一）、**讲义不自足**（大量纯图片页、嵌入对象、答案栏空白、讲课顺序≠学习顺序）、**课堂口述信息无处沉淀**（教授明说的考试范围、答题格式、讲义错误只存在于录音里）。

直接让 AI"总结课件"会得到不可信、不连贯、不可验证的产物。**需要的是一套工程化的体系**：明确的输入规范、可执行的质量标准、可复现的产出。

## 2. 架构

三层结构，每层有自己的规则文件：

```
材料层  course_files_export/ + transcripts/     只读原始材料，按类型有处理规则（PDF/pptx/docx/csv/ipynb/转录）
   ↓
规则层  _meta/                                  笔记模板 · 材料处理规则 · 转录处理规则 · 对抗自检清单 · 术语总表 · 设计规格
   ↓
产出层  <课程>/notes/ + _meta/ + code/          精读笔记 · 知识台账 · 考点库 · 术语表 · 数据集卡 · 分析脚本
   ↓
追踪层  Notion（进度库 + DDL 库）                八格流水线追踪每讲进度；作业与考试自动登记
```

**指导文件对 AI 无关**：根目录 `CLAUDE.md`（Claude Code 专用）与 `AGENTS.md`（任何 AI 通用）保持等价，任何模型都能按同一套方法论接手。

### 三大核心机制（体系的骨架）

| 机制 | 解决什么 | 怎么做 |
|---|---|---|
| **① 前置知识台账** | 读到第 N 讲时不出现没定义过的概念 | 每门课维护 L0 入场基线 + L1 概念登记表（首现于哪一讲）。写新笔记时，不在表里的概念**必须就地展开并回写**；跨课复用的概念由首现课承担，其他课只回指 |
| **② 正文按学习逻辑重排** | 讲义是讲课顺序，不是学习顺序 | 正文重组，附「笔记小节 ↔ 讲义页码」双向映射表。**重排改的是顺序不是覆盖范围**——每一页都必须在正文有实质讲解 |
| **③ 讲义 × 转录双源比对** | 教授"准备讲的"和"实际讲的"不一样 | 两者的**差集**是最高价值信息：课上讲了但课件没有（🎙️）、课件有但课上略过（⏭️）、教授明说会考（🔴）、两者矛盾（🔀）。考点按证据强度分三档 |

## 3. 关键设计决策（本人做出，附理由）

这一节是简历里"设计能力"的证据。每条都是一个有取舍的判断。

| 决策 | 取舍 | 理由 |
|---|---|---|
| **读者假设：没听过课、只懂 AI/ML 基础、其他领域零基础** | 放弃"笔记是给自己的备忘"，改为"教材级精读" | 这个假设把"写得清不清楚"变成可验收的标准——任何未解释的概念都是缺陷 |
| **不用 git，用 Obsidian + Notion** | 放弃版本历史，换来纯文本 + 双链 + 手机端进度追踪 | 笔记版本历史极少用；纯 Markdown 不被工具锁死；进度追踪需要的是勾选框不是 diff |
| **单文件笔记 + 课程级共享文件** | 不拆成每概念一文件 | 一讲的内容是一条论证，拆碎了读不出逻辑；共享的（术语、考点、台账）才单独成文件 |
| **取消篇幅上限** | 原定 8000–15000 字/讲；实测有转录的一讲达 3.5 万字 | 篇幅由材料量决定。压缩砍掉的恰是"让没听过课的人也能懂"依赖的部分。**唯一保留的是下限**：每页都要有归属 |
| **预习可用性规则：讲义每一页都必须在正文有实质讲解** | 禁止"课上略过所以不写" | 读者假设是没听过课的人——**课上略过恰恰意味着这部分只能靠笔记学**。起因是一次真实事故：某讲 19 页只登记进索引没展开，而那正是期中考内容 |
| **对抗自检取代普通自查** | 写完后换成"想证明这篇不合格的审查者"身份攻击自己的产出 | 五次真实事故（跳过图片页、只进索引不展开、把"有备注字段"当"有备注内容"、把"时间戳连续"当"录音完整"、按文本长度误判分隔页）**都通过了普通自查**——它们都"看起来做完了" |
| **考点置信度分档，无转录时封顶** | 🔴教授明示（必须附原话）> 🟡大纲反推 > ⚪推断；无录音的讲最高只能到 🟡 | 防止 AI 把推断包装成事实。"教授说了"必须能指到时间戳 |
| **分析代码必须可复现** | 数据集的每个数字都要有对应脚本；脚本必须有断言自检 | 断言在首个样板脚本里就抓到一个真实的数据特征（收益文件首行非 NaN） |
| **术语总表只收跨课概念，并设"一词多义"专节** | 不做全量词典 | 真正的价值在冲突处：`Agent` 在三门课指三个东西、`Bias` 三义、R² 在金融与商业分析里量级期望相差 50 倍 |

## 4. 质量保障：对抗自检清单（12 项）

| 组 | 项 | 验证方式 |
|---|---|---|
| **A 覆盖** | ① 每页在正文有讲解 ② 课上略过≠不写 ③ 低文本页全部视觉复核 ④ 嵌入对象已提取 | **脚本验，不许目测**；输出"未讲解的页 = []" |
| **B 真实性** | ⑤ 无转录不出现"教授说" ⑥ 每条来源可回溯 ⑦ 置信度不越级 ⑧ 数字全部可核 | 随机抽 5 处回原文核对；时间戳逐个在转录文件里验证 |
| **C 连贯性** | ⑨ 无悬空概念 ⑩ 台账已回写 | 对照 L0/L1 表逐词查 |
| **D 目标达成** | ⑪ 随机抽 3 页做预习可用性抽测 ⑫ 反方视角：最弱一节 / 答不上的考点 / 哪些是推断 | 用随机数抽，不许挑写得好的页 |

**验收纪律**：简报不许写"已全部检查通过"——报数字、报页码、报结论。**自检脚本报错先怀疑脚本**（曾误报一处未闭合标签，实为正文里的代码跨度）。

## 5. 多代理并行生产流程

五门课的材料处理在同一天内**并行**完成，用了一套明确的协作协议：

- **分工**：主 agent 负责规则、共享文件、Notion、验收；每个子 agent 只写自己课程目录下的文件
- **共享资源的写冲突**：子 agent 不改根目录共享文件，把跨课术语写进本课的「待并入清单」，主 agent 统一去重合并（227 条候选 → 68 概念 + 23 歧义 + 44 译名）
- **失败处理**：一个 agent 因单次输出超过 64k token 上限失败 → 提取成果留在临时目录 → 重开时复用 → **写入规则**：长笔记必须分块写入再拼接
- **验收不采信自述**：每个 agent 交付后，主 agent 用脚本重跑逐页覆盖检查

## 6. 材料处理的工程细节（可作为"解决过什么难题"的素材）

| 难题 | 解法 |
|---|---|
| 讲义 PDF 里大量**纯图片页**（某讲 86 页中 23 页），文本提取为空 | 建立"低文本页必须逐页视觉复核"规则；发现被跳过的页里有整篇论文、关键对照表、唯一红框强调 |
| pptx 里的**嵌入 Excel/Word OLE 对象**（某讲 41 个），`python-pptx` 取不到 | PowerPoint COM 自动化转 PDF 再提取；练习答案只存在于 OLE 对象里 |
| **多页文本完全相同但截图不同**（同一张图逐步高亮，16 页 7 组） | 发现"按文本去重会丢 9 页"，改为逐页视觉判定 |
| **课堂录音转录质量差**（会计课 ASR 把 debit 识别成 damage/tennis/stereotype 等 9 种） | 建立按课程积累的 ASR 纠错样本库；所有术语按讲义还原，不确定处显式标 `[?]` |
| **录音完整性误判**："时间戳连续"≠"覆盖整堂课" | 增加"看第一段内容像不像开课"的判定；发现两份录音分别缺开头 15 分钟与缺结尾 20 分钟 |
| **官方课程目录与教授大纲口径冲突**（及格线、GenAI 政策、CILO 权重、课程顺序） | 每门课做四源逐项对校（官方目录 / 大纲 / 讲义 / 转录），冲突处显式列表并标采信依据 |
| 讲义**自身错误**（SQL 语法错、p 值定义反了、Ridge 与 Lasso 性质写混、同一人两个名字、页码沿用上一章模板…） | 每篇笔记 §9.3 逐条勘误；跨课通用的错误进根术语总表「跨课勘误」节 |

## 10. ⚠️ 给简历 agent 的注意事项

1. **分清人做的和 AI 做的**。本人的贡献是**架构、规则、决策、验收标准**（§2–§5）；具体笔记文字由 AI 生成。简历里写"设计并主导"是准确的，写"撰写了 38 万字笔记"是不准确的。
2. **数字有出处**。§7 的每个数字都是脚本统计的，可复核；不要四舍五入成更好看的数。
3. **不要夸大技术深度**。这是一个工程化的知识管理体系，不是研究项目。它的价值在"把不可控的 AI 产出变成可验收的"，不在算法。
4. **可以强调的软技能**：把模糊需求（"帮我做笔记"）转化为可执行规范的能力；从失败中提炼规则的习惯（五次事故 → 12 项清单）；对 AI 产出保持验证而非信任的纪律（"验收不采信自述"）。
5. **匹配岗位时可以侧重的面**：
   - **AI 产品 / 提示工程**：§3 决策、§4 清单、§5 多代理协议
   - **数据 / 分析**：§6 材料处理难题、代码库的可复现设计
   - **知识管理 / 文档工程**：三层架构、术语总表、Obsidian + Notion 组合

## 11. 2026-09-24 增量：本地课程问答 Agent 原型

这项新增工作沿用本知识库的五门课资料，而不是新建无关题材。**课程 vault 只读**；代码在本人独立面试工作区的 `projects/cityu-course-agent/`，SQLite 索引与向量库在 vault 外的本机 scratchpad，模型在本机 `E:` 盘。本仓库没有收录问答程序代码或生成的索引。

| 环节 | 截至 9 月 24 日可核实的实现与边界 |
|---|---|
| 材料进入检索 | 笔记按标题、PDF 按页、PPTX 按幻灯片、转录按时间切块；记录课程、来源类型、笔记状态和定位符。已索引 3,723 个笔记块、1,390 个讲义块、1,225 个转录块；只覆盖可抽取文字，图像页和 PPTX speaker notes 尚未完整覆盖。 |
| 检索 | SQLite FTS5 中文双字关键词基线；官方 Qwen3-Embedding-0.6B GGUF 在本机生成 6,338 个向量；可切换 dense 与 RRF 混合模式。 |
| 回答与 Agent 边界 | 本地 Qwen3-4B 在给定证据下回答，输出编号引用；无证据或无有效引用时拒答。固定 `ask` 是 RAG 工作流，`agent` 仅能判断是否再检索一次，工具只读。 |
| 开发烟测 | 16 道人工选取题的“来源＋定位符”Recall@5：关键词 13/16、dense 15/16、RRF 13/16。题集参与开发和修正，**不代表独立泛化效果或答案准确率**。复合问题出现过无引用生成，现已在输出前拦截。 |
| 尚未完成 | 大规模独立题集、逐条答案与引用人工评分、图像/OLE 内容覆盖、正式注入测试、SFT/LoRA 微调、线上服务。不可把这些写成已完成经历。 |

**可用于面试的事实口径**：在已有 CityU 课程知识库上实现了只读、本地的课程问答原型，比较关键词、语义与混合检索在小型开发题集上的来源定位表现，并对无有效引用的回答拒绝输出。微调目前是后续实验计划，课程知识继续由检索库提供。§9 的 2026-09-10 简历句子仍是历史版本；若更新简历，须按当前资料和本人实际分工重新核对数字，不能把这个原型直接写成已部署产品。
