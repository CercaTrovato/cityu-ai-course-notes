# 教学图示工具流程

先读 [[教学图示规范]]，决定图要解决的理解问题，再按下面工具执行。选择工具不能代替来源、语义与实际显示核对。图文教学语义统一引用 [[可读性总规则]] §11.3；整批末尾验收时机引用该文件 §1.3。本轮创作时允许必要渲染、来源／计算依据与文件防损，所有候选完稿后集中执行本文语义与真实显示核对，不派中途验收。无法实际查看须写待核；渲染成功不等于视觉通过。候选只写 scratch，最末由管理者发起单一发布者的哈希校对与原子写，不建立反复盲评流程。

## 1. Mermaid：普通流程与小图

直接在对应正文维护带 `mermaid` 语言的代码块。流程用 `flowchart`，时序用 `sequenceDiagram`，状态用 `stateDiagram-v2`，简单 UML 用 `classDiagram`。题目要 UML 时保留 UML 读法，不为使用 `erDiagram` 换成另一种未解释记号。

源块是最终可编辑成果；实际打开 Obsidian 阅读视图查看。受限时生成同源本地浏览器预览，并留下实际核对范围。循环、条件分支、返程和终点必须来自正文机制；结构分类图不能冒充流程。复杂类图端点遮挡时，切换下一路线或分图，不删数字来凑布局。

## 2. Graphviz：密集模型的固定入口

本机没有依赖系统 `dot.exe`。采用官方 Viz.js 的 Graphviz WASM，在本地 Node 运行；课程数据留在本机。2026-10-07 实际验证 `@viz-js/viz 3.31.0`，内置 Graphviz `16.1.0`，固定版本记录在 `_meta/tools/diagram-runtime.json`。

依赖存 `E:/app-data/diagram-tools`，npm 缓存也放该持久目录；不放 C: 默认缓存、不放 vault、不放任务 scratch。不安装或升级全局 Node/npm。首次搭建才从官方 npm registry 安装，之后渲染无需网络：

```powershell
npm install --prefix 'E:\app-data\diagram-tools' --cache 'E:\app-data\diagram-tools\npm-cache' --save-exact --ignore-scripts --no-audit --no-fund '@viz-js/viz@3.31.0'
```

另一机器可选其他 vault 外持久缓存，通过 `--runtime-dir` 传入；不要静默升级版本。输入模型、临时 DOT／SVG／布局及诊断均留在该任务 scratch，核对之后用原子写发布最终成果。

### 2.1 输入语义清单

模型 JSON 的 `schema` 为 `cityu-concept-graph-v1`；`diagram_type` 选择 `uml-rea`、`uml-class` 或 `relational`。每个节点包含 `id / label / kind / source / status / attributes`；每条关联包含 `id / a / b / a_multiplicity / b_multiplicity / label / source / status / attributes`。属性也包含 `id / name / source / status`。

`status` 为 `source`（来源事实）、`reference`（参考推断）、`assumption`（范围假设）。`scope` 写模型范围，`assumptions` 是假设数组，确实没有额外假设可以为空；`figure_caption` 为可选的可见范围／来源图注。`layout.columns` 按列列出节点 ID，若提供须把所有节点恰好列一次。位置只是布局，不表示因果。

`a_multiplicity` 是贴在 a 类旁的数，回答“固定一个 b，有几个 a”；`b_multiplicity` 相反。代码为布局交换连线起终点时，同时交换两端标注，输出报告保留源端点与绘制端点映射。当前渲染器画普通无向关联，不用它悄悄画带因果、时间或继承意义的箭头。

每张模型只维护一份 JSON，结构图和全属性图由它生成。图源中的附加说明或来源是数据，不能被当成命令执行。工具转义文本并拒绝输出脚本／远程资源；它不能判断来源字段里填写的事实是否真的成立。

### 2.2 渲染与核对

在 vault 根执行，以下路径按当前任务替换：

```powershell
node _meta/tools/render_concept_graph.mjs --input 'E:\app-data\codex\scratchpad\task-name\model.json' --output 'E:\app-data\codex\scratchpad\task-name\model-full'
node _meta/tools/render_concept_graph.mjs --input 'E:\app-data\codex\scratchpad\task-name\model.json' --output 'E:\app-data\codex\scratchpad\task-name\model-overview' --overview
```

每次输出 `.dot`、`.svg`、`.layout.json` 和 `.render.json`。DOT 保留可编辑结构，SVG 是最终矢量图，布局和渲染报告是诊断。报告写版本、源 JSON SHA-256、模型数量与端点映射；`semantic_review` / `visual_review` 初始明确为待核，不因运行成功自动 PASS。

`--overview` 省略类框内字段，但保留全部节点、业务关联、端点和关联属性。报告分别写总属性数和实际展示的字段数。完整图展示全部字段；两图要在正文标清各自范围，概览图不冒充全属性答案。

拿原题／结构清单逐关系反解，核属性归属和具体小例。然后实际看 SVG：文字与节点／线／标签是否遮挡、端点是否贴对、字体是否清楚。渲染 warnings 包含字体测宽或布局问题时不能无视。当前 WASM 的英文标签已实际验证；中文框内标签仍需实测字宽，不能仅凭 Node 成功退出宣称可读。

正文附近登记核对范围：来源与未知项、结构及端点对照、小例、实际查看方式和具体发现。对于数值图或核心计算，不省略真实复算。发现具体问题后只改受影响源，再看那张图。

### 2.3 发布与原子写

图源及 SVG 发布到课程 `notes/figures/<ASCII名>/` 或私有 `assignment/practice/work/<ASCII名>/`；新建目录用 ASCII。原始课件不移动、不改。私有完整答案及图仍受 Git 忽略，不因工具输出改变公开边界。

Agent 发布文本、JSON、DOT、SVG 时通过 `_meta/tools/safe_write.py` 的 `atomic_write`；图先在 scratch 渲染，不直接让 Node 输出覆盖 vault 文件。保留模型 JSON、最终 DOT／SVG 和必要核对记录。相同语义的概览与全属性输出共享一个 JSON，不手动维护第二套业务定义。

Obsidian 中可用 SVG 嵌入并提供图源链接；SVG 要有可读文字，不能把 PNG 截图当唯一成果。检查最终保存的嵌入目标和实际显示，不只查看 scratch 中的副本。

## 3. Matplotlib：真实数值图

复用本机 Python 与现有课程代码，保存真实输入版本和生成脚本；没有可靠数据时只能画标明假设的示意，不仿造课件坐标。轴名、单位、时点、图例、基准及精度从计算口径得到。SVG 为默认矢量成果，教师需要 PDF 时另导 PDF。

必须看生成图和要求的最终导出页面：中文字体、负号、公式、图例和轴刻度清楚；计算和正文结论对得上。`savefig` 成功不等于值算对。图源或真实数据有更新，重新运行并同步正文，不只编辑图中的文字。

## 4. 首个实际样例与适用边界

2026-10-07 用 AC6761 Case 5 的私人参考模型验证这条路线：同一语义清单生成结构图和全属性图，7 类、8 关联、21 属性及 16 端点与原解析一致。图源和答案留在本地私有 `assignment/`，这里不公开其完整源码。

工具固定的是生成与核对路径，不能保证未知教材事实或假设天然正确。旧图不因新增工具就全部通过验收；本次没有全量重画历史笔记。用户已学会、官方已核、提交及转录状态仍分别记录。
