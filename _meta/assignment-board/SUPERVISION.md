## 每个工作会话的一个推进周期（2026-11-10 更新）

**固定顺序：本批成果核验 → GitHub 推送与远端核验 → 回传总监督 → 本地看板更新 → 线上同步与回读 → 给本人群汇报稿。** 每次推进指一批有实际结果的工作，例如一次研究查证、一个可运行版本、一次成员交付验收或一轮计划修订；不是每条消息、每个临时文件都单独提交。

1. **读取规则和当前状态。** 先读根级 `_meta/作业规范.md`、本课作业制作规范、目标任务说明，再读本流程和 `assignment.json`。共用制作要求、课程特殊要求、具体作业事实各有权威入口，不另复制一套互相冲突的规则。接续已核工作，明确本批范围和对应 GitHub 仓库。
2. **推进并核验成果。** 给本人连贯易懂的解释，完成不依赖本人选择的工作。需要本人观点、业务取舍或团队承诺时，明确建议、备选和影响；没有答复不等于批准。来源、计算、运行、视觉和独审按本批适用要求执行，候选与已通过成果如实区分。
3. **写回课程状态与发布候选。** 按 README.md 的 SHA-256 冲突检测和原子写协议维护本作业 `assignment.json`、`coordination.json` 及 `notes/supervision-report.md`。课程会话是这些文件的单一写者。自己的完整性基线保存在专属 scratch，不覆盖共用 integrity_manifest.json。发布前可先准备回传草稿，但不得预填“推送成功”或“看板已核”。
4. **提交、推送并核验 GitHub。** 更新本批成果、当前方案、任务卡和组员需要的文件入口。先 fetch，核对远端和实际差异，仅提交本批已核范围，不夹带其他会话改动；使用本人署名，不加 AI 署名、不 force push、不绕过钩子。推送后核对远端分支及提交 SHA，并回读本批文件或 Git blob。关键入口和相对链接须能使用。只有执行过 push 或本地有提交不算远端完成。
5. **推送成功后回传总监督。** 在本地监督报告记录本批完成/未完成、本人决定、成员自报与已核成果、缺口、下一步、仓库与分支、远端提交、文件/检查证据及当前三份记录哈希。课程会话主动回传总监督；不只在自己的聊天里结束。内部回执不必为记录自身的提交 SHA 而无限追加提交，组员需要的业务说明发生实质修订时才形成下一笔发布。
6. **总监督更新本地看板，同批同步线上并回读。** 总监督读报告和证据，核状态，必要时定向发回修正；只维护自己的监督回执和共享看板，不抢写课程文件。更新后核对看板实际展示的本批状态、依赖、验收缺口和待决定事项。源文件保存、本地页面刷新、总监督核查、线上发布与回读分别记录，不能相互替代。按 [ONLINE-SYNC.md](ONLINE-SYNC.md) 完成同批线上同步；既定范围已获持续授权，不等待本人另说同步。功能变化须接入并部署线上工程，数据发布不能替代代码部署。
7. **本地与线上看板回读核实后给群稿。** 课程会话可提前拟稿，总监督在回读后交给本人，或通知课程会话给出最终群稿。每批提供一份连贯、可直接复制的文字，不让本人再拼接多段工具回执；实际发送由本人操作。

## GitHub 范围与失败处理

- 推送目标是该作业已经确认的协作仓库；课程公共知识库与小组私有仓库的资料范围分别维护。不得推错仓库、自动扩大公开范围、暴露凭据或复制未获授权的第三方私人资料。私有仓库可按已确认需要提供具名分工，公共课程记录仍按相应隐私规则处理。
- 新作业尚未绑定仓库时，先把本地成果和拟发布清单准备好，再明确缺少的目标信息；不能猜一个仓库上传或声称发布完成。已绑定且在既定范围内的推送无需再次逐次确认。
- GitHub 失败、冲突或检查未通过时，保留本地成果，向本人和总监督说明失败环节、影响范围和下一步；仍可回传阻塞，不必等成功才报问题。不能把失败回传记为正常收尾完成。
- 看板维护、服务不可用或尚未完成总监督回读时，记“GitHub 已核／看板待同步或待核”。可以准备群稿候选，但最终回执不得宣称整轮闭环完成。看板恢复后接续本地更新、线上同步回读和群稿交付，不重做未变的研究，也不为绕过维护而擅自重启、覆盖看板代码。
- 实际记录至少分别说明成果检查、GitHub 发布、总监督接收、看板回读、群稿交付的状态；可写在 `notes/supervision-report.md`，遵守当前 JSON schema，不擅自添加不受支持的必填字段。完成度只按真实交付与验收更新，不因提交次数或文档数量上涨。

## 群汇报稿的统一要求

使用本人面向组员的口吻，简单、礼貌、具体。按“本次进展 → 本人的想法及理由 → 仍差什么 → 下一步谁做什么 → 请大家反馈什么”的逻辑写；必要时分短段或列点，不堆会话 ID、哈希、检查器术语或压缩到无法读懂。只有确实来自本人的观点才写成“我决定”，代理建议、建议日期和未确认分工必须保留建议性质。

- 所有关键链接都在可复制群稿中写出完整 `https://...` 地址，不只用“点击这里”或隐藏网址的 Markdown 链接。提供当前方案/任务入口和本批成果的必要链接即可，不把每个文件都堆进消息。
- 说明成员下一步该读什么、交什么、交给谁；时间没获确认就礼貌询问，不能写成组员承诺。个人已派任务、组员自报、实际收件、验收通过与正式提交分别描述。
- 有缺件、质量问题或阻塞时直接说明具体影响和补件要求；已有可继续推进的部分也写清。群稿可以请组员提出意见，不自动替本人发送或替组员答复。

## coordination.json 格式（课程会话单一写者）

```json
{
  "schema_version": 1,
  "assignment_id": "IS6400-A06",
  "thread_id": "实际课程会话 ID",
  "root_thread_id": "01a1b491-403e-7651-9aba-13e5b647af93",
  "model": "gpt-6.1-sol",
  "status": "working",
  "updated_at": "2026-11-07T15:00:00+08:00",
  "summary": "当前正在解决什么；已核实与建议分开",
  "report_path": "本课程/assignment/graded/目标目录/notes/supervision-report.md",
  "decisions": [
    {
      "id": "IS6400-D01",
      "question": "需要本人作出的具体决定",
      "recommendation": "建议与理由",
      "options": ["方案 A", "方案 B"],
      "status": "pending",
      "answer": null,
      "answer_source": null
    }
  ]
}
```

`status` 仅使用 `working`、`waiting_user`、`ready_for_review`、`blocked`、`complete`。它表示当前会话工作阶段，不能被理解为整门课或作业已完成。decision status 使用 `pending` 或 `decided`，后者必须有真实 answer 与 answer_source（用户回复所在会话及时间或消息定位）。没有待决策项时 decisions 为空数组。由课程会话在开始工作时创建；总监督不抢写。

## 总监督的运行边界

### 管理版看板维护（2026-11-10）

每次核对课程回传时，按 [MANAGEMENT.md](MANAGEMENT.md) 同步该课的管理叙述、交付和验收差距、依赖条件、技术事实；复核后再更新 management.json 的来源版本绑定。不能只换哈希。该文件由总监督单一写入，课程会话继续维护自己的原始记录。管理拆解未同步时保留过时提示，不把旧进度当最新。新报告应明确“原要求、实际结果、已核项、缺项、谁补、下一交件”，使用完整句子说明原因和影响。

### 真实团队与本地影子组分开（2026-11-08）

本人可要求课程会话用本地代理模拟各岗位，作为对照研究。此类产物与真实组员的交付分开记录：主 `tasks` 及完成度只计真实团队或已发生的协调事项；本地代理产出不加入主任务完成数或分母。由课程会话在 `summary`、`coordination.summary` 和监督报告独立章节中记录本地对照范围、证据、输出位置、已核/待核状态。

本人确认已分发任务，可以更新该协调事实；不能据此推定全组已认可节点或提交成果。影子组的代码、数据、计算复核与组员交付不互相替代。对照仅使用被授权的开发/验证范围，最终评估是否开启另列。主监督核查回传时注明自己检查了哪些文件和数值，不把课程会话的复算冒称为主监督重新执行。

当前活跃回合通过 wait_threads 接收阶段结果并跟进；总会话结束后不声称自己仍在后台持续轮询或已设自动化。各课程会话的文件更新会继续进入本地看板。本人在这里说“汇总/监督进度”时，从登记会话和回传文件接续，不重启已经完成的研究，也不重复派出会话。

本机看板连接状态仅表示本地服务可用；会话状态是最后一次工作会话回报，须同时显示更新时间，不伪装成实时模型运行状态。
