## 范围与使用

第一版于 2026-11-07 建立：23 个现有 `assignment/graded/Axx-*` 文件夹各有一份 `assignment.json`；其中五个当前小组项目完成初始进度整理，EF5560 A01 为历史已评分归档，其余 17 项只建立入口，不推断制作或提交状态。

看板提供课程筛选、搜索、交付时间线、需要确认的事项、任务详情和依据。每 5 秒重读文件；连接中断时明确提示最后成功快照。日期采用香港时间。服务只绑定 `127.0.0.1`，没有写入 API，不向其他设备或公网开放，也不读取 `.env`、私人群文件或任意仓库文件。

浏览器不会直接访问整个课程库。代码只扫描 `*/assignment/graded/*/assignment.json`，并核对元数据明确列出的本地及库外证据文件哈希；来源哈希变更、来源缺失、元数据无效和未接入文件夹均显式提示。

## 结构：沿用现有目录

```text
<course>/assignment/
  AGENTS.md                    # 当前课程会话的管理入口
  graded/Axx-existing-name/
    assignment.json            # 当前进度事实入口
    notes/                     # 现有任务说明与决策
    work/                      # 现有工作稿
    submission/                # 现有拟交或已交文件；存在不等于提交
    metadata-history/          # 使用 update.py 后保存的历史元数据
```

保留 AC6761 `assignment/ai-financial-analyst/` 等既有工作区，通过来源路径关联；不迁移、改名、复制或修改原始课件。机器契约见 `schema.json`。所有课程共用同一版本，新增课程也适用。

## 状态与证据口径

- `board_scope`：`active` 当前项目，`archived` 已结束归档，`intake` 已登记但待核实。范围不等于完成状态。
- `tasks[].status`：`unknown` 未知、`todo` 明确待做、`in_progress` 进行中、`blocked` 受阻、`done` 有依据的完成。任务标题须界定成果，例如“PPT 初稿”完成不能升级为“最终 PPT”完成。
- `submission` 与制作任务分开；只有相应证据才能记 `submitted` / `graded`。本人陈述、其他会话核验、正式回执的证据强度应在 `note` 中说明。不将文件存在、Canvas Start Assignment、Notion 未开始或 AI 已生成材料当作最终提交证明。
- `sources` 保留本地文件与 SHA-256、会话 ID 或原来源 URL。会话结论仅按其实际核验时间与范围承接；本看板没有重新登录各课程 Canvas，也没有持续读取会话、Notion、GitHub 或群聊。禁止放入访问令牌、私人群成员资料或访问授权链接。
- `reviewed_at` 是此次信息整理日期；`progress_as_of` 是制作进度实际所依据的日期；`updated_at` 是元数据编辑时间。重新打开旧记录不自动刷新制作日期。超过 7 天的当前项目会提示更新。
- `milestones` 分交件、展示与内部建议。`datetime` 必须带时区；`date` 保留“未注明时刻”；`before_date` 保留“该日前”；未知用 `null`。不擅自补成 23:59。日期已过而无回执只提示“待核提交”，不直接断言迟交。
- `next_action.basis=proposed` 为监督建议；`agreed` 只用于已确认安排。不得把推荐行动写成组员承诺。
- 默认 `task_scope_complete=false`，显示完成任务数 / 已登记追踪项数，不展示整体完成百分比。锁定完整任务范围后才可设为 true，此时是等权任务比例，不代表工作时长、质量、课程成绩或正式提交完成度。不能以新增准备任务稀释未完成的核心交付。

## 其他会话怎样更新

当前四课独立会话的派出、回传、总监督核对及本人决策流转见 [SUPERVISION.md](SUPERVISION.md)。课程会话在本作业目录维护 `coordination.json`；看板“会话协作”读取其阶段回报及待决策项，提供会话和报告入口。模型状态不自动从聊天平台同步，页面显示的是带时间的最后回报。总监督的核对绑定元数据、协调记录和报告哈希；新版本出现后会重新显示待核对。

1. 先读取目标作业的 `assignment.json` 和本指南，并核对本次真实成果。只有管理字段变更不需要重做教学内容审查；若改教学正文仍遵守课程原流程。
2. 遵守全库同步关闭与完整性快照要求。更新前取得文件完整 SHA-256，在任务专属 scratch 目录保存候选。保留其他会话的分工、日期、个人学习及提交事实。
3. 写清做了什么、还差什么、负责人、证据和进度日期。只有新证据才能关闭阻塞、升级状态或修改截止。资料有冲突时保留差异和待确认项。
4. 用下列工具验证并原子替换；旧版本保存在该作业 `metadata-history/`。如果哈希冲突，重新读最新版本并合并，不能覆盖。跨会话须约定单一写者；哈希比较是冲突检测，不是操作系统级事务锁。
5. 写后运行全量元数据校验并回读看板。不要只在聊天里说已完成而漏写 metadata，也不要为更新看板代发邮件或提交作业。

```powershell
# 获取完整 SHA-256
Get-FileHash -Algorithm SHA256 -LiteralPath '<目标 assignment.json 的绝对路径>'

# 先验证候选，填入真实 ID、候选路径及前一步哈希
& 'D:/anaconda3/python.exe' -X utf8 '_meta/assignment-board/update.py' --id AC6761-A01 --candidate '<scratch 中的候选 JSON>' --expected-sha '<完整 SHA-256>' --dry-run

# 去掉 --dry-run 后执行写入；保留历史、原子写、精确回读
& 'D:/anaconda3/python.exe' -X utf8 '_meta/assignment-board/update.py' --id AC6761-A01 --candidate '<scratch 中的候选 JSON>' --expected-sha '<完整 SHA-256>'

# 校验现有元数据、缺失入口及来源变更
& 'D:/anaconda3/python.exe' -X utf8 '_meta/assignment-board/server.py' --check
```

依赖：Python 3.9+ 和 `jsonschema`（本机 `D:/anaconda3/python.exe` 已具备）。网页没有第三方 CDN 或前端构建依赖。`server.py --port 8767` 可更换端口。服务器代码变动后重启服务，界面代码变动后刷新网页；元数据变动自动重读。
