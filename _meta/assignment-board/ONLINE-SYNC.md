- 每批本地更新完成必要核验后，同批同步线上并回读，是已获授权的必要收尾。不再等待本人另说“同步”，不重复索取普通同步或既定项目部署的批准。

## 必须完成的收尾

1. 核对事实、状态、日期和本次范围，完成适用检查，原子写回本地并回读。课程会话维护自身记录；总监督核报告、管理叙述和共享看板，避免并发抢写。
2. 数据与资料更新：在既定共享范围内检查和补齐精确白名单，再运行线上工程的 `node scripts/publish.mjs --publish`，可用 `--course IS6400` 限定单课。发布器使用本机已加密凭据；不得输出密钥。
3. 功能更新：把本地适用改动接入线上工程，保留 GitHub 登录、首次自选一课后的锁定和成员只读策略；完成构建与适用测试，部署既有 Vercel 项目。按代码/数据依赖安排次序，不能只同步 JSON 就称新功能上线。
4. 数据发布后核课程版本、附件及本批关键状态；代码部署后核 READY、正式域名、实际页面或线上构建指纹。单纯写文件、点同步或启动部署不算完成。
5. 分别汇报 GitHub、本地看板与线上看板各自的真实结果，再提供适用的群消息草稿。同步失败要保留旧线上版本，记录失败阶段、影响和下一步，继续能独立完成的修复；不能只报“本地已完成”后省略线上状态。

## 边界

- 这是每批更新的必做发布步骤，不是上传中间半成品、每次自动保存都触发一次部署，或声称后台无限轮询。
- 保留事实/建议/未知、团队交件/本地辅助、已见验证/盲测、候选/定稿/正式提交的区分。可带明确待复核提示同步新事实，不得为了上线伪造验收或只换指纹消除提醒。
- 不自动递归上传未审文件；保持课程隔离和现有共享范围，凭据、私人通信及第三方个人资料按既有规则处理。
- 本规则不启用电脑或手机的 Remotely Save 自动同步，不替代原有原子写、完整性核对和同步关闭要求。
- 桌面“同步课程看板”继续保留给本人使用；它是补充入口，不是代理停止在本地、等待本人点击的理由。
