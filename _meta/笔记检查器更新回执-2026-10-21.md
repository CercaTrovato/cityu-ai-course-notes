# 笔记检查器更新回执 · 2026-10-21

按用户要求更新 note_quality.py；仅改工具、规则及验证证据，不修改课程笔记，不提交 Git。

## 1. 改了什么

默认使用 current 模式。固定七格标签、80/150/250/350 字阈值、两个类比、误解条数、页数／小节平均比不再直接制造当前 FAIL。接受普通段落、表格、编号步骤和有效代码注释；小节 a 后缀保留，父单元可以统合子节推导。发现旧代码语言匹配正则中误存的退格字符，一并改为真正的单词边界。

保留 L 格式、R 可读性与现行 C 内容证据检查。空正文、原题／空标签／占位句代替讲解、全篇没有可识别计算代入的计算公式、代码没有任务／关键行解释、可安全解析的纯数字等式矛盾、确定源版本的缺页归属、显式原题清单不符仍阻塞。理由／符号解释不足、跨单元例子和来源版本冲突只报待核；不能凭关键词缺失就断言解释不存在。

旧 G/E 算法与判定保存到 JSON historical 字段；显式 --profile historical --strict 可查看旧配额。编号和正则 bug 已修复，因此不把本次统计冒称旧版 bug 的逐字回放；此前历史日志和实修回执均未改写。

note_release_gate.py 已消费 C.hard：现行 C 结果缺失／不可靠或存在硬阻塞时，不能借 L/R 干净放行。发布门槛可透传 --source-checks；merge_apply.py 沿既有调用自动采用现行 C 检查，并同步显示 L/C/R。来源、候选、图资产哈希与教学回执要求保留。

## 3. 检查范围与限制

机器 PASS 只表示可验证项未阻塞。没有原题清单时明确 unverified_without_manifest；清单通过也只证明声明范围的源版本、全文／选项和逐问中英锚点匹配，不能证明所有原题已收、清单无抄写错误或答案语义正确。当前实际示例仅 2 题；不将其套到全讲或五门课。

纯数字等式检查不执行程序，不验证符号推导、模型运行或未识别单位／百分比换算。跨节算例是否对应同一机制、真实推理与 D 层证据、原题逐选项解析、来源真实性与实际图文显示仍按现行流程做一次实质核对；本次没有重做八篇教学验收或改变材料／本人学习状态。
