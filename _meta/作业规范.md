# 作业规范：从零学会，做出可核查的高质量成果

> 本文件管 `<课程>/assignment/`。讲义本身的教学题仍按 [[课件题目处理规则]] 在 module 正文逐问讲解；这里另建可操作的练习工作区。课程级补充不得降低本规范的来源、深度和私有门槛。

## 1. 先核 Canvas，再锁任务

每次新建任务和最终定稿前，检查对应课程的 Canvas **Assignments、Announcements、Files、Modules**。在任务总览记录四个入口、实际命中的任务／附件链接、核对日期与时间、版本或 SHA-256、计分、截止时区、迟交、交付格式和改动。只在讲义或课堂出现的练习也要查 Canvas；找不到时写「Canvas 未发布」和讲义页码或转录时间戳，不推断它会被收取。

Canvas 页面与附件冲突时逐项列出两种原文及核对时间；行政要求以较新的 Canvas 明示口径为准，但保留较早口径供复核。附件无法取到、版本未比对、评分标准缺失时，任务保持 `draft`，不得宣称可提交。原始材料始终留在 `course_files_export/`，只读引用；ZIP 的处理见 [[材料处理规则]] §8c。

## 2. 私有目录和总览

```text
<课程>/assignment/                 # 整棵树本地私有
├─ 00-overview/                    # 侧栏最前的阅读入口
│  ├─ 作业总览.md                  # 首屏：当前任务、截止、状态、下一步
│  └─ 知识地图.md                  # 首现台账与课程知识回链
├─ graded/
│  └─ A01-topic/                   # 每项计分任务仍有独立目录
│     ├─ notes/开始这里.md          # 导览；未有实质教程时用任务说明.md
│     ├─ work/                     # 可复现 Notebook、工作稿、衍生结果
│     └─ submission/               # 明确标 DRAFT 的草稿或核查后的正式件
└─ practice/
   ├─ 练习索引.md                  # 来源、缺口、待回填状态
   └─ M01-练习精读.md              # 有实质内容且核实后才创建，按讲次合并
```

一项项目的报告、视频等多个交付物仍放在同一个 `Axx` 目录。总览首屏必须让读者知道当前作业、正式截止／冲突、进度和下一步点哪里；其后用逐项任务卡列出评分与交付，不把宽表当学习入口。逐项保留：ID／题目／类型／Canvas 链接与原始来源／评分或占比／截止（含时区；无则写无）／交付清单／教程与工作区链接／前置讲次／进度／阻碍／最近核对。**文件存在、本人学会、Canvas 提交是三件不同的事**。仅用户确认后记录「本人已学习／练习」或「已提交」。

状态依次为 `待核`、`draft`、`可提交`、`已提交`、`已评分`；历史练习可用 `待回填`。只有全部 §5 门槛通过才从 `draft` 升为 `可提交`。总览不得把预计 DDL 写成正式 DDL。

## 3. 手把手教程与知识递进

教程按「题意和逐小问评分点 → 先修唤醒 → 概念与语法 → 理论和实现对照 → 按顺序操作 → 输出解释 → 失败排查 → 自测 → 加分深度 → 提交核对」写。课程讲义的 L0 不自动成为作业 L0：**Python 的变量、函数、循环、参数、路径，以及 pandas／sklearn API，首次使用时都须用人话、最小例子和实际代码解释**。非代码题同样解释推理步骤、依据、反方与限制。

`00-overview/知识地图.md` 记录「概念／English 或代码写法／首次作业与小节／一句话定义／依赖／课程笔记或术语表回链」。首次出现就地完整解释；后续给一句唤醒和回链。作业台账链接课程 `_meta/知识层级台账.md`、`_meta/术语表.md` 与对应 module。可公开且不泄露完整评分答案的通用术语才回写课程术语表；公开笔记不指向私有完整答案，避免 GitHub 断链。

代码教程的示例必须与 `work/` 源码一致；从干净环境按展示顺序运行，不依赖未说明的变量或手动修改中间结果。每步列输入文件、路径、运行命令、预期输出、图表或公式的符号与单位、常见报错及检查办法。影响结果的随机种子、划分、缺失值和模型选择均在源码及教程写明。生成图表必须能从源数据重做；原始材料不得改动。

### 3a. Notebook 与练习的实际阅读验收

**Notebook 的 HTML 提交件（2026-09-30 用户明确）**：先在 `.ipynb` 完成并保存答案、解释、代码输出、图表和字号，再通过 Jupyter 菜单或标准 `nbconvert --to html` 直接导出。HTML 与 Notebook 保持相同的单元格顺序及内容；不另制作 HTML 页面，不重排、隐藏或单独维护答案。辅助导出脚本仅调用标准导出器并保存返回结果。

代码作业采用 Obsidian 导览 + Jupyter 完整教学：每个代码 cell 前说明目的、新概念与关键语法，紧接可运行代码，运行后解释预期输出、关键数值、常见错误、理论对应与「所以呢」。核心分析不能只调用外部大函数。导览不重复维护长教程；Notebook 从一个数据路径 cell 开始，使用已核实的 kernel，从空内核 Restart & Run All。

源码 ZIP 从同一 Notebook 生成清除输出的副本，不另存一套分析逻辑；基线数值核对完成前保留旧脚本。三表、模型、权重须与旧结果一致，任何差异逐项记录依据。目录改变后须重新核报告生成、打包、相对路径和解压重跑。

非计分练习按讲次合并。未写好只在练习索引登记来源、受阻与待回填，不创建 Pxx/tutorial 占位目录。旧占位目录先备份与哈希，检查无后增成果，将来源/阻碍/链接合入索引，再移到 vault 外可恢复归档。尚未取得课堂内容的计分任务用任务说明登记，不称教程。

独立公式的开始与结束 `$$` 必须各占一行，符号就近解释并给数字例子。逐式实际查看 Obsidian 与 Jupyter：红色 LaTeX、源码未渲染、缺字或溢出均不合格。验收须从 Obsidian 侧栏走到总览、任务导览和下一步，再实际运行 Notebook；链接检查通过不能代替看懂、找得到和跑得通。

## 4. ★ 加分深度是所有计分作业的必做项

先逐项满足题目与评分标准，再提出至少一个由**实际结果或可靠来源**支持的深入判断、拓展检验与局限。AI／ML 可检验泛化、模型行为或泄漏风险；金融可分析收益与集中风险；伦理可比较利益相关者与反方；会计可测试口径和边界。明确区分「教授要求」「材料事实」「团队推断」。额外模型或图表须回答具体问题；复杂度本身不算加分。

教师规定的 Figure／Table 编号与顺序不可改。若允许附录，新增图表标 `Figure A1`、`Table A1` 等，从正文引用，不占用规定编号。若禁止附录或页数不足，在允许正文中写有证据的精炼拓展，不挤掉必答内容。不计分练习也加入可迁移的思考，但不虚构评分加分点。

## 4a. ★ 人工阅卷可读性、数字与公式一致性

老师会逐页看成品。**在不牺牲题目覆盖、证据和分析深度的前提下，首先让人读得顺**：正文用清楚的学生语言，先给结论和它对应的具体结果，再解释方法与限制；首次出现的技术词当场定义。删掉空泛套话、重复的“重要性”宣言和堆叠的长句；不要为了显得专业而把简单判断写成难读的 AI 腔。完成后遮住代码，只读报告正文并朗读抽查：没有运行环境的老师能否看懂“做了什么、结果是什么、为什么可信、哪里不确定”。

默认排版以 **A4 正文约 10.5–11 pt、表格及图注至少约 9 pt** 为起点，留足行距和图表周围空间；课程若给出指定模板或字号，以课程规定为准。不能靠把正文、表格或图注缩到难读来塞进页数上限，应先压缩重复话、调整图表尺寸与分配页空间。所有图轴、单位、图例和脚注在正常 PDF 缩放及打印预览下须可辨；逐页查看，不仅检查 `pdfinfo` 页数。

**先从现行 brief 摘出数字口径并写一张“精度表”**：每类量确定单位、展示小数位、舍入方式及适用位置。若要求至少六位小数，就在该类量的正文、表格、图注和附录一致保留至少六位；若要求的是六位**有效数字**，要按有效数字而非小数位执行。不同量可以有不同精度，但同一指标重复出现时必须相同；百分数与小数不能无说明地混用。所有模型选择和汇总计算用**未舍入值**，最后一步才格式化；检查负号、零、N/A、时间区间、样本量、变量名和大小写在全文一致。

**公式必须在最终成品中以数学公式显式排版**：Markdown 用 `$…$`／`$$…$$`，PDF／Word 用真正渲染的上下标、分式、根号和数学符号，不能把 `x^2`、`sqrt(52)` 等代码写法直接当作成品公式，也不能让读者看到未渲染的 LaTeX 源码。关键公式就近解释每个符号、单位与一个数值代入；导出 PDF 后逐页视觉检查公式不缺字、不变成方块、不溢出。图表和公式的标题、编号与正文引用也逐项对照。

## 5. `可提交` 的六道门槛

1. Canvas 现行题面、附件版本、DDL、评分与提交方式已核对；差异已记录。
2. 每小问有直接答案、过程或证据、来源和边界；教师规定的图表／表格全部对应。
3. 零基础读者可从头独立重做；代码从干净环境直接运行且数值与报告一致。
4. **加分深度有可复核的依据、解释和局限；缺失即保持 `draft`。**
5. 页数、文件名、图表编号、单位、**人工阅卷的字号与说人话程度、同指标全篇精度一致、公式实际渲染**、隐私及官方检查器均符合本作业要求；视觉复核有记录。
6. 人员信息、提交人、团队结论由本人核实；缺身份资料的文件明确标 `DRAFT`。

没有全库统一的 AI 辅助声明。仅当 Canvas 与当前 brief 对该项作业明确要求时，才在该项交付检查中列入并如实处理。不能以「去 AI 味」替代真实性或课程规定。

## 6. 安全、回写与验收

`assignment/` 默认全部本地私有，不能因总览或临时脚本误入公开 Git。迁移既有个人作业先备份和哈希核对，再解除旧路径跟踪；普通取消跟踪不清除 Git 历史。不得移动、改名或修改 `course_files_export/` 的原始课件。同步关闭后才写 vault；开工备份与快照，收工核对完整性及意外改动，写笔记使用 `_meta/tools/safe_write.py` 的原子写机制。

计分任务状态同步到课程总览、`_meta/作业与DDL.md` 和可访问的 Notion 作业看板；Notion 只记进度，不复制私有正文。若无连接，列出需人工更新的字段和值。提交 Canvas、Git 提交或推送须由具体任务授权，不因产生文件自动执行。
