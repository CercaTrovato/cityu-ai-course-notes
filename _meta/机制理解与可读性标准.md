# 机制理解与可读性标准

本文件只定义**不同内容需要解释到什么深度**。读者起点与表达按 [[可读性总规则]]；独立子代理审查按 [[笔记制作与融合验收流程]]。D 是教学证据维度，不是自动评分，任何 L/C/R、历史 G/E 或回执通过均不能推出机制已讲透。

## 1. 核心与背景的边界

本讲要求读者执行、计算、用来解题或据以得出关键结论的方法，是核心。它不因讲义仅一行、登记 L0、曾学过或在库函数内部而免讲。只作历史、目录、对比名称或未来预告，当前结论无需操作其内部机制的，才是背景：说明输入输出/用途、当前影响和展开位置，不无限追补。

作者在候选前列核心任务与背景边界，独立审查者核对是否漏掉实际依赖。不能把“调用模型预测”所需的关键训练/预测机制降为背景来减少工作；也不因代码调用了一个底层排序函数，就在无关课程重讲排序算法。判定依据是**本讲学习目标与当前推理依赖**。

## 2. 深度维度与适用原则

下表为作者和审查者的内部问题，不强制八个标签、图数、失败场景数或题数。适用内容取并集，同一解释可同时满足多个维度；无需重复扩写。确不适用须根据当前任务说明理由，不能以内容难免讲。

| 维度 | 所需证据 |
|---|---|
| D1 问题与输入输出 | 具体任务、对象、已知/待求/参数、输出及其意义 |
| D2 状态与步骤 | 按顺序追踪对象和量，写关键中间状态及更新顺序 |
| D3 结构与控制 | 流程/数据流/关系图或清楚的结构表达，匹配真实机制 |
| D4 依据 | 定义/约定、推导、经验事实、实现或规范依据及必要条件 |
| D5 完整实例 | 同一输入走到本讲要求的终点，中间结果可核 |
| D6 结束与边界 | 为什么此处可结束，空集/平局/零分母等实际相关边界 |
| D7 失败与取舍 | 会错在哪里、为何会错、怎样识别或调整及代价 |
| D8 迁移与诊断 | 改关键输入/条件后的有理由答案，验证能复用机制 |

不强制每个术语完整 D1–D8。纯概念没有迭代就不编停止条件，规范论证没有数值就不编公式，行政信息只说明事实与行动。多个能力要求来自当前任务，不能互斥分类逃避算法中公式/代码的解释。

## 3. 内容类型的最低深度

下列具名例子是历史失败的反例锚点，不是穷尽清单或每篇必写主题；作者与审查者须从本讲任务识别新的同类断点。

### 3.1 算法与可执行过程

公开数据形状、初始化、状态、步骤/分支、更新式和判断依据；用同一小例从输入到输出，展示真实变化及停止检查。本讲核心迭代/分支算法保留可追踪的控制流程图，返回边与终点明确；同一有效图可服务多个单元，不设每标题图数。单步运算不因“有计算”扩成算法八件套；无迭代过程用依赖/数据流表达，不虚构循环。核心流程不能由算法家族分类图代替。

数值算法解释目标量、关键更新理由及所需最小推导。以 K-means 为例，要能说明最近分配、固定成员为何取均值、状态如何更新，以及局部停止不保证全局最好。若本讲教学 K-means++，须解释距离平方权重、归一化、实际抽取及加入中心后的重算，再接主迭代；概率表不是一次抽样运行。

讲清理论与实现：容差/最大步数不冒充理论收敛证明；“有下界”不足以单独证明有限步停机。按实际机制说明平局、空簇等边界、失败征兆及调整代价。抽样公开种子或所用随机数，不沿用旧状态的概率/距离。

### 3.2 技术系统与工具

追踪一个真实或明确标补充的输入经过各模块，说明中间表示、状态由谁保存、每模块做什么、失败如何传递，以及最终输出。数据流图区别训练/使用、检索/生成、模型/周边系统，不只画“用户→模型→答案”。实际使用到数值算法或代码时再叠加其要求；背景模块说明职责即可。

### 3.3 会计、金融与统计计算

先固定主体、时点、单位与输入，再讲业务动作及账户/数量变化。公式或记账规则说明性质与适用条件，展示完整算例和结果含义。明确存量/变化量、总额/单价、样本/总体、比例的分母和信息何时可知。

AMM 的恒定乘积是选定定价规则，不是价值不变的自然定律；池子新余额不等于用户付款；交易前报价、整笔均价和交易后下一小笔报价对应不同问题。会计借贷是按账户类型使用的记账方向，不能让“借=增加”冒充通用规律；客户账本与银行账本切换须重新说明主体。试算平衡不保证无任何会计错误。

核对恒等式、数量级和适用的经济解释，展示改变关键条件后哪一步重算。缺原始数据时列已知、未知及可判断范围，不倒造数据假装复算。

### 3.4 伦理、法律与理论论证

先给事实和要判断的问题，再列判断标准、适用前提、从事实到结论的步骤、最强反例/冲突与改条件后的结论。概念须能实际用于案例，而不只是背定义；例如要求写 maxim 时，应示范如何从行动者/情境/行为/目的构造待检准则。

区分理论内判断、经验事实、价值取舍与现行法律结论。法律/标准注明法域、版本和时间，涉及现实有效性时核当前一手来源，无法核实保留限制。论证图呈现真实依赖，不画观点名词串；无数值依据不编公式。

### 3.5 概念、比较、图表与行政事实

概念解释用途、正式含义、正例和易混反例；比较选共同任务与维度，说明条件怎样影响选择；图表说明一行/点/线/轴代表什么、怎样从值到结论、何种反读会错。具体例连接正式抽象，类比能反解回准确条件，不以“通俗”删掉阈值或例外。

行政事实只给来源、现行要求、冲突/未知与该做什么；不强加算法、类比或迁移题。安装/软件步骤按实际操作解释，环境安装仍须用户允许。

## 4. 完整例、推导和图的边界

例子优先使用原材料；新增例、推导、条件变式标“笔记补充”，保留原例及来源。数字脚本与结果留库外任务目录，长期需要复验的成果在正式核对记录保留关键输入/输出及可定位来源，不只留下会消失的临时路径。

完整例的终点由任务决定：要求完整迭代就不能止于第一轮；要求识别关系就无需造数值运算。按真实不同动作展开，不设最少行数。正式推导与直觉相连，不把模型约定写成被证明的事实；引用定理可明确未在此证明，但须解释本节使用方式与条件。

图选择、语义和实际观看按 [[教学图示规范]]、[[教学图示工具流程]] 及 [[可读性总规则]] §11.3。节点、箭头、图例、公式和正文用同一对象与条件，示意趋势不冒充实证结果。
