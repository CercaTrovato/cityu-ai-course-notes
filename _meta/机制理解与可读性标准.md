## 1. 先定深度，不能用 L0 免讲本讲主角

逐个登记实际出现的方法、技术、计算或推理过程，而不是只数标题。按用途分两级：

| 等级 | 判定 | 必须做到 |
|---|---|---|
| 核心 | 本讲正式教学；出现在学习目标 / 术语卡；用于解题或计算；课堂案例的关键因果环节；代码真正调用的建模方法 | 按 §3 的适用类型完整展开。不以“L0”“前面学过”“讲义只一句”免除机制说明 |
| 背景 | 只用于历史、目录、对照或未来预告，当前任务不要求执行它 | 一句话说明作用、与当前内容的关系和具体回链 / 展开位置；不能以一句话承担本讲实际用到的运算 |

本篇更早处已经讲透同一机制时，给精确回指、一句话唤醒，再解释当前变式；不重复整段。跨篇回链不能代替本节运行算法所需的操作知识。将主题降为“背景”须在审修台账写出来源与理由；以减少欠账为目的降级无效。

**先修最小包**：每个核心机制开始前点明所需知识。求和、向量、矩阵、概率、导数等若要实际操作，给就地读法与最小例子；不能只将词放进 §5 术语表便认为已解释。语法在 T01 已解释的，可唤醒后回指；具体库参数、数据形状和返回值必须解释。

## 2. 按五个台阶组织正文，支持不同基础的读者

五个台阶组成同一条学习链，不能互相替代，不强制新增五级标题：

1. **先看问题**：用一个具体任务说明输入、想要的输出，以及直接做会遇到什么困难。前三行不得堆陌生术语。
2. **建立直觉**：先解释它怎样解决问题；类比要说明对应关系与类比失效处。生活故事不能代替真实步骤。
3. **看见机制**：展现操作顺序、状态变化、判断分支、循环或依赖链；告诉读者每一步接收什么、改了什么、留下什么。
4. **解释依据**：把关键公式 / 规则与上一步动作对应起来，解释为什么合理及依赖的条件；通过一个完整例子验证。
5. **迁移和诊断**：换数据、参数或情境，要求读者预测中间结果、发现错误、判断何时换方法。

数学较强的读者可以快读直觉层，但数学部分须自足；数学较弱的读者顺读时不能从“这是均值”突然跳到未解释的矩阵方程。可以标“先读机制，再读推导”，不把核心依据挪到 §9 或另一篇导致主线缺失。

## 3. D 层必做证据：按类型叠加，不能互斥判型

一个单元可以同时属于算法、公式、代码和图表类型，适用要求取**并集**。算法包含公式时，公式六件套和算法八件套都要有；把算法改名为“定义型”或把公式放进引用块不能减少要求。纯概念、历史或行政信息不强加数学、循环或伪代码。

### 3.1 算法与可执行过程：八件套

| 证据 | 正文最低内容 | 验收动作 |
|---|---|---|
| D1 问题、输入与输出 | 任务；数据的行列 / 形状；已知量、超参数、待求量；输出标签 / 数值 / 结构及其含义 | 读者能说清算法接收什么、交出什么；不把 K 当作输出、不把初始化当完整聚类 |
| D2 状态与步骤 | 编号步骤，每步写输入 → 动作 → 中间输出；定义当前中心、已访问集合、候选队列等实际状态；说明更新顺序 | 能在任一步暂停，列出当前状态并继续下一步；不能只背“分配、更新、重复” |
| D3 控制流程图 | Mermaid 图放在机制附近；节点与编号步骤对应；分支标判断，循环画返回边，终点写输出 | 迭代算法的图能区分初始化、迭代和停止；仅有“算法家族分类图”不算 |
| D4 原理与数学 / 逻辑依据 | 数值算法给目标量、核心更新式、符号表；逐项解释为何这样算；至少解释一个关键步骤的推导或不变量。非数值过程给规则、依赖和约束 | 能回答“为什么是平均值”“为什么取最近中心”“为什么边界点不能扩展”这类机制问题；只贴公式不算 |
| D5 从输入到结束的完整例子 | 同一份小数据贯穿；公开初始状态、至少一次非平凡更新、必要的下一轮、停止检查与最终输出。每步中间结果可核；数字附脚本来源 | 遮住结论仍能按步骤得到结果。只给第一次迭代、概率表或最终标签不算完整 |
| D6 停止与边界 | 正常停止、实现的容差 / 最大步数等与理论区分；平局、空集、零分母等至少覆盖实际会遇到的边界 | 能说明“为什么现在停”，以及遇空簇、相同点等如何处理；不能用“有下界”独自证明有限步停机 |
| D7 失败机制与选择 | 至少两个与机制相连的失败 / 敏感场景，并说明诊断征兆、可行调整与其代价 | 解释为什么失败，不能只罗列“怕离群点、怕高维”；不把改进说成保证 |
| D8 迁移题与可核答案 | 新数据 / 新参数 / 新情境，至少一题预测中间状态，另一题判断失败原因或替代方法；折叠答案含理由与来源 | 审查者实际解题并记录中间结果；“我认为读者可以”不算证据 |

**数学深度的边界**：解释支撑算法操作的最小推导，不无目的展开定理。K-means 至少讲 SSE、固定中心时为何最近分配、固定成员时为何均值最优，以及局部停止为何不保证全局最好。K-means++ 至少讲最近中心距离、平方权重、归一化概率、累计概率抽样、加入新中心后的重算，再接回 Lloyd 迭代。概率保证若写出，区分期望与单次结果；未证明的定理可给来源与读法，不假装已推导。

**无天然迭代的过程**：用依赖 / 数据流图替代返回循环；完整例子仍须走到输出。不得为了满足图形要求虚构循环。

### 3.2 技术系统与工具

如 tokenization、embedding、attention、Transformer、RAG、agent harness、SQL / Access 与 API 工作流：讲清 **输入 → 各模块动作 → 中间表示 → 输出**，画真实数据流或调用流程；至少追踪一个具体输入经过系统的全过程。明确由谁保存状态、检索与生成各自使用什么、失败如何传递，区分训练与使用、模型与周边系统。若包含数值机制，再叠加 §3.1 D4 的数学要求；若包含真实代码，叠加 [[笔记质量规范]] §5.7，并交代数据形状、参数效果、输出核对和运行环境。不能只画“用户 → 模型 → 答案”。

### 3.3 会计、金融与统计计算

给业务问题、已知数据与单位、公式 / 记账规则的适用条件、推导或守恒关系、完整算例、核对恒等式 / 数量级 / 样本外边界、参数或业务条件改变后的结果。每一步说明经济或会计含义。金融策略须说明信号何时已知、交易发生时间与收益对应期；有算法的树、正则化、神经网络仍走 §3.1。试算平衡不能被写成没有任何会计错误的保证。

### 3.4 伦理、法律与理论论证

给要回答的问题、前提、判断标准、逐步推理链、案例事实到结论的映射、最强反例 / 冲突与条件改变后的结论。流程 / 论证图呈现实际决策依据，不能把观点列表当推理。明确理论内有效性、经验事实、规范性判断与法域 / 时间范围。没有数值依据就不编数学公式；法条与现实法律结论须核当前一手材料，无法核实则标来源限制。

### 3.5 图表与纯概念

图表解释坐标、点线 / 颜色、如何从图得到结论、可能读错的原因，并给一项变式。纯概念解释定义、动机、正例、反例、与近邻概念的边界和下一步用途。概念一旦被用来执行某个核心计算或判断，叠加对应过程要求。

## 4. 算例与图示的实质门槛

- 数据优先来自讲义；图片坐标只有目测值时不能把它写成精确原始数据。为教学新增的迷你数据必须标 **“💡 笔记补充”**，与原例分开。
- 手算展示至少 3 个**不同动作**，而不是把同一式子拆成 3 行；迭代至少展示一次状态真的变化，再给必要后续状态和终止依据。若例子第一轮即停，应另给能体现变化的例子。
- 抽样须指定随机数或随机种子及选择规则，概率表本身不是一次运行。重算距离不能沿用旧表。训练 / 验证方法须防数据泄漏。
- 复算脚本和结果放 vault 外的本任务目录；正文写脚本绝对路径或可定位的脚本名及输出量。长期项目内既有 code 仍按原材料规则管理。不能只引用一个已经找不到的历史脚本并声称已验证。
- Mermaid 节点文字、判断和返回边须与算例一致；至少实际解析并看最终图形，语法无报错仍不能证明流程正确。符号单位一致，表格中数学竖线用 `\mid`。

## 6. 执行顺序、验收状态与并发保护

1. 先读课程背景、概念台账、现行规则、全部本讲材料；盘点核心与背景主题，找原文和现有讲解差距。
2. 写逐主题缺口与修复动作，先修机制和错误，再补图 / 算例 / 变式。不按增加字数排序。
3. 分块修复，保留逐页说明、原题与课堂引文；补充推导显式标“笔记补充”，不冒称教授讲过。
4. 跑 `note_quality.py --strict --sections`、`link_check.py`、`readme_check.py` 和完整性核对；记录具体问题。机器检查只判结构，不宣告理解通过。
5. 对新重要算例复算、对新图看渲染，按 §5 做一次定向核对；有缺口修对应主题。背景主题检查遗漏与悬空术语。
6. 台账状态限定 **未审 / 缺口已确认 / 已修待验 / 已验收 / 材料受阻**。新 frontmatter 可加 `mechanism_spec: v1`、`mechanism_review: pending|passed`；适用 D 项与必要定向核对完成后才写 `passed`。保留实际执行范围，不把旧转录 v1.0 降级来混淆材料融合与理解质量。
