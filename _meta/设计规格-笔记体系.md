# 设计规格 · 笔记体系

> 本体系的设计依据。**想改规则之前先读这里**——很多看起来多余的约束是有理由的。

---

## 1. 要解决的问题

把 CityU 四门课的原始材料，转成**没听过课的人也能学会**的中文笔记，并追踪学习进度。

**读者画像（唯一的、也是最重要的约束）**：只有 AI / 机器学习基础，哲学、伦理学、法律、会计、金融**零基础**。

这条画像推出了后面几乎所有设计决策。

---

## 2. 三个核心机制及其理由

### 机制一 · 前置知识台账

**要解决的**：读第 N 讲时冒出没定义过的概念。

**考虑过的方案**

| 方案 | 为什么不选 |
|---|---|
| 每讲开头写"你需要先知道 X、Y" | 只是声明。正文里照样会蹦出新的陌生词，管不住 |
| 靠写作时的自觉 | 不可靠，尤其换别的 AI 来写时 |
| **✅ 前置知识台账** | 唯一能**机械化验证**的方案 |

**为什么它有效**：把「零基础」从模糊形容词变成一条可对照的线（L0 基线），再把每个概念的首现 module 登记下来（L1）。于是"这个词该不该解释"变成一次查表，而不是一次判断。

**代价**：每写完一讲要回写台账。这是有意接受的成本——不回写，机制就失效。

### 机制二 · 正文按学习逻辑重排

**要解决的**：课件顺序 ≠ 学习顺序。

M01 的实证：60 页里前 13 页是课程行政信息，中间四段之间几乎没有过渡，且 FATP（整门课的目录）被埋在第 45 页的商业泛论中间。照页码抄，自学者会在第 13 页就被打断。

**代价**：读者看到的不是原顺序，可能对不上课堂进度。**用第 8 节的页码映射表补偿。**

### 机制三 · 讲义 × 转录双源比对

**加入时间**：2026-09-08，用户提出后追加（原设计只有讲义）。

**为什么它值得单独立一个机制**：讲义和转录不是同一种东西的两个版本——

- 讲义 = 教授**准备**讲什么
- 转录 = 教授**实际**讲了什么

**两者的差集才是最高价值的信息**。「课件没有但课上讲了的」只有到场的人才有；「教授说这个会考」是唯一能把考点从推断升级为事实的依据。把转录当成"讲义的补充说明"会浪费掉它最值钱的部分。

**代价**：多一道处理工序，且要处理 ASR 专名错误（哲学术语的语音转写错误率很高）。规则见 [[转录处理规则]]。

## 3. 其他设计决策与理由

| 决策 | 理由 | 代价 |
|---|---|---|
| **九节骨架固定，不增删节** | 空节本身是信息（"本讲无转录，无法比对"比没有这一节更有用）。固定结构也让跨 module 对比成为可能 | 某些讲会有几个近乎空的节 |
| **七格微结构不可省格** | 「🎙️ 课堂补充」这一格即使为空也保留——**让欠债可见**。删掉就再也想不起来哪里缺 | 无转录时看起来有点空 |
| **四种来源必须显式标注** | 读者要能分辨"这是教授说的"还是"这是 AI 编的"。这是笔记可信度的地基 | 标注符号增加视觉噪音 |
| **图表重画为 Mermaid/表格，不嵌位图** | 可全文搜索、可编辑、可被 AI 读懂、库体积小；且重画时可以把课件没画出来的隐含逻辑补进去 | 需要人工理解图意；纯图片页若不做视觉复核就会丢内容（M01 已发生，见其 §9.5） |
| **如实记录课件错误** | 读者需要知道哪些页信噪比低、哪些说法不能照抄进考卷。粉饰课件对读者零收益 | 需要有把握才敢下判断 |
| **单文件 + 课程级共享文件** | 单文件自包含、好读；术语/考点/DDL 跨 module 累积则必须共享 | 术语在两处（笔记 §5 + 课程术语表）都有，需同步 |
| **中文主体 + 英文术语与定义** | 考试是英文的，术语卡要能直接默写；但解释用中文才降低门槛 | 中英混排的排版成本 |
| **Notion 只管进度，不同步正文** | 避免一份内容两处维护导致不同步；Mermaid 在 Notion 也渲染不了 | 手机上看不了笔记正文 |
| **不建 git 仓库** | 用户明确要求，自行备份 | 无版本历史 |

### ✅ 已决策：篇幅不设上限（2026-09-09）

**触发**：M02 实测 35,909 中文字，超原上限 2.4 倍。

| 笔记 | 中文字数 | 行数 | 材料量 |
|---|---|---|---|
| M01 | 16,360 | 1,264 | 60 页讲义，**无转录** |
| **M02** | **35,909** | **2,811** | 86 页讲义 + **2h18m 转录（480 段）** |

**用户决定：模板不设上限。** 已写入 [[笔记模板]] 的「使用说明」。

**理由**（记录下来，将来想改时先读这段）：

1. **篇幅由材料量决定，不由指标决定。** 一门课每讲的讲义页数与录音时长差异巨大，任何固定字数区间都会在某些讲上逼着人删内容
2. **有转录的一讲天然是无转录的两倍以上。** 三大核心机制里的「讲义 × 转录双源比对」，产出物就是差集——课上讲了而讲义没有的内容。M02 这类内容有 8 大块。**为了压字数而砍它，等于砍掉这套体系的核心价值**
3. **备选方案都更糟**：
   - 拆成 `M<NN>-正文.md` + `M<NN>-速查与自测.md` → 违背用户已定的"单文件 + 课程级共享文件"组织方式
   - 压缩 ⚠️ 常见误解 / 💡 换个说法 → 砍掉的恰是"让没听过课的人也能懂"所依赖的部分，与 §1 的核心假设直接冲突

**代价（明知而接受）**：单篇变长，一次通读的时间成本上升。**对冲手段是笔记内部的分层**——§0 三分钟速览、§4 速查表、§6 考点清单，都是为"不通读也能用"设计的入口。

**唯一保留的硬约束**：讲义每一页都必须在 §8 映射表里有归属。**下限没有取消，取消的只是上限。**

## 6. 怎么改这套体系

1. 改**笔记骨架** → 改 [[笔记模板]]，并在本文件 §5 记录理由
2. 改**材料处理** → 只改 [[材料处理规则]]（加状态表一行 + 规则一节），不动根级 CLAUDE.md / AGENTS.md
3. 改**通用方法论** → 同时改根级 `CLAUDE.md` 和 `AGENTS.md`，**两份必须保持等价**
4. 改**某一门课特有的规则** → 改该课的 `CLAUDE.md` / `AGENTS.md`，不要污染根级

**已写好的旧笔记不强制回改**，除非用户要求。
