# 开源仓库说明：这是什么、怎么下载、怎么用、怎么复现

> 给从 GitHub 来的读者的操作手册：怎么下载、怎么打开、怎么跑验收脚本、怎么把这套方法搬去自己的课。动机、设计和机制的说明在根 [README](../README.md)。
> **先读 `NOTICE.md`**：课程材料与转录有使用限制，笔记可能有错。

---

## 1. 这是什么

我在 CityU 读 MSc AI in Business，这是我 2026 年 9 月开学起用 AI 辅助方式建的**五门课课程知识库**。它不是"上传几份笔记"，而是一套可运行的**知识工程流水线**：

```
讲义 PDF/PPTX ─┐
               ├─→ 双源比对 ─→ 九节骨架 + 七格微结构的中文精读笔记 ─→ 脚本量化验收 ─→ 独立零基础试读
课堂录音转录 ──┘         ↓
                 台账 / 术语表 / 考点库 / 作业与DDL / 数据集卡片 / 可复现代码
```

三个特点：

1. **讲义页码和课堂引文可追溯**：各篇 §8 记录页码映射；`_meta/tools/transcript_check.py` 核对时间戳与引文。脚本结果仍需人工对照原材料。
2. **质量有明确验收门槛**：`_meta/笔记质量规范.md` 把"透彻"拆成三层门槛（合规 / 密度粒度 / 元素清单），`note_quality.py` 判 PASS / FAIL；再按 `_meta/对抗自检清单.md` 做独立零基础试读。旧笔记未全部达到当前严格标准。
3. **方法与工具与内容分离**：规则、模板、技能、脚本（`_meta/`、`.claude/skills/`）可以直接搬去做你自己的课。

规模（2026-09-24）：5 门课、26 篇笔记（15 篇 v1.0、11 篇 v0.9）、16 个转录文本文件；EF5560 另有 `run_all.py` 可复现分析脚本。按现行严格标准追溯复测，7 篇 PASS、19 篇未通过；方法与局限见 [全库质量基线](全库质量基线-2026-09-24.md)。

## 3. 下载与打开

**下载**

```bash
git clone https://github.com/CercaTrovato/cityu-ai-course-notes.git
```

或在 GitHub 页面 `Code → Download ZIP`。整库约 80 MB，其中 67 MB 是课程材料；只想要方法与笔记可以只取 `_meta/`、`.claude/`、`*/notes/`、`*/_meta/`。

⚠️ **`*/course_files_export/` 与 `*/transcripts/` 受版权与隐私限制**，只用于核对笔记引用，**未经许可不得下载、再分发**——见 `NOTICE.md`。

**用 Obsidian 打开（推荐）**

1. 安装 [Obsidian](https://obsidian.md/)（1.13 以上）。
2. `Open folder as vault` → 选仓库根目录。
3. 仓库自带 `.obsidian/app.json`、`core-plugins.json` 等基础设置；**不含任何社区插件与同步配置**（`.gitignore` 排除了 `plugins/` 与 `workspace.json`）。公式（MathJax）、Mermaid 图、`[[双链]]`、`<details>` 折叠都是 Obsidian 原生支持。
4. 从根 `README.md`（vault 首页）或各课 `00-课程总览.md` 进入。

**用其他编辑器**：Cursor / VS Code 的 Markdown 预览能看公式与折叠，但 `[[双链]]` 不可点击；GitHub 网页可直接看公式，Mermaid 图也能渲染。

## 5. 怎么读一篇笔记

每篇 `M0N` 笔记都是同一副**九节骨架**：

| 节 | 内容 | 什么时候看 |
|---|---|---|
| §0 三分钟速览 | 这一讲讲了什么 / 学完应该能 / 只记三件事 | 课前 3 分钟 |
| §1 知识衔接 | 你已经有的（回指）/ 本讲新概念 / 重排说明 | 课前 |
| **§2 正文** | 每个概念一节，**七格微结构** | 主体 |
| §3 一图看懂 | Mermaid 图 | 复习 |
| §4 速查表 | 考前一页纸 | 考前 |
| §5 双语术语卡 | 可直接写进考卷的英文定义 | 考前 |
| §6 考点预判 | 🔴 教授明示 / 🟡 大纲反推 / ⚪ 笔记推断 | 考前 |
| §7 自测 | 概念题 + 案例题（答案折叠） | 复习 |
| §8 讲义页码映射 | 每一页讲义 ↔ 笔记小节 ↔ 课堂覆盖 | 对照讲义时 |
| §9 延伸与勘误 | 课上略过 / 课上补充 / 讲义的错 / 课外补充 / 待核对 / 变更记录 | 怀疑笔记时 |

§2 每个小节固定七格：**是什么**（先人话再定义）→ **为什么需要它** → **课件原例**（讲义 p.X）→ **🎙️ 课堂补充**（带时间戳的教授原话；无转录写"待转录补充"）→ **💡 换个说法**（≥ 2 个角度）→ **⚠️ 常见误解**（每条带"为什么错"）→ **所以呢**（引向下一节）。公式型小节另有符号表、手把手数字例子、"为什么公式长这样"、极端情况。

四种来源标记：`（讲义 p.X）`原文 · `🎙️` + `` `时间戳` `` 课堂转录 · `💡（笔记补充）`AI 或我补的解释 · `🔗` 外部资料（带获取日期）。**⚪ 与 💡 是推断，出错概率最高。**

版本：`v0.9` = 只有讲义；`v1.0` = 已合并课堂转录。frontmatter 里有 `transcript: pending / merged`。

## 6. 复现与验收

**环境**：Python ≥ 3.9。三个验收脚本只用标准库；EF5560 `code/` 需要 `pandas numpy matplotlib statsmodels scipy`（`EF5560_Fintech_and_AI_in_Finance/code/requirements.txt`）。Windows 上先 `set PYTHONIOENCODING=utf-8`（或在 Git Bash 里 `export`）。

**① 笔记质量量表**（任何一篇笔记，在仓库根目录）

```bash
python _meta/tools/note_quality.py IS6400_Business_Data_Analytics/notes/M03-数据类型与描述性分析.md --pages 69 --strict --sections
```

输出 L（合规）/ G（密度粒度硬门槛）/ E（元素清单）三层与 PASS / FAIL；`--sections` 打印逐小节明细。阈值定义在 `_meta/笔记质量规范.md`，校准过程在 `_meta/质量体检-2026-09-16.md`。

**② 全库链接检查**

```bash
python _meta/tools/link_check.py
```

期望输出 `link_check 问题数: 0`。

**③ 转录融合验收**（证明笔记里的时间戳和引文能回到转录）

```bash
python _meta/tools/transcript_check.py audit AC6761_Artificial_Intelligence_Accounting/notes/M02-交易的会计处理.md --transcript AC6761_Artificial_Intelligence_Accounting/transcripts/M02-transcript.txt AC6761_Artificial_Intelligence_Accounting/transcripts/M01-transcript.txt
```

12 项检查（A1–A12），其中 A4 逐个核对时间戳是否存在、A5 用词组模糊匹配核对每句原话是否真的在转录里——这是防止 AI 编造引文的机制。

**④ EF5560 讲义数字复现**

```bash
cd EF5560_Fintech_and_AI_in_Finance/code
python run_all.py          # 11 个脚本；每个脚本头部写明对应讲义页与笔记小节
```

图与表输出到 `code/output/`，笔记用 `![[...]]` 引用。

## 7. 用同一套方法做你自己的课

1. 复制 `_meta/`（规则 + 工具）、`.claude/skills/transcript-merge/`、根 `CLAUDE.md` / `AGENTS.md` 到你的 vault；建一个课程目录，照 §4 的结构放 `course_files_export/` 与 `transcripts/`。
2. 先写 `_prep/课程前置资料.md`（大纲对校）和 `_meta/知识层级台账.md`（哪些概念算已知、哪些要就地展开）——这两份决定笔记的详略。
3. 让 AI 助手（Claude Code 会自动读 `CLAUDE.md`；Codex 等读 `AGENTS.md`）按 `_meta/笔记模板.md` 分块写笔记，每写完一块跑 `note_quality.py --strict --sections`，不达标不进下一块。
4. 转录到手后按 `.claude/skills/transcript-merge/SKILL.md` 合并，用 `transcript_check.py audit` 验收。
5. 派一个**没看过讲义**的 AI 按 `笔记质量规范.md` §8 的六道题试读，结果写进笔记 §9。

Notion 进度看板（`_meta/Notion进度看板.md`）是我个人的，字段定义可以参考，数据库本身不公开。

## 8. 已知限制

- 笔记是 AI 生成 + 我复核的产物，**不是官方材料**；已知问题在各笔记 §9.3 / §9.5，未知问题一定还有。
- 转录是 ASR 输出，错误率高（会计课最差，见 `.claude/skills/transcript-merge/reference/asr-dictionary.md` 的真实样本）；笔记引用时已按讲义纠正并用 `[ ]` 标出改动，但不保证每处都对。
- 部分笔记（2026-09-16 之前写的）尚未按新版质量规范返工，`_meta/质量体检-2026-09-16.md` 列出了哪些 FAIL、差在哪。
- 只有 EF5560 建了可复现代码库；其他四门课的数字来自笔记里注明的脚本（当时在临时目录跑），未全部入库。
- 中文为主，英文只出现在术语、引文与定义。

## 9. 反馈与贡献

- **发现笔记错误**：开 Issue，写明笔记文件、小节号、讲义页码，最好附你认为正确的说法与依据。
- **改进规则或脚本**：欢迎 PR；规则改动请同时更新 `_meta/` 里的对应文件与变更记录。
- **版权或隐私问题**：按 `NOTICE.md` 联系，会立即处理。
