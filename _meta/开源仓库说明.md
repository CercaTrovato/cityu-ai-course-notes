# 开源仓库说明：这是什么、怎么下载、怎么用、怎么复现

> 给从 GitHub 来的读者的操作手册：怎么下载、怎么打开、怎么跑验收脚本、怎么把这套方法搬去自己的课。动机、设计和机制的说明在根 [README](../README.md)。
> 规则体系是本库的核心：先读根 README 的[规则体系](../README.md#规则体系)，再按[笔记制作与融合验收流程](笔记制作与融合验收流程.md)执行；README 负责解释各文件如何协作，本文件负责下载、复现和迁移操作。
> **先读 `NOTICE.md`**：课程材料与转录有使用限制，笔记可能有错。

## 1. 这是什么

我在 CityU 读 MSc AI in Business，这是我 2026 年 9 月开学起用 AI 辅助方式建的**五门课课程知识库**。它不是"上传几份笔记"，而是一套可运行的**知识工程流水线**：

```
讲义 PDF/PPTX ─┐
               ├─→ 双源比对 ─→ 九节骨架 + 七格微结构的中文精读笔记 ─→ 必要来源/计算核对 ─→ 文件与结构检查
课堂录音转录 ──┘         ↓
                 台账 / 术语表 / 考点库 / 作业与DDL / 数据集卡片 / 可复现代码
```

三个特点：

1. **讲义页码和课堂引文可追溯**：各篇 §8 记录页码映射；`_meta/tools/transcript_check.py` 核对时间戳与引文。脚本结果仍需人工对照原材料。
2. **质量与理解分别核对**：L/G/E 检查结构、粒度和元素，R 层辅助定位句段、表格与解释缺口；`_meta/机制理解与可读性标准.md` 要求运行步骤、原理、可复算例和失败边界。按 2026-10-02 的现行流程，一次实质修复后只核必要来源、计算、新增图形和文件安全，不重复全量 Q/R 盲读或补造读者分数。讲义原题仍逐问作答，来源和评分成品边界仍须保留；脚本 PASS 不代表事实全部正确。
3. **方法与工具与内容分离**：规则、模板、技能、脚本（`_meta/`、`.claude/skills/`）可以直接搬去做你自己的课。

当前规模（2026-10-10）：5 门课、29 篇笔记（22 篇 v1.0、7 篇 v0.9）、25 个转录文本；EF5560 的 `run_all.py` 当前发现 15 个分析脚本。9 月 24 日的 7 PASS / 19 未通过属于当时 26 篇的[历史复测](全库质量基线-2026-09-24.md)，不能作为当前库存结论；本次没有重跑全库 strict。

课堂／课间练习的共同标准见 [[课堂练习完成与解析规范]]：难句拆到具体对象和条件，所有小问讲出过程，配学习总结、误区与改条件例；五门课的两类规则入口及课程作业细则共同继承。个人完整案例仍留私有 `assignment/`，不把参考解析完成写成官方已核、本人学会或已提交。

配图方法固定在 [[教学图示规范]] 与 [[教学图示工具流程]]：普通流程用 Mermaid，密集模型用本地 Graphviz／Viz.js 的 SVG，真实数值图用 Matplotlib。保留来源清单与可编辑图源，分别核对业务含义和实际显示；完整个人图与答案继续留在私有 assignment。

本轮 29 篇的图文可读性整改、98 个配套资产和检查边界见 [2026-10-10 更新记录](更新记录-2026-10-10.md)。在 GitHub 上可直接查看普通 Markdown 公式与 Mermaid；`[[双链]]`、`![[图片嵌入]]` 请用 Obsidian 打开，图源目录也可直接浏览。

## 3. 下载与打开

**下载**

```bash
git clone https://github.com/CercaTrovato/cityu-ai-course-notes.git
```

或在 GitHub 页面 `Code → Download ZIP`。仓库同时包含讲义、数据、转录和部分生成图表，下载体积会随材料增加；只想读方法与笔记可以优先取 `_meta/`、`.claude/`、`*/notes/`、`*/_meta/`。

⚠️ **`*/course_files_export/` 与 `*/transcripts/` 受版权与隐私限制**，只用于核对笔记引用，**未经许可不得下载、再分发**——见 `NOTICE.md`。

**用 Obsidian 打开（推荐）**

1. 安装 [Obsidian](https://obsidian.md/)。
2. `Open folder as vault` → 选仓库根目录。
3. 仓库自带 `.obsidian/app.json`、`core-plugins.json` 等基础设置；**不含任何社区插件与同步配置**（`.gitignore` 排除了 `plugins/` 与 `workspace.json`）。公式（MathJax）、Mermaid 图、`[[双链]]`、`<details>` 折叠都是 Obsidian 原生支持。
4. 从根 `README.md`（vault 首页）或各课 `00-课程总览.md` 进入。

**用其他编辑器**：Cursor / VS Code 的 Markdown 预览能看公式与折叠，但 `[[双链]]` 不可点击；GitHub 网页可直接看公式，Mermaid 图也能渲染。

## 5. 怎么读一篇笔记

每篇 `M0N` 笔记都是同一副**九节骨架**：

| 节 | 内容 | 什么时候看 |
|---|---|---|
| §0 三分钟速览 | 这一讲讲了什么 / 学完应该能 / 只记三件事 | 课前 3 分钟 |
| §1 知识衔接 | 你已经有的（回指）/ 本讲新概念 / 重排说明 | 课前 |
| **§2 正文** | 每个概念一节，**七格微结构** | 主体 |
| §3 一图看懂 | Mermaid 图 | 复习 |
| §4 速查表 | 考前一页纸 | 考前 |
| §5 双语术语卡 | 可直接写进考卷的英文定义 | 考前 |
| §6 考点预判 | 🔴 教授明示 / 🟡 大纲反推 / ⚪ 笔记推断 | 考前 |
| §7 自测 | 概念题 + 案例题（答案折叠） | 复习 |
| §8 讲义页码映射 | 每一页讲义 ↔ 笔记小节 ↔ 课堂覆盖 | 对照讲义时 |
| §9 延伸与勘误 | 课上略过 / 课上补充 / 讲义的错 / 课外补充 / 待核对 / 变更记录 | 怀疑笔记时 |

§2 每个小节固定七格：**是什么**（先人话再定义）→ **为什么需要它** → **课件原例**（讲义 p.X）→ **🎙️ 课堂补充**（带时间戳的教授原话；无转录写"待转录补充"）→ **💡 换个说法**（≥ 2 个角度）→ **⚠️ 常见误解**（每条带"为什么错"）→ **所以呢**（引向下一节）。公式型小节另有符号表、手把手数字例子、"为什么公式长这样"、极端情况。

四种来源标记：`（讲义 p.X）`原文 · `🎙️` + `` `时间戳` `` 课堂转录 · `💡（笔记补充）`AI 或我补的解释 · `🔗` 外部资料（带获取日期）。**⚪ 与 💡 是推断，出错概率最高。**

版本：`v0.9` = 只有讲义；`v1.0` = 已合并课堂转录。frontmatter 里有 `transcript: pending / merged`。

## 6. 复现与验收

**环境**：Python ≥ 3.9。三个验收脚本只用标准库；EF5560 `code/` 需要 `pandas numpy matplotlib statsmodels scipy`（`EF5560_Fintech_and_AI_in_Finance/code/requirements.txt`）。Windows 上先 `set PYTHONIOENCODING=utf-8`（或在 Git Bash 里 `export`）。

**① 笔记质量量表**（任何一篇笔记，在仓库根目录）

```bash
python _meta/tools/note_quality.py IS6400_Business_Data_Analytics/notes/M04-特征工程-特征重要性与降维.md --pages 69 --strict --sections
```

输出 L（合规）/ G（密度粒度）/ E（元素清单）和 R（可读性）诊断；加 `--readability` 显示全部 R 项。`--sections` 打印逐小节明细。阈值定义在 `_meta/笔记质量规范.md`，校准过程在 `_meta/质量体检-2026-09-16.md`。

**② 全库链接检查**

```bash
python _meta/tools/link_check.py
```

正常应无真实断链。本次 2026-10-10 检查的 22 条报警来自已有 .py/.json/.dot 图源双链：当前脚本会误加 .md 后缀，目标已按实际路径与哈希核对存在。原始退出码 1 如实保留，不能写成全部脚本通过。

**③ 转录融合验收**（证明笔记里的时间戳和引文能回到转录）

```bash
python _meta/tools/transcript_check.py audit IS6400_Business_Data_Analytics/notes/M04-特征工程-特征重要性与降维.md --transcript IS6400_Business_Data_Analytics/transcripts/M04-transcript-partial.txt
```

检查含 A1–A14：A4 核时间戳，A5 核引文词组，A13/A14 定位未加括号的改写与数字差异。多源并集不能证明每条引用归属正确，仍须按源核对；lecture 与 tutorial 分开统计时，A12 的时长占比也不能单独判缺录。

**④ EF5560 讲义数字复现**

```bash
cd EF5560_Fintech_and_AI_in_Finance/code
python run_all.py          # 当前 15 个脚本；每个脚本头部写明对应讲义页与笔记小节
```

图与表输出到 `code/output/`，笔记用 `![[...]]` 引用。

## 7. 用同一套方法做你自己的课

1. 复制 `_meta/`（规则 + 工具）、`.claude/skills/transcript-merge/`、根 `CLAUDE.md` / `AGENTS.md` 到你的 vault；建一个课程目录，照 §4 的结构放 `course_files_export/` 与 `transcripts/`。
2. 先写 `_prep/课程前置资料.md`（大纲对校）和 `_meta/知识层级台账.md`（哪些概念算已知、哪些要就地展开）——这两份决定笔记的详略。
3. 让助手先读根与课程规则，按共同骨架、读者基础和机制标准写正文。以一次实质补全为主，再做适用的结构检查及必要计算/来源核对；存量正文不为标签反复改写，不逐块重做全量验收。
4. 转录到手后按 `.claude/skills/transcript-merge/SKILL.md` 合并，用 `transcript_check.py audit` 验收。
5. 按现行简化流程记录实际做过的来源、计算、图形和文件检查；仅对具体新错误定向核对，未做独立 Q/R 的不能填写相应分数。旧的真实验收记录保留。

Notion 进度看板（`_meta/Notion进度看板.md`）是我个人的，字段定义可以参考，数据库本身不公开。

## 评分作业与学习材料

公开笔记服务自学，完整个人评分答案和提交件留在被 Git 忽略的 `assignment/`。制作规则分三层：全局[作业规范](作业规范.md)、各课程独立细则、具体任务的当前 Canvas/brief 记录。正式答卷保留题目要求的方法、代码、结果和引用；零基础教程、自测、提交检查与内部管理记录放私人学习导览。讲义的九节/七格结构不自动套到提交稿。实际使用 AI 时按现行规则写一句真实工具声明，教师另有明确要求时保留；未提交的文件不能因生成或检查通过而标为已提交。

## 8. 已知限制

- 笔记是 AI 生成 + 我复核的产物，**不是官方材料**；已知问题在各笔记 §9.3 / §9.5，未知问题一定还有。
- 转录是 ASR 输出，错误率高（会计课最差，见 `.claude/skills/transcript-merge/reference/asr-dictionary.md` 的真实样本）；笔记引用时已按讲义纠正并用 `[ ]` 标出改动，但不保证每处都对。
- `_meta/质量体检-2026-09-16.md` 和 9 月 24 日质量基线是历史缺口记录；后续修复见机制审修台账及各篇变更记录，不能仅从旧 FAIL 或新 PASS 推完整正确。
- EF5560 有完整分析代码库；本轮各课新增图源也位于 `notes/figures/`，有独立说明与输入数据。历史临时计算尚非全部入库，不能把局部复现推广为所有结论。
- 中文为主，英文只出现在术语、引文与定义。

## 9. 反馈与贡献

- **发现笔记错误**：开 Issue，写明笔记文件、小节号、讲义页码，最好附你认为正确的说法与依据。
- **改进规则或脚本**：欢迎 PR；规则改动请同时更新 `_meta/` 里的对应文件与变更记录。
- **版权或隐私问题**：按 `NOTICE.md` 联系，会立即处理。
