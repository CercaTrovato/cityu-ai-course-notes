# CityU 教学规则独立审计

审计日期：2026-10-22  
审计范围：根 `AGENTS.md`、根 `CLAUDE.md`、`_meta/可读性总规则.md`、`_meta/笔记模板.md`、`_meta/机制理解与可读性标准.md`、`_meta/笔记质量规范.md`、`_meta/笔记制作与融合验收流程.md`、`_meta/tools/note_release_gate.py` 的 `review_gate`。  
边界：只读正式库；未读取本任务的 `findings.md` 或 `HANDOFF.md`；本报告是独立判断。

## 结论

多轮规则仍会产出难读笔记，主要原因不是规则不够多，而是**真正能发现理解断点的独立读者被流程取消了，机器可验证的结构又占据了执行注意力**。现行规则已经准确承认脚本无法可靠判断指代、术语解释、推理跳步、例子贴切度和段落位置（`_meta/可读性总规则.md:630-640`），却把最终实质核对交回作者或主代理本人（`_meta/笔记制作与融合验收流程.md:37-46`），并在多处明确停用独立审查（`_meta/机制理解与可读性标准.md:18-28,102-106`；`_meta/笔记质量规范.md:221-225`）。这正好留下了最关键的盲区。

最新用户要求应成为现行长期规则：**候选完稿后必须派一名未参与写作的独立子代理，以高中生知识起点审查可读性；只审一次，修复后只复核明确缺陷，不恢复全库评分、重复盲读或多轮验收。**这条新规则应显式覆盖 2026-10-02 “不强制独立代理”的旧表述。

## 实际冲突与失败机制

### 1. “换一个身份”不是独立审查

- 根规则要求作者“换一个身份”攻击自己的产出（`AGENTS.md:289-300`；`CLAUDE.md:286-297`）。同一个上下文已经知道自己想表达什么，最容易自动补全缺失步骤。
- 日常流程进一步规定“可由主代理自己完成，不强制另派评分代理”（`_meta/笔记制作与融合验收流程.md:37-40`）。
- 质量规范直接写“独立盲读流程已停用，不再分派评分代理”（`_meta/笔记质量规范.md:221-225`）。
- 机制标准也把旧独立 Q/R 审查整体停用（`_meta/机制理解与可读性标准.md:18-28,102-106`）。

旧流程把“取消重复评分”和“取消独立读者”绑在一起。前者合理，后者恰好移除了语义质量唯一有效的外部检查。

### 2. 读者画像与最新要求不一致

现行画像是“只有 AI / ML 基础，其他学科零基础”（`AGENTS.md:29-39`；`_meta/笔记质量规范.md:42-52`；`_meta/笔记模板.md:122-126`）。这仍允许作者默认读者懂模型、训练、特征、概率或常见 API。最新要求是审查者按**高中生知识起点**阅读。若不在规则中明确覆盖，审查者仍可能沿用 AI / ML 基线放过跳步。

建议将作者的课程先修台账与审查者画像分开：材料可以引用课程正式先修，但独立可读性审查不得默认读者掌握大学层面的 AI、统计、会计、法律、金融或编程术语。正文若确实依赖先修，必须在当地用一句唤醒或完整解释把桥接写出来。

### 3. 固定结构容易替代教学目标

- 九节固定、每个概念七格不得省略、每个 `###` 还要“所以呢”（`AGENTS.md:190-217`；`_meta/笔记模板.md:34-49,85`）。
- 同一套规则又承认“标签齐全不代表解释充分”（`_meta/笔记模板.md:118-126`），并指出历史上形式全做到仍然难读（`_meta/笔记模板.md:407-412`）。

这会产生明显的目标替代：执行者先填七个标签、九个章节和回执字段，再把“全部槽位存在”误认为“已经教会”。空的“待转录补充”、泛化类比、模板化“常见误解”和机械“所以呢”还会增加阅读噪声。

建议保留九节作为导航，保留七类信息作为**覆盖提示**，但取消“每个概念逐格显式出现”的教学完成含义。允许同一学习单元合并呈现，只要读者能够回答：对象是什么、为何需要、怎样一步步做、条件与失败点、具体例子、和前后概念的关系。来源标记、原题、未知边界仍必须显式保留。

### 4. 完整性要求缺少“合并重复”的出口

模板同时要求篇幅不设上限、每页在正文实质讲解、固定九节和七格（`_meta/笔记模板.md:34-49,89-112`）。这能防漏页，却容易把重复课件页逐页重述，形成“覆盖完整但学习路径淹没”的长文。

完整性不能降低，但可改成：每页的**独有知识、条件、数字、图、原题和来源地位**必须有归属；重复页可共同指向一个完整解释，并在映射表标明合并理由。完整原题仍逐题保留和解析，不能被“合并重复”吞掉。

### 5. “用脚本验，不许目测”与脚本边界自相矛盾

模板说逐页覆盖“用脚本验，不许目测”（`_meta/笔记模板.md:89-112`），但总规则明确脚本不能判断术语是否解释、推理是否跳步、例子是否贴切等（`_meta/可读性总规则.md:630-640`）。流程还要求真实观看图与最终载体（`_meta/笔记制作与融合验收流程.md:41-50`）。

应改为：脚本只验可机械确认的完整性、格式、哈希和明显缺项；来源语义、原题完整性、教学理解与视觉显示必须人工审查。禁止把脚本 PASS 写成教学通过。

### 6. 现行/历史指标并存，继续诱发凑数

根规则一处说当前退出码依据 L / C / R（`AGENTS.md:3-7`），另一处仍把共同标准描述为 L / G / E（`AGENTS.md:14`），工作流又要求保留历史 G / E 输出并执行大型对抗清单（`AGENTS.md:273-312`）。质量规范虽说明 G / E 只作历史诊断（`_meta/笔记质量规范.md:78-90,116-124`），但后文仍完整保留大量阈值、元素清单和校准表。执行者在时间有限时自然优先完成可计数事项。

建议把 historical G / E 移到单独附录或历史文档，现行入口只保留一句链接。日常交付默认不展示历史分数，除非用户明确要求比较旧口径。

### 7. `review.json` 只能防错文件，不能证明独立审查

`review_gate` 会核对候选、基线、报告与资产哈希，也会检查四个状态是否为 `passed` 及证据字符串非空（`_meta/tools/note_release_gate.py:107-139`）。它不会、也无法判断：

- 审查者是否独立于作者；
- 审查者是否真的按高中生起点阅读；
- “evidence” 是否只是看似具体的套话；
- 推理链、例子和图是否真的可理解。

因此，把 JSON 做得更复杂只会增加新的填表目标。更多状态、分数、逐节布尔值和文本长度门槛都可以被同一作者一次性生成，反而制造“机器已认证教学质量”的错觉。

代码应只承担真正能证明的边界：文件存在、候选哈希一致、基线未漂移、必需审查工件被绑定、存在未解决阻塞时拒绝写回。**独立性、读者起点和语义结论必须由真实调度记录与独立审查文本负责，工具输出应继续明确“不代替语义判断”。**

## 建议的最简长期框架

### A. 写作契约：四个不可降级目标

1. **来源真实**：讲义、转录、笔记补充、外部资料分开；未知保持未知。
2. **内容完整**：每页独有内容有归属；完整原题、全部选项/小问、答案、过程和来源地位保留。
3. **能从零学会**：按问题 → 对象 → 动作/推理 → 中间结果 → 结论 → 条件/失败点组织；核心机制有完整可复算或可走通的例子。
4. **文件安全**：只在 scratch 产候选；基线、哈希、原子写、冲突检测、写后回读继续执行。

九节、七类信息、R 提示和 D 证据是实现工具，不得单独作为完成证明。

### B. 三个角色，职责不可互换

| 角色 | 必须做 | 不得做 |
|---|---|---|
| 作者 | 读源材料；完成候选、页码/原题覆盖、来源标记、重要计算；最多一次整篇自查 | 给自己的候选签发独立可读性通过 |
| 独立审查者 | 候选完稿后，以高中生知识起点读全部本次教学范围；不看作者自我评价；只报告具体理解断点、位置、原因和最小修复要求 | 改正文；打总分；按字数、七格或标签判质量；重新做全套来源审计 |
| 主代理 | 确认作者与审查者不是同一代理；核对来源/完整原题/计算/视觉/文件安全；汇总阻塞；安排修复；决定是否写回 | 用自己的复读替代独立审查；把脚本或 JSON 完整称作教学通过 |

### C. 一次独立审查流程

1. **冻结候选**：记录候选 SHA-256、目标路径、`full` 或 `changed` 范围。新写/整篇整改审全篇；局部修改审全部新增、受影响单元及必要上下文。
2. **派独立子代理**：明确“未参与写作”“高中生知识起点”“不依赖作者解释”“只读候选和必要图示”。这是长期硬门槛，覆盖 2026-10-02 的旧冲突。
3. **只交一个简洁报告**：候选哈希、审查范围、结论 `可发布/阻塞`、阻塞项。每个阻塞项只需四栏：精确位置、读者在哪里断掉、缺少的桥、最小修复。可选建议与阻塞项分开。不需要评分、字数、逐节打勾或复杂 JSON。
4. **作者定向修复**：只改明确缺陷及同类写法。若候选变更，主代理核对实际 diff、来源和哈希。
5. **定向复核**：独立审查者只复核已列阻塞项及受其影响的上下文；不重启全篇审查。若修复引入新问题，新问题成为新的具体阻塞。
6. **主代理收口**：来源/原题/计算/视觉/文件安全各自按既有边界核对；全部阻塞清空后才写回。

### D. 可读性阻塞标准（不评分）

以下任一项在本次范围内存在，就阻塞教学发布：

- 推理所需术语、符号、对象或前提未在当地解释，读者必须猜或跨多屏寻找；
- 从条件到结论缺少关键动作或理由，例子不能独立走完；
- 公式、代码、表格或图没有说明“输入是什么、做了什么、结果怎样读”；
- 引用、翻译、标签或答案结论代替了教学解释；
- 关键条件、边界、失败机制或反例被省略，导致读者会做出错误迁移；
- 完整原题、选项/小问、答案过程或来源地位缺失；
- 最终图示/载体未实际查看却声称可读。

不因为句子略长、字数不足、七格不齐、类比数量不足或历史分数低而单独阻塞；只有它们造成上述具体理解断点时才阻塞。

### E. 无法派独立子代理时的真实状态

如果工具、并发槽、权限或环境使独立子代理不可用：

- 可以继续完成候选、机器预检、来源核对和文件安全工作；
- 必须记录：`独立高中生视角可读性审查：未执行（原因）`；
- 不得由作者或主代理补写“独立审查报告”；
- 不得标记教学验收通过，也不得进行依赖该门槛的正式写回/发布；
- 恢复能力后只补这一轮独立审查，不重做已经有证据的来源和机械检查。
