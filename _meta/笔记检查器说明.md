# 笔记检查器说明

默认 current 按现行规则检查格式、内容证据和可读性。固定标签、字数、类比数量、页数与小节平均比不决定默认 FAIL；教学要求、来源边界与逐题解析要求继续执行。

## 1. 常用命令

在 vault 根运行。T 笔记可显式加 --tut；发布门槛根据 --note 的正式目标名识别 T，scratch 文件名不影响。

~~~powershell
D:\anaconda3\python.exe -X utf8 _meta/tools/note_quality.py <笔记.md> --strict --sections --readability --json
D:\anaconda3\python.exe -X utf8 _meta/tools/note_quality.py <笔记.md> --profile historical --strict --json
D:\anaconda3\python.exe -X utf8 _meta/tools/note_quality.py EF5560_Fintech_and_AI_in_Finance/notes/M02-回归与样本外设计.md --source-checks _meta/quality-contracts/ef5560-m02-canvas-20261020.json --strict --json
~~~

最后一条命令只核清单声明的两题。可用 --pages N 指定同一来源版本的总页数；混合版本或与 source 冲突的页数只报版本待核，不能套用另一版页码推导缺页。

current 中 --strict / --legacy 仅影响另存的旧 E 统计，不豁免 C/L/R。R 的既有启用条件不变：readability_rules 为 v1/v2 或 --readability-strict 时，其机械硬项计入退出码；发布门槛还按制作流程核 R。退出码 0 只表示本次机器可验证项未阻塞，1 为阻塞，2 为参数、文件或无法检查。

## 2. 当前检查与人工边界

| 项目 | 当前行为 | 仍须实质核对 |
|---|---|---|
| L / R | 保留格式与可读性检查；机械硬项按原规则处理 | 语义疑点、误报及实际渲染 |
| C_STRUCTURE / C_EXPLANATION | 空正文、只有原题／标签／占位句，阻塞 | 有一段文字不代表解释正确完整 |
| C_CALCULATION_STEPS | 有计算公式且全篇无可识别代入步骤，阻塞；其他单元有算例时保留具体待核线索 | 算例是否对应当前机制、参数单位、完整可复算链；不以别处算例自动充当本节证据 |
| C_CODE_PURPOSE / C_CODE_EXPLANATION | 代码缺任务／关键行解释时阻塞；接受普通段落、表格、步骤和有效注释 | 逐行解释的正确性与程序实际运行；Mermaid 不当作程序代码 |
| C_ARITHMETIC | 安全解析纯数字四则、幂和开方等式；按显示小数精度容许舍入，矛盾时阻塞 | 符号推导、百分号／单位换算、模型结果；不执行代码，不把明确错误示范判作作者结论 |
| C_PAGE_REFERENCES / C_PAGE_VERSION | 同一确定版本缺正文页码归属，阻塞；多版本冲突报待核 | 页码引用不证明页面已经实质讲解，非内容页豁免仍须有依据 |
| C_SOURCE_CONTRACT | 见 §3；源版本、题面／选项、逐问中英锚点不符时阻塞 | 清单抄写是否忠实、源题是否全收、答案与逐项解释是否正确 |
| C_REASONING_REVIEW / C_SYMBOLS | 缺理由／过程或符号解释线索，只报待核 | 按实际已有解释位置区分缺口、误报、合理保留 |

小节 2.4.1a 的 a 不再被截成 2.4.1；父单元可统合其子步骤。取消为旧 G/E 凑配额，并不取消解释链、具体例子、停止边界、失败机制与迁移题等适用 D 层要求。

## 3. 原题清单

先人工对原件建立清单，再传 --source-checks。工具不凭题号或中文概述宣布原题完整。仓库内的示例只覆盖 EF5560 M02 新版物理 p.26–27 两道公开选择题，不覆盖该讲全部题目。

清单 schema 为 note-source-checks-v1，至少包含以下字段：

| 字段 | 内容 |
|---|---|
| sources | 以 source_id 为键，值含 path、sha256；相对路径从清单所在目录解析 |
| questions | 非空数组，每项含唯一 id、source_id、正文 section、original、answers |
| original | 原语言完整题面、情境、全部选项与原字母／编号；按人工回源保真 |
| options | 选择题的字母到完整选项文本的对象；original 也须含这些原字母与全文 |
| answers | 每个小问一项，含唯一 id、中文解析锚点 chinese、独立英文参考答案锚点 english；填具体内容，不能只填标签 |

清单可附 scope 和 source_location 供人工审查。正文定位须唯一；匹配仅归一化 Unicode、空白和引用前缀，不删除单词边界或算术操作符。源题正文与答案不能仅藏在程序里。答案锚点是抽取证据，并不证明完整推理或逐选项解析。

~~~json
{
  "schema": "note-source-checks-v1",
  "scope": "明确本次核对的源与题目范围",
  "sources": {"lecture": {"path": "相对清单的原件路径", "sha256": "原件的64位SHA-256"}},
  "questions": [{
    "id": "p26-q1", "source_id": "lecture", "section": "2.4.6a",
    "source_location": "physical p.26",
    "original": "实际完整原题，包括情境和所有选项",
    "options": {"A": "实际A选项全文", "B": "实际B选项全文"},
    "answers": [{"id": "main", "chinese": "实际中文解析中的具体句子", "english": "Actual independent English answer."}]
  }]
}
~~~

以上仅说明字段，不能直接作为通过凭证。实际清单见 _meta/quality-contracts/ef5560-m02-canvas-20261020.json。

- unverified_without_manifest：没有传清单，原题完整性未验证。
- manifest_contract_passed：只通过所声明源哈希、题面／选项及答案锚点的字面核对，不等于全部原题或答案语义通过。
- contract_failed：清单格式、来源版本或声明内容不符，属于硬阻塞。

发布门槛也接受 --source-checks <清单.json> 并转交检查器；未传时仍执行人工逐源核对，不能把未验证状态写成通过。融合器调用现行 C 检查，但不会自动发现或附带原题清单；需要清单时先显式核对并把结果纳入来源核对报告。

## 4. JSON 与旧结果

输出末行 JSON: 后为完整 JSON。消费端读 profile、legacy_problems（L）、C.hard / C.warn、C.source_coverage、R.hard / R.warn。current 顶层 G 为空，顶层 E 仅保留当前待核线索；旧计数、旧 E 列表与旧判定在 historical 中。不要继续按顶层 E 的数量推导当前 FAIL。

historical 模式保留旧 G/E 算法与 strict / legacy 判定，用于历史配额对照。编号后缀与代码语言正则边界修复也作用于该模式，故不保证重现旧版 bug 导致的每条计数。不得追改旧日志或把历史 FAIL 换成 current PASS。

note_release_gate.py 已消费 C.hard，并在 current 的 C 结果缺失或结构不可靠时阻塞；教学回执、来源／候选／图资产哈希和原子写保护保持有效。
