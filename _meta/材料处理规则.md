## 2. 通用原则（硬约束）

1. **原始文件只读**。绝不移动、改名、删除、修改。（§0 的迁移是**用户明确要求**后的例外）
2. **中间产物不落库**。提取的 txt、下载的 PDF 一律放临时目录
3. **提取即复核**。文本提取为空的页 = 纯图片页，必须视觉看一遍，不能当它不存在
4. **来源可追溯**。笔记里每条信息都要能指回原材料的具体位置（页码 / 时间戳 / 文件名+cell 序号）

## 3. 讲义 PDF

```bash
pdfinfo "<讲义>.pdf"                        # 先看页数
pdftotext -layout "<讲义>.pdf" out.txt      # -layout 保留分栏与表格，必须加
```

按 `\f`（换页符）切分即得逐页文本。

**已知坑**
- 项目符号会被渲染成 `�`。批量替换成 `-`
- Windows 下 Python 默认 GBK 输出会抛 `UnicodeEncodeError`。加 `PYTHONIOENCODING=utf-8`
- 幻灯片多栏排版提取后会交错；看不懂的段落回去看原页
- 动画分层可能一页拆成多页、内容重复

**图片页复核（必做）**：提取后文本为空的页往往是**关键的图**（时间线、四象限、对照表、流程图），甚至可能整页贴着一篇论文。必须视觉读一遍并重画为 Mermaid 或表格。

**具体方法**（Claude Code）：直接用 **Read 工具的 `pages` 参数按页读 PDF**，页面会以图像呈现，单次最多 20 页：

```
Read(file_path="<讲义>.pdf", pages="17-22")
Read(file_path="<讲义>.pdf", pages="60")
```

不需要任何额外的图像提取工具。**别的 AI 若无此能力**，在笔记 §9 写明「第 X 页为图片，未纳入」，并列入待核对表。

> 💡 IS5113 M01 的教训：4 页纯图片页初次被跳过，补读后发现其中有**整页引用的 2025 年 arXiv 论文**、**两张关键对照表**、以及**唯一一处教授用红框强调的重点**。图片页往往比文字页信息密度更高，**不能省这一步**。

**质量检查点**
- [ ] 页数与 `pdfinfo` 一致
- [ ] 所有空文本页已复核或已声明未纳入
- [ ] 页码映射表覆盖全部有内容的页

## 4. 大纲 PDF / DOCX

**产出**：`_prep/课程前置资料.md`

**必须做对校**——大纲通常有两个版本：

1. **教授发的 Course Outline / Syllabus**（本学期实际教学口径）
2. **学校官方课程目录**：`https://www.cityu.edu.hk/catalogue/pg/<学年>/course/<课程码>.pdf`

**规则**
- **以教授的 Outline 为准**
- 但官方目录里有而 Outline 没有的**硬性信息必须补进来**：学分、先修、**及格线**、考试时长、**GenAI 使用政策**
- 冲突处**显式列表标注**：`官方说 X ／ Outline 说 Y ／ 采信 Y`，写明理由

> 💡 IS5113 的经验：官方目录写明了「持续评估 ≥25% 且考试 ≥25%」和「哪些评估任务允许用 GenAI」，这两条 Outline 上完全没有，但对学生极其重要。**每门课都要抓官方目录。**

**质量检查点**
- [ ] 学分、考核权重、及格线、考试时长都有明确数字
- [ ] GenAI 政策已查明
- [ ] 冲突项已逐条列出并说明采信依据
- [ ] 官方目录的抓取日期已记录

## 5. `.docx`

```python
import docx
d = docx.Document(path)
paras  = [p.text for p in d.paragraphs]
tables = [[[c.text for c in r.cells] for r in t.rows] for t in d.tables]
```

⚠️ **表格内容不在 `paragraphs` 里，必须单独取 `tables`**，否则会漏掉大纲的考核表这类关键信息。

prs = Presentation(path)

## 7. `.csv` / `.xlsx` 数据文件 ✅

**触发**：`Business_Data_Analytics/Airbnb.csv`、`Fintech_and_AI_in_Finance/course_files_export/data/*.csv`（8 个）

### 7.1 提取

```python
import pandas as pd
df = pd.read_csv(path)
df.shape; df.dtypes; df.head(); df.isna().mean(); df.describe(include='all')
```

对每个数据集，产出**固定六项**：

| 项 | 内容 |
|---|---|
| 规模 | 行数 × 列数、文件大小 |
| 字段清单 | 字段名 · 类型 · 含义 · 取值范围/类别数 |
| 缺失率 | 逐列缺失比例，标出 >5% 的列 |
| 目标变量 | 若是监督学习数据，指出因变量是哪一列 |
| 已知坑 | 编码、单位、异常值、类别不平衡、时间范围 |
| 与讲义的对应 | 这份数据配合哪一讲/哪个 tutorial |

### 7.2 产出物

**数据集卡**，统一写在 `<课程>/_meta/数据集.md`（一个课程一个文件，每个数据集一节）。

**不要**为每个数据集单独建笔记文件——数据集是**教学材料的配件**，主体仍是对应的 module 笔记；module 笔记里链过来即可。

### 7.3 边界（重要）

- **数据集卡只做描述性概览。** 分析分两类：教授给的 notebook 里的分析写在 `T<NN>` 笔记（§8）；**我们自己做的可复现分析写进 `<课程>/code/`（§8b，2026-09-10 起启用）**，笔记里链过去
- **不要把数据文件的内容大段贴进笔记。** 只放字段表和统计摘要
- **不修改原始数据文件**，也不生成清洗后的副本落进 vault

### 7.4 已知的图表例外

本库规则是「图表重画为 Mermaid / 表格，不嵌位图」。但**统计图（分布、散点、相关矩阵）Mermaid 画不了**。

**当前处理**：数据集卡里**只用表格描述**（分位数、类别频次）。
**统计图由 `<课程>/code/` 的脚本生成到 `output/`**（§8b），笔记用 `![[...]]` 嵌入——**图必须可复现**（有对应脚本、有断言自检），这是嵌位图的前提。2026-09-10 起以此替代原来的"不生成统计图"。

import json

for i, c in enumerate(nb['cells'], 1):

### 8.2 产出物：代码讲解笔记

文件名 `notes/T<两位数>-<主题>.md`（`T` = Tutorial，与讲义笔记的 `M` 区分）。

**结构**（比 module 笔记轻，但仍带 frontmatter 与知识衔接）：

```
0. 这个 notebook 在教什么（一段话）
1. 前置：需要哪些库、怎么装、对应哪一讲的理论
2. 逐块讲解 —— 每个 code cell 一节：
      这块在干什么   （一句话）
      逐行注释       （关键行，不是每一行）
      为什么这么写   （为什么用这个函数/参数，而不是别的）
      输出说明       （输出意味着什么；notebook 已有输出时直接引用）
      ⚠️ 易错点
3. 完整流程串讲（把散落的 cell 串成一条线）
4. 自己动手 —— 改哪个参数会发生什么
5. 与讲义理论的对应表（cell ↔ 讲义页码）
```

### 8.3 「读者零基础」在这门课怎么理解 ⚠️

本库的核心假设是「读者只有 AI/ML 基础，其余零基础」。对 **IS6400 这类技术课，这条假设需要重新校准**：

- 线性回归、PCA、KMeans、决策树、集成学习 → **属于 L0**（读者有 ML 基础），不必从零讲
- **Python 语法、pandas / sklearn / numpy 的具体 API** → **不确定是否属于 L0**
- 商业解读（"这个系数在业务上意味着什么"）→ **不属于 L0**，必须讲

**⚠️ 待用户确认**：IS6400 的 L0 基线要不要包含 Python/pandas 熟练度？这直接决定代码讲解笔记的详细程度（是逐行讲语法，还是只讲建模思路）。
在确认之前，**默认按"Python 语法熟悉、但特定库 API 不熟"来写**——即不解释 `for` 循环，但解释 `sklearn` 的 `fit/predict` 约定和参数含义。

### 8.4 GenAI Prompt 单元格（IS6400 特有）

## 8b. 自建分析代码库 `<课程>/code/` ✅（2026-09-10 新增）

**触发**：课程提供了数据文件（§7），且笔记里出现了**由数据算出来的数字**（累计收益、回撤、R²、误差验算……）。

**为什么要有它**：§7 的数据集卡片里的验证是 agent 当场跑出来的，**代码没留下**——读者只能信，不能复现。§8 的 `T<NN>` 笔记讲的是**教授给的** notebook；本节讲的是**我们自己写的**分析代码。两者分开放。

**首例**：`Fintech_and_AI_in_Finance/code/`（2026-09-10 建），完整设计说明见其 [`README.md`](../Fintech_and_AI_in_Finance/code/README.md)。**新课程建代码库时照抄那份 README 的结构。**

### 8b.1 目录约定

```
<课程>/code/
├─ README.md            设计说明：怎么跑、目录约定、硬规则、脚本↔笔记映射表
├─ requirements.txt
├─ run_all.py           按编号跑全部
├─ common/
│   ├─ load.py          ★ 统一数据入口——每个 loader 的 docstring 写死列名、口径、坑
│   └─ plot.py          统一绘图（中文字体、跨图一致的配色、保存到 output/）
├─ L0N_<主题>/          每讲一个目录，脚本按 <两位序号>_<内容>.py 编号
└─ output/              图与表，笔记用 ![[L0N_XX_<name>.png]] 引用
```

### 8b.2 三条硬规则

1. **单一数据入口**：所有脚本只能通过 `common.load` 读数据。日期列转换、收益口径、列名陷阱**集中处理一次**，不让每个脚本各踩一遍
2. **不改原始数据**：`course_files_export/` 只读，衍生结果写 `output/`
3. **每个脚本可独立运行**：开头两行 `sys.path` 引导 + 固定格式 docstring（目的 / 讲义页 / 笔记小节 / 输入 / 输出 / **关键决定**）。「关键决定」格是写给不读代码的人的：每个影响结果的选择（口径、窗口、起点、是否年化）都列出来

### 8b.3 与笔记的双向链接

- 笔记对应小节末尾：`📁 代码：[路径](../code/...)` + `![[输出图]]`
- 笔记里由数据算出的数字**带来源脚本名**：「最大回撤 −38.66%（`L01_03`）」
- README §4 维护一张**脚本 ↔ 讲义页 ↔ 笔记小节 ↔ 回答什么问题**的映射表，每加一个脚本加一行

### 8b.4 质量检查点

- [ ] `run_all.py` 全部 ✅
- [ ] 每个脚本至少一个 `assert` 做口径或数值自检——**样板脚本就是靠断言抓到"收益文件首行不是 NaN"这个真实数据特征的**
- [ ] 笔记里每个引用的数字都能在某个脚本的 stdout 里找到
- [ ] 每张输出图用 `Read` 工具打开看过：中文不是方块、坐标合理、图能独立传达答案
- [ ] `load.py` 的 docstring 与 §7 数据集卡片的描述一致；发现新的数据特征**两边都要更新**

### 8b.5 边界

- 只做**笔记里需要的**分析，不做探索性挖掘。每个脚本要能回答 README 映射表里的一个具体问题
- 无交易成本、无换手约束等简化假设**写进 README「已知限制」**，不藏在代码里

## 11. 怎么新增一种材料类型

   - **提取方式**（具体命令或代码，不要写"用某工具"）
   - **产出物形态**（生成什么文件、放哪、什么结构）

   - **质量检查点**（勾选清单）
3. 规则写完，把状态改成 ✅ 或 ⚠️
4. 再开始处理该类型的材料
