⭐ 这一页在教什么 —— "找出什么没发生"的标准三步套路

看图前先问：怎样找全体商品中没有正面反馈的那些？

flowchart TD
    A["Step 1：先找出<br/>『有正面反馈的商品』<br/>InventoryWithPositiveSalesCallReactions"]
    B["Step 2a：把全部商品表<br/>InventoryType<br/>外连接到 Step 1 的结果"]
    C["Step 2b：在 Step 1 那一侧的字段上<br/>加条件 Is Null"]
    D["结果：全部商品里<br/>没有出现在 Step 1 结果中的那些"]
    A --> B --> C --> D

箭头代表先筛正面集合、再连全部商品、再查无匹配的操作顺序。

沿例子读图（笔记补充）：教学商品 I1 有正面记录，I2 没有。先取得 I1 的正面商品键，再保留全体商品 I1、I2 外连接该集合，检查匹配时必非空的身份键。最终留下 I2，表示无正面记录，不等于明确负面。这里把主体逻辑写在左边便于读法，与原画布摆放无关。

图旁边界：p.91没给结果；I1/I2仅教学例。无正面记录也可能尚未拜访，不等于客户明确否定。

文字替代：先筛正面记录、保留全部商品，再查匹配侧身份键无匹配；“匹配侧”不等于屏幕固定右侧。

读图自测：右侧有记录但tag为Null，用tag判断缺匹配安全吗？

不安全。应检测匹配时必非Null的身份键；未知tag不能证明右记录不存在。

这个套路有个正式名字：反连接（anti-join）（💡 笔记补充，讲义未提这个术语）。

逐步理解它为什么有效：

  1. 外连接之后，InventoryType 的每一行都在（六种商品全在）
  2. 有正面反馈的商品，右侧 CustomerReactiontoProduct 有值
  3. 没有正面反馈的商品，右侧 CustomerReactiontoProduct 是 Null（外连接没匹配上）
  4. 在右表匹配时必非 Null 的身份键上加 Is Null → 只留下没有右侧匹配的行 = 没有正面反馈的商品

⚠️ 三个关键点：

点 说明
参考逻辑把 InventoryType 写在左侧 以 InventoryType LEFT JOIN 正面集合 表达全保留主体；原画布主体在右，两者不矛盾
Is Null 检查匹配侧身份键 选匹配时必非 Null 的键，不能用本来可空的普通字段代替
写法是 Is Null（两个词），不是 = Null 见 §2.20.2。= Null 永远查不出东西

⚠️ 讲义 p.51 的 EXISTS 与这里的 Is Null 是一对：p.51 说 EXISTS 取"非空"（但那个写法是错的），p.91 用 Is Null 取"空"。Is Null 才是 Access 里真正能用的写法（p.91 的截图证明了这一点）。
